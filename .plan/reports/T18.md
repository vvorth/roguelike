Assumptions made:
- The four new Shift-diagonal key entries were folded into the *existing* per-delta rows of
  `_MOVEMENT_BINDINGS` (e.g. the `(1, -1)` row now reads `("u", "9", "K", curses.KEY_SR)`)
  rather than added as new table rows, since CONTRACT-v4 §5.1 states these resolve to the exact
  same deltas the legacy diagonals already produce. This keeps one dict entry per delta instead
  of risking two different `Command` objects that happen to compare equal.
- `DESCEND`/`ASCEND`'s old private table `_STAIR_BINDINGS` was renamed to `_NO_ARG_BINDINGS` and
  extended with `(AUTO_EXPLORE, "E")` and `(WALK_PREFIX, "w")`, since all four commands share
  the same "zero-arg, single key, `Command(kind)`" shape. This is a private, non-exported name
  (not part of `__all__`), so renaming it is not a contract-visible change; T21 or any other
  consumer should not import it.
- Where the brief said existing tests were "yours to update, not delete," I kept the original
  test function where its *intent* still held (e.g. `test_no_move_command_is_stationary` and
  `test_every_move_delta_is_a_unit_step` iterate `keys_module._KEY_BINDINGS.values()` generically
  and needed no edits — they cover the new bindings automatically) and only rewrote the two tests
  whose asserted *outcome* the contract explicitly flips.

Structural notes for T21 (dispatches on CommandKind, adds no new keys):
- `CommandKind` now has exactly 7 members in this fixed order: `MOVE, QUIT, UNKNOWN, DESCEND,
  ASCEND, AUTO_EXPLORE, WALK_PREFIX` (auto() values 1-7) — this is the order CONTRACT-v4 §5
  declares and the order `test_command_kind_members` asserts.
  `AUTO_EXPLORE` and `WALK_PREFIX` always carry `Command(kind)` with `dx == dy == 0` — same
  shape as `DESCEND`/`ASCEND`, so a `match`/`if` chain on `command.kind` can ignore `dx`/`dy` for
  all four non-`MOVE`, non-`QUIT`, non-`UNKNOWN` kinds uniformly.
- There is still exactly one `Command` value per distinct binding outcome: pressing `curses.KEY_SR`
  and pressing `"K"` produce `Command`s that are `==` (and, since `Command` is a frozen dataclass
  with hashable fields, hash-equal too) — a caller can dedupe or set-membership-test commands
  without caring which physical key produced them. The four Shift-diagonals are indistinguishable
  from — and literally produce the same `Command` object identity is not guaranteed, but
  value-equal to — the pre-existing `yubn`/numpad diagonals. No new `Command` shape, no new field,
  was introduced.
- `keys.py`'s only exported surface is unchanged (`CommandKind`, `Command`, `QUIT_COMMAND`,
  `UNKNOWN_COMMAND`, `translate_key`); the binding tables (`_MOVEMENT_BINDINGS`,
  `_QUIT_KEYS`, `_NO_ARG_BINDINGS`, `_KEY_BINDINGS`) are private (leading underscore, not in
  `__all__`) and were changed in shape (`_STAIR_BINDINGS` renamed to `_NO_ARG_BINDINGS`) — nothing
  outside this module should have imported them, and the test suite only reaches
  `_KEY_BINDINGS` via `roguelike.keys as keys_module` for exhaustiveness checks, not by name
  elsewhere.
- No escape-sequence parsing, no new `Command` fields, no message history/severity/event bus were
  added, per the brief's explicit prohibitions.
