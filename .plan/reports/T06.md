Behaviour as implemented:
- `step` dispatches on `command.kind` (T04's recommendation), with the `not state.running`
  guard first, so a stopped game is inert for every command kind including `MOVE`.
- `QUIT` → `replace(state, running=False)`; turns and player untouched.
- `MOVE` → `try_move(state.level, state.player, command.dx, command.dy)`; on
  `moved=False` the *input state object* is returned, so position and turns are unchanged
  by construction rather than by arithmetic. On `moved=True`,
  `replace(state, player=result.position, turns=state.turns + 1)`.
- `UNKNOWN` → the input object, unchanged.
- `run` sets `curses.curs_set(0)` and `stdscr.keypad(True)`, each in its own
  `try/except curses.error`, then loops draw → `getch` → `translate_key` → `step` while
  `state.running`. It contains no rule of its own; an AST test asserts it calls `step`,
  `new_game`, `format_status` and `translate_key` and never `try_move` or `is_walkable`.
- `play` calls `generate_level(seed, width, height)` then `curses.wrapper(run, level)` —
  the only `curses.wrapper` call in the module, asserted by AST to be inside `play`.

Contract deviations: none.

Assumptions made:
- **Rejected moves return the input object itself**, not a copy. CONTRACT §7 says "position
  and `turns` both unchanged" and permits returning the same object for `UNKNOWN`; returning
  it for a blocked `MOVE` too makes "changes nothing" structural. The acceptance criterion
  that demands a *distinct* object is scoped to "when something changed", and the tests
  assert distinctness only for successful moves and for `QUIT`.
- **`play`'s defaults are the literals 80 and 22**, exactly as CONTRACT §7 spells the
  signature, rather than `generator.DEFAULT_WIDTH`/`DEFAULT_HEIGHT`. They happen to be equal
  today; the contract binds the literal signature, so I wrote the literals. If the
  orchestrator ever changes the generator defaults, `play`'s defaults will not follow.
- **`play` does not pass `max_rooms`**, leaving the generator's default of 12. The §7
  signature exposes only seed/width/height, so there is no way to thread it through and no
  reason to invent one.
- **The frame after the quit key is not drawn.** The loop draws before each `getch`, so the
  last frame the player sees is the one they pressed `q` on. §7 says "repeat until
  `not state.running`" and "returns when the player quits"; drawing a final frame nobody can
  see before `endwin()` would be wasted work.
- **`step` accepts `Command`s the key layer cannot produce** — in particular a `MOVE` with
  `(0, 0)`. I added no guard: per §5 a `MOVE` never carries `(0, 0)`, and T05's `try_move`
  already returns `moved=False` for a zero delta unconditionally, so no turn would be
  consumed either way. Adding a guard here would have contradicted T05's recorded semantics
  by duplicating them; the two layers agree redundantly, as T05 noted.
- **No type or arity validation on `step`'s arguments.** §7 and §11 mandate no error
  behaviour for `game.py` at all, so I invented none — the same literal-fidelity choice T01,
  T03 and T05 each recorded for their own malformed-input cases.
- **`format_status` is built with one f-string split across two source lines** purely for
  line length; the produced string is a single line with exactly two spaces between fields
  and is compared against a string literal in the tests.
- `curses` is imported at module top level (allowed by §0.3) for `curses.error`,
  `curses.curs_set` and `curses.wrapper`. A subprocess test confirms that importing
  `roguelike.game` in a fresh interpreter leaves `curses.LINES`/`curses.COLS` unset, i.e.
  no terminal was touched at import time.

Open questions for integrator:
1. **The status line is row `level.height`, so the frame is `height + 1` rows tall.** With
   `play`'s defaults (80x22) that is 23 rows, which fits a classic 80x24 terminal. If
   `main.py` lets `--height` reach 23 or more on a 24-row terminal, T03's `draw` clips the
   status line away — specified behaviour (§4, BRIEF Q15), not a defect, but `main.py`'s
   `--height` handling may want to budget the extra row. T03 raised the same point.
2. **`play` never passes `max_rooms`.** If the CLI should expose it, that is a §7 signature
   change and therefore a contract change, not a code change.
3. **No final frame is drawn after `q`.** If the smoke test asserts on frame count, expect
   one frame per key press *including* the quit key, and none after it.
4. **`run` returns `None` and swallows nothing but `curses.error` from its two setup calls.**
   An exception raised inside `render.draw`, `translate_key` or `step` propagates out of
   `run` and out of `curses.wrapper` — which is deliberate: `wrapper` restores the terminal
   first, so the traceback lands on a sane screen. `KeyboardInterrupt` takes exactly that
   path. If `main.py` wants a quiet exit on `Ctrl-C` rather than a traceback, that belongs in
   `main.py`, not here.
5. `roguelike/__init__.py` was not touched, so `roguelike.game` must be imported by full
   path — the same note T01, T02 and T03 each raised.
