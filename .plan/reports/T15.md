## How the anchor room is sized and positioned (the integrator needs this)

Writing `(rx, ry)` for `required_up` and `w`/`h` for the drawn floor size:

1. `w = rng.randint(MIN_ROOM_SIZE, min(MAX_ROOM_SIZE, width - 2))` and likewise `h` — the
   **same distribution as an ordinary room**, so the anchor is not distinguishable by size.
2. `x = rng.randint(max(1, rx + 2 - w), min(rx - 1, width - 1 - w))`, and `y` the same
   transposed. The four bounds are exactly: `x >= 1` and `x2 <= width - 2` (G6), plus
   `x <= rx - 1` and `x2 >= rx + 1`, which put `rx` **strictly inside** the floor rect —
   never on a floor edge.
3. That interval is **never empty**. Its ordering conditions reduce to `rx >= 2`,
   `rx <= width - 3` (the anchorable range, validated up front) and `3 <= w <= width - 2`
   (true for every drawn size, since `MIN_ROOM_SIZE == 4` and the draw is capped at
   `width - 2`, which is `>= 4` because `width >= MIN_ROOM_SIZE + 2`). So the anchor needs
   no retry loop, no fallback and no repair pass.
4. It is inserted into `_place_rooms`' list **before the rejection sampling starts**, so it
   is `rooms[0]` and every later candidate is rejected against it by the ordinary
   `intersects(margin=1)` test. Nothing is carved, reshaped or repaired afterwards, so
   **no door is ever orphaned** — requirements 8 and 9 are not implemented, per §3.2.
5. Being `rooms[0]` is load-bearing for G14: the corridor router marks `placed[0]` connected
   from the start and only ever *drops* rooms it cannot reach, so the anchor can never be
   dropped, whichever of `_lay_out`'s 8 layout attempts wins. The anchor is drawn once,
   before `_lay_out`, and reused unchanged by every attempt.
6. Because `rx` is strictly interior, all eight of its neighbours are floor of the same
   room, so it is an open spot (G13) — which is what lets the level *below* anchor at this
   level's down-stair in turn.

Measured cost: rooms/level 10.92 -> 10.88 over 200 seeds (better than RESEARCH-v3's
10.87 -> 9.71, because `_lay_out`'s retry loop absorbs most of the loss).

## How G8 remains guaranteed

Three independent reasons, in order of strength:

1. **Stairs do not change walkability.** Both stair tiles are in `tiles.WALKABLE`, and both
   are stamped over cells that were already room-interior `FLOOR`. The walkable set after
   stamping is bit-for-bit the set before it, so G8 cannot be affected by the stairs at all.
   A test (`test_stamping_a_stair_does_not_change_the_walkable_set`) pins this.
2. **The anchor changes the layout, not the invariant.** It is an ordinary room as far as
   `_blocked_mask`, `_door_candidates` and `_plan_corridors` are concerned; it just happens
   to be placed first. The router's existing structural argument is unchanged: every route
   starts from a cell or room already connected to `rooms[0]` and ends at the room being
   joined, and an unreachable room is dropped rather than carved and stranded.
3. **It is re-verified on every single call.** `_assert_guarantees` still runs a flood fill
   from `level.player_start`, which G17 pins to `stairs_up` — so the one flood fill covers
   both v1's "from `player_start`" and v3's "from the up-stair" wording. A level that
   violated G8 would raise `RuntimeError` rather than be returned.

The tests re-verify it independently: 30 seeds x 3 map sizes **with** an anchor and 30 x 3
**without**, plus every room ceiling, plus twelve five-level descent chains. Ad-hoc stress
outside the suite: **9,720 levels** (9 sizes x 6 room ceilings x 60 seeds x
{no anchor, `(2,2)`, `(width-3, height-3)`}) and **400 chained levels** — zero G8, G13, G14,
G16 or G18 failures.

Assumptions made:
- **`depth` type errors.** CONTRACT-v3 §3.4's prose reads "`depth` not an `int` or `< 1` ->
  `ValueError`", but §11 v3's table says "`depth < 1` or non-int | `ValueError` /
  `TypeError`" and the brief's acceptance criteria say `depth="1"` raises `TypeError`. I
  followed the table and the acceptance criteria: **non-int -> `TypeError`, `< 1` ->
  `ValueError`**, with every `TypeError` raised before any `ValueError` (the v1 precedence
  rule, still pinned by `test_type_errors_take_precedence_over_value_errors`).
- **`bool` in `required_up` is accepted as `int`.** v1 rejects `bool` only for `seed`;
  `required_up=(True, True)` is `(1, 1)` and fails the anchorable range with `ValueError`
  anyway.
- **`required_up` must be a `tuple`**, not any 2-sequence — `[2, 2]` raises `TypeError`,
  matching "a 2-tuple of `int`".
- **The generator only ever *chooses* in-room open spots.** G10 requires `player_start` to
  be inside a room's floor rect and G17 makes it the up-stair, so the chooser is restricted
  to open spots lying in a room. A corridor cell can in principle be an open spot (two
  corridors merging into a 3-wide blob; measured **0** occurrences over 200 default levels)
  and is a perfectly legal `required_up` — it is simply never chosen. G14's test anchors at
  *every* open spot under the unrestricted §3.1 definition, so this is covered either way.
- **G13/G16 are unconditional, not lucky.** Every room is at least 4x4 (`randint` is floored
  at `MIN_ROOM_SIZE` and `width - 2 >= MIN_ROOM_SIZE` after validation), and every cell one
  step inside a room's floor edge has all eight neighbours inside that same rect. So each
  room offers at least four open spots: two distinct stairs always exist, and on a
  multi-room level a *different* room always has one. Room-*edge* cells are never open spots
  — their outward neighbour is the wall ring, and even beside a door, G9b keeps the cells
  flanking that door `WALL`.
- **RNG draw order and count changed, as the brief allows.** Two extra `randint` pairs for
  the anchor (before every other draw, when `required_up` is given) and two `randrange`
  calls for the stairs (after the layout). Levels therefore differ from v2 for every seed.
  Still one local `random.Random(seed)`; no module-level `random.*`; no `time`,
  `os.urandom`, `id()`, `hash()`; no set or dict iteration order reaching the output — the
  stair candidate lists are built by iterating rooms and `range`s in order.
- **`max_rooms` still counts the anchor**, so `len(level.rooms) <= max_rooms` holds and
  `max_rooms=1` yields a single-room level that is the anchor.
- **`_assert_guarantees` raises `RuntimeError`**, unchanged from T02/T09, and now also
  covers G13-G20 via the new `_assert_stairs`. Verified non-vacuous by mutation (below).
- **Three pre-existing tests were amended, not deleted** (listed above) — the same treatment
  T13 gave the two table-equality assertions in `tests/test_level.py`.
