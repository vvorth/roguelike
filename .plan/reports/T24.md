Assumptions made:
- **`Tab` is bound via `_NO_ARG_BINDINGS`** (the same table that already holds `DESCEND`,
  `ASCEND`, `AUTO_EXPLORE`, `WALK_PREFIX`), since `FIRE` and `TARGET_NEXT` share their
  `dx == dy == 0` shape and the brief says to extend, not restructure, the table-driven design.
  No new binding table was introduced.
- **`import curses.ascii` was added as a second top-level import statement**, alongside the
  existing `import curses`. Plain `import curses` does not expose the `curses.ascii` submodule as
  an attribute (verified interactively: `AttributeError: module 'curses' has no attribute
  'ascii'` without the explicit submodule import) — `curses.ascii.TAB` is unusable without it.
  This does not add a new import "root": both resolve to root module `curses`, so the
  leaf/stdlib-only AST checks in `test_keys.py` are unaffected and still pass.
- **`"\t"` and the bare int `9` were removed from `test_keys.py`'s "unknown keys" fixtures.**
  `ord('\t') == 9 == curses.ascii.TAB`, so both are now legitimately `TARGET_NEXT`, not
  `UNKNOWN`. Removing them (with an explanatory comment at each site, pointing to the new test
  that covers the code 9 case) was necessary to avoid a direct contradiction with the new
  binding; this is the one place existing v1-v4 test *fixtures* changed, though no v1-v4
  *behaviour* changed — 9 and Tab were previously unbound and untested for any specific kind
  beyond "not raising", and remain non-movement, `dx == dy == 0`, non-quit either way.
- **The F-vs-f trap named in the brief is covered by a dedicated test**
  (`test_lowercase_f_is_fire_uppercase_f_is_still_unknown`) asserting both directions explicitly,
  plus `"F"` is folded into the general unknown-keys parametrize list and the `t`/`a`/`i`/`g`
  sweep, so a `F`/`f` swap would fail at least three independent tests.
