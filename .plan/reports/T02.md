## Algorithm chosen (for the integrator's end-to-end test)

**Room placement: random placement with rejection sampling.** Up to `max_rooms * 20`
candidate rectangles are drawn from the local RNG (size in `[MIN_ROOM_SIZE, MAX_ROOM_SIZE]`
clamped to `width - 2` / `height - 2`, position drawn so `1 <= x` and `x2 <= width - 2`,
likewise for `y`); a candidate is kept only if `not candidate.intersects(placed)` at the
default `margin=1` against every room already kept. `rooms` is in placement order.

**Corridors: L-shaped doglegs forming a spanning tree.** Each room *i > 0* is joined to the
nearest room *j < i* (Manhattan distance between floor centres, ties broken by the lower
index) with a two-leg corridor between the two floor centres; the RNG picks horizontal-leg-
first or vertical-leg-first.

**Why connectivity is guaranteed structurally.** Each room's floor is an internally
connected rectangle; each corridor is a 4-connected run of cells whose two endpoints are
room floor centres; and "room *i* joins some room *j < i*" is exactly a spanning tree over
the rooms. The union of rooms and corridors is therefore one 4-connected region, and
`player_start` (= `rooms[0].center`) lies in it. Nothing else is ever carved, so there are
no orphan stubs and no pockets. This is then *re-verified* at runtime by a flood fill in
`_assert_guarantees` before the `Level` is returned.

**Doors.** A corridor cell becomes `Tile.DOOR` iff it is currently `WALL`, lies on some
room's `on_perimeter`, and the corridor steps directly from it into *that same room's*
floor (checked against the path's immediate predecessor/successor). That rule places a door
only where a corridor genuinely pierces a wall — never mid-corridor, never alongside a wall
the corridor merely runs past. Corridor cells that are already walkable (room floors the
corridor crosses, cells an earlier corridor carved, earlier doors) are left untouched.

Contract deviations: none.

Assumptions made:
- **`intersects(margin=1)` expands both rectangles.** Confirmed by reading T01's code and
  report: two rooms whose floor rects are exactly one cell apart still report
  `intersects() == True` and are rejected by G5, so the minimum legal gap between floor
  rects is **two** cells and every room owns its own wall ring. The placement loop is
  designed around this rather than against it. On 80x22 it still yields ~3-13 rooms.
- **`bool` is rejected for `seed` only.** §3.1 says "`seed` not an `int`, **or a `bool`** →
  `TypeError`" but for `width`/`height`/`max_rooms` says only "not `int` → `TypeError`".
  Since `bool` is an `int` subclass, I took the literal reading: `generate_level(1,
  width=True)` passes the type check and then fails the size check with `ValueError`
  ("dimensions too small", which matches the §11 table), and `max_rooms=True` behaves as
  `max_rooms=1`. Adding a bool rejection for the dimensions would have contradicted the
  §11 row for too-small dimensions. Flagging it because it is the one place where a
  stricter reading is defensible.
- **Validation order.** All four type checks first (seed, then width, height, max_rooms),
  then `max_rooms < 1`, then `width`, then `height`. So a call that is wrong in several
  ways raises `TypeError` in preference to `ValueError`; tested.
- **`player_start` is `rooms[0].center`** — the centre of the first room placed. Always
  inside a floor rect, always `FLOOR`. The contract fixes only that it be inside some room
  and walkable, so the integrator should not depend on *which* room it is in.
- **`max_rooms` as a work ceiling.** `max_rooms * 20` candidate draws. Placing fewer rooms
  than `max_rooms` because the map filled up is correct and common (on 80x22 with
  `max_rooms=12`, typically 3-13 rooms result; at 6x6 exactly 1).
- **`_assert_guarantees` raises `RuntimeError`** if a finished level would violate
  G3-G10. The contract says "raise instead" without naming an exception type for this
  should-never-happen path; `RuntimeError` was my choice. It has never fired.
- **Room-count guarantee is structural.** The first candidate is always accepted (nothing
  to intersect) and a legal candidate always exists once `width, height >= MIN_ROOM_SIZE +
  2`, so `rooms` is never empty. There is an unreachable `if not rooms` fallback in
  `_place_rooms` so G4 cannot be broken by a future edit.
- **Determinism.** One `random.Random(seed)` per call, consumed in a fixed order
  (`randint` x4 per placement attempt, then `getrandbits(1)` per corridor). No module-level
  `random` calls, no `time`/`os.urandom`/`uuid`/`id()`/`hash()`, no set or dict iteration
  affecting output — the only `set` is inside the self-check flood fill and is used solely
  for membership and length. Nearest-room selection breaks ties on the lower index, so it
  is total-ordered.
