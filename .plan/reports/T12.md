```python
@dataclass(frozen=True)
class GameState:
    level: Level
    player: tuple[int, int]
    explored: frozenset[tuple[int, int]]
    visible: frozenset[tuple[int, int]]

    running: bool = True

def new_game(level: Level, radius: int = 20) -> GameState
def step(state: GameState, command: Command) -> GameState
def format_status(state: GameState) -> str    # UNCHANGED from v1
def run(stdscr, level: Level) -> None
def play(seed: int, width: int = 80, height: int = 22) -> None
```

One private helper: `_take_turn(state, player, open_doors) -> GameState`. It is the **only**
place field of view is recomputed after `new_game`, and therefore the single definition of what
a consumed turn does (turns + 1, recompute `visible`, `explored |= visible`). Its two callers are
exactly the two transitions CONTRACT-v2 §7 allows: an accepted move and a door opening. There is
no third way to reach it, so a turn cannot be consumed without sight being refreshed, and sight
cannot be refreshed without a turn being consumed — a property one test asserts directly by
sweeping all ten command kinds and requiring `recomputed == consumed_a_turn`.

One deliberate omission, permitted rather than required: **`game.py` does not import
`roguelike.world`.** CONTRACT-v2 §10 lists `world` among the modules `game.py` may import, and
the brief repeats that list, but nothing in §7 needs it — passability is decided inside
`movement.try_move` and transparency inside `fov.compute_visible`, both of which call `world`
themselves. Importing it to leave it unused would be re-derivable logic waiting to happen. The
import-graph test allows `roguelike.world` in the permitted set, so adding it later is not a
test change.

Assumptions made:
- **`new_game` sets `explored` to the same frozenset object as `visible`**, since they are equal
  by definition at turn 0. `frozenset` is immutable, so aliasing is unobservable, and the
  acceptance criterion `explored == visible` holds by construction.
- **A rejected move returns the *same object*, not an equal copy.** v1 did this and CONTRACT-v2
  keeps `UNKNOWN` "unchanged (may be the same object)"; extending it to a wall bump is what makes
  "FOV was not recomputed" assertable by identity (`after.visible is state.visible`) rather than
  by equality, which would pass even if a recompute happened and returned an equal set. Several
  tests rely on this and would need weakening to `==` if a future change returns a copy.
- **`ValueError` from `try_move` (`dx`/`dy` outside `{-1, 0, 1}`) and from `compute_visible`
  (negative radius) propagates out of `step`/`new_game` unchanged**, rather than being caught.
  Those rules belong to §6 and §14; `keys.translate_key` cannot produce such a command, so the
  only way to see them is a hand-constructed `Command` or radius, which is caller error. Pinned
  by a test for the radius case.
- **`open_doors` only ever grows**, like `explored`. There is no close-door path, no `o` command,
  no door-closing command, and no command kind beyond `MOVE`/`QUIT`/`UNKNOWN` — asserted by a
  test that `CommandKind` still has exactly three members and that the strings `OPEN`/`CLOSE`/
  `WAIT` do not appear in `game.py`'s source.
- **`radius` is carried through every transition** by `dataclasses.replace`, so a game started at
  a custom radius keeps it forever. `step` never reads `fov.DEFAULT_RADIUS`; only `new_game`'s
  default does.
- Test levels are hand-built from character grids (`#` wall, `.` floor, `+` door) so the
  assertions are exact; open/closed is decided solely by `open_doors`, never by a second tile
  value. `generate_level` is used only in five composition tests, and those assert relationships
  (`explored >= visible`, `turns == accepted + opened`, `open_doors` are all `Tile.DOOR` cells),
  never a specific room count, door count or grid — per T09's open questions 1-3.
- The bump-to-open rules are pinned on one 9x5 two-room level whose entire column `x == 4` is
  wall apart from a single door at `(4, 2)`, so "the room beyond is invisible until you open it"
  is a statement with no escape hatch: before the bump, none of the nine eastern floor cells is
  visible or explored; after it, all nine are both.

Open questions for integrator:

1. **`tests/test_integration.py` does not collect** — `from roguelike.render import
   render_to_lines` (line 27), a name CONTRACT-v2 §4 deliberately deletes. Confirmed by running
   it; it is yours, and I did not touch it. `render.to_lines(render.render_to_cells(...))` is the
   v2 equivalent, and note `render_to_cells` needs `visible`, `explored` and `open_doors`, which
   an integration test can take straight off a `GameState` from `new_game`/`step`.
   `main.py` needs no change: it imports only `game.play`, whose signature is unchanged.

2. **The live smoke test will see a nearly-blank first frame on a large level, and that is
   correct.** At radius 20 on 80x22 the player typically sees one room and a corridor mouth;
   everything else is `UNSEEN`, which §4.1 renders as a blank space, not a dimmed glyph. A tester
   expecting v1's fully-drawn map will read this as a bug. Walking reveals it.

3. **Bumping a door looks like nothing happened unless you watch the glyph.** The player does not
   move, so only the `+` -> `'` change and the `Turns:` counter show that the turn was spent.
   There is no message log (out of scope), so that is the entire feedback channel. This is the
   contracted behaviour, not a defect, but it is the one thing a play-tester is most likely to
   report.

4. **Cost per accepted move is ~2-3 ms of FOV** (T10's measurement, which I did not re-measure),
   against a blocking `getch`. A rejected move costs nothing at all — `step` returns the input
   object without touching `fov`.
