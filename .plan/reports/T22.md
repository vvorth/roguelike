```python
# roguelike/stats.py — __all__ = ["BASELINE", "Stats", "Derived", "Actor", "derive"]
BASELINE: int = 10

@dataclass(frozen=True)
class Stats:
    str_: int
    agi: int
    vit: int

@dataclass(frozen=True)
class Derived:
    max_hp: int
    speed: int
    evasion: int
    block: int

@dataclass(frozen=True)
class Actor:
    stats: Stats
    hp: int
    status_effects: tuple[StatusEffect, ...] = ()

def derive(stats: Stats) -> Derived

# roguelike/items.py — __all__ = ["WeaponKind", "Weapon", "DAGGER", "SHORTBOW"]
class WeaponKind(Enum):
    MELEE = auto(); RANGED = auto()

@dataclass(frozen=True)
class Weapon:
    name: str
    kind: WeaponKind
    damage_min: int
    damage_max: int
    range: int = 1

DAGGER: Weapon = Weapon("dagger", WeaponKind.MELEE, 2, 5, range=1)
SHORTBOW: Weapon = Weapon("shortbow", WeaponKind.RANGED, 1, 4, range=6)

# roguelike/status.py — __all__ = ["StatusKind", "StatusEffect", "REGEN_TURNS",
#                                   "apply_effect", "tick_effects"]
class StatusKind(Enum):
    POISONED = auto()

@dataclass(frozen=True)
class StatusEffect:
    kind: StatusKind
    remaining_turns: int
    magnitude: int

REGEN_TURNS: int = 10

def apply_effect(effects: tuple[StatusEffect, ...], new: StatusEffect) -> tuple[StatusEffect, ...]
def tick_effects(effects: tuple[StatusEffect, ...]) -> tuple[tuple[StatusEffect, ...], int]
```

Assumptions made:
- **`derive`'s internal `_clamp` helper is a private, unexported function.** The contract names
  only `derive` as the public surface of `stats.py`; `clamp` appears in prose, not in the code
  block, so I read it as an implementation detail rather than a symbol other modules should
  import.
- **`REGEN_TURNS` is a bare constant with no application logic.** §22.4 describes *how* the
  player regenerates (1 HP per `REGEN_TURNS` world-ticks, capped at `max_hp`, player only), but
  the brief's "Out of scope" list explicitly excludes any `heal()` helper and `status.py`'s
  declared surface has no such function — applying it is `game.py`'s job (owned by another
  task). I only carry the constant, and said so rather than adding a helper nobody asked for.
- **`tick_effects` does not deduplicate by `StatusKind`.** The contract's invariant ("never more
  than one entry per kind") is `apply_effect`'s responsibility to maintain going in; `tick_effects`
  is specified purely in terms of "each effect" and I implemented it that way. Documented and
  tested explicitly (`test_tick_effects_damage_equals_sum_of_magnitudes`) so a caller that somehow
  hands it two entries of the same kind gets defined, not surprising, behaviour.
- **Frozen-dataclass equality is used to compare `StatusEffect`/`Derived`/`Weapon` instances in
  tests** rather than field-by-field assertions everywhere, since `@dataclass(frozen=True)`
  generates `__eq__` and the acceptance criteria's own table format ("exactly `Derived(...)`")
  invites it. Every acceptance-criteria row that asks for "all four fields explicitly" also has
  a field-by-field assertion alongside the equality check (see
  `test_derive_at_baseline_matches_all_four_fields_exactly`).

3. **`block`'s floor-toward-negative-infinity behaviour is exercised at an odd sub-baseline
   value** (`str_ == 5` → `(5-10)//2 == -3`, clamped to `0` by the outer `max(0, ...)`) so that a
   future accidental swap to `int((str_-10)/2)` — which would give `-2` — has a test positioned
   to catch the *rounding direction*, not just the final clamped-to-zero result. Worth keeping
   in mind if `combat.py` (T25) implements the parallel STR damage modifier: that modifier is
   *not* clamped to zero the way `block` is, so the same rounding trap is live there in a form
   this task's tests cannot see.
