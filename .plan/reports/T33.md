## THE LOOKUP — what `combat.py` needs

```python
def resistance_of(species: Species, damage_type: DamageType) -> Resistance
```

Pure function, two positional args (`species`, `damage_type`), both required, no defaults.
Returns a `roguelike.items.Resistance`. Looks up `SPECIES_DATA[species].resistances`, defaulting
to `Resistance.NORMAL` for anything not in that dict. Never raises for any real `Species` /
`DamageType` pair. Exported in `npc.__all__`.

## Shape chosen

`SpeciesData` gained one field:

```python
resistances: dict[DamageType, Resistance] = field(default_factory=dict)
```

Absence means `NORMAL` (per the field's own docstring, already in place from the prior
session) — the dict holds only exceptions, so `Species.RAT` and `Species.JACKAL` carry an
empty `{}`. `resistance_of` is the one place that applies that default; nothing else should
index `.resistances` directly.

## Open questions

None blocking. Two things worth flagging for `combat.py` (T32) and any integration test:

- `resistance_of` takes the *species enum*, not an `NPC` or `Actor` — the caller resolves
  `npc.species` itself and passes that in. This mirrors how `SPECIES_DATA[npc.species]` is
  already read elsewhere in this codebase (e.g. `wants_to_flee`).
- The player has no species and is never a valid input to `resistance_of` — resistance in
  this bestiary is a monster-only concept, per §26.3's table (only the four `Species` members
  appear). If `combat.py` ever needs a "does the player resist" case, that is out of this
  module's scope and not something this task's contract mentions.
