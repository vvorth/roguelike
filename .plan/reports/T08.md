Assumptions made:
- Capability ladder thresholds: colors >= 256 uses the binding palette; 8 <= colors < 256 uses
  COLOR_WHITE (7, ANSI literal) for TERRAIN/PLAYER and COLOR_YELLOW (3, ANSI literal) for DOOR,
  with EXPLORED equal to VISIBLE (dim signal deferred to the renderer, per §15.2); colors < 8
  returns color = -1 for every role/visibility. This matches the two boundary rows the contract
  specifies explicitly (>=256 and <8) and the ">= 8" row's "COLOR_WHITE / COLOR_YELLOW" wording,
  extrapolated to the one un-stated case (PLAYER at 8 <= colors < 256): I used COLOR_WHITE + bold,
  consistent with "PLAYER — white, bold" holding at every capability level except mono, where
  bold is kept (it's a renderer attribute independent of colour) but color becomes -1.
- Interpreted "distinguishable colours" at colors=8 as TERRAIN (7) != DOOR (3), which the
  COLOR_WHITE/COLOR_YELLOW assignment satisfies directly.
- role_for(tile, is_player=True) returns Role.PLAYER regardless of tile validity; only Tile.WALL,
  Tile.FLOOR, Tile.DOOR exist per tiles.py so no other tile values are reachable.
