# T26 — NPCs, AI and spawning
Status: todo
Depends on: T22 (`stats.py`, `status.py`), T23 (`fov.has_line_of_sight`)

## Goal
The monster type, the four-species bestiary, the two-state AI that decides what a monster does
each turn, and the spawn rule that places them on a level.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1–4 are complete and passing **1982 tests**: a procedurally generated multi-level
dungeon, field of view, fog of war, doors, colour, diagonal movement, pathfinding and automatic
navigation.

Version 5 populates the dungeon. You own the monsters: what they are, how they decide, and where
they start. Another worker owns the turn loop that executes your decisions.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Another worker is running in parallel on combat arithmetic.

**Your module decides; it does not act.** `plan_action` returns an `NpcAction` *intent* —
wait, move here, attack — and `game.py` carries it out. This is the same split that put the
planners in `activity.py` and `advance` in `game.py`, and it is what keeps the import graph
acyclic: **`npc.py` must not import `combat`, `game`, `render`, `keys` or `events`.**

**The user asked for off-screen simulation, and this is where it lives.** Monsters run their
real AI every turn whether or not the player can see them. That was measured and is affordable:
per-hunter A\* costs ~0.5 ms, and a line-of-sight check costs 0.167 ms.

### Two things that are easy to get wrong and produce an unplayable game rather than a crash

1. **Spawn clustering.** Measured: a baseline player beats **one** jackal 97% of the time and
   **two** jackals **0% of the time** — 600 simulated fights, zero wins. Being surrounded is
   death. So a spawn rule that can drop two monsters next to each other beside the player's
   starting staircase kills level-1 characters through no fault of their own. The two radius
   rules in §24.4 are hard requirements, not preferences.
2. **Lockstep packs.** If every monster spawns with `energy = 0`, they all act on the same ticks
   and a group moves as one organism. Seed the starting energy randomly. It is one line.

### Use the pathfinder you already have

`pathfind.find_path` is written, tested and frozen. Call it. **Do not write a Dijkstra map, a
flow field, a path cache, or incremental replanning.** This was measured: a shared Dijkstra map
is *slower* than plain A\* until about 12–15 monsters are hunting simultaneously, and version 5
puts six on a level. Re-plan every turn, exactly as the player's travel activity already does.

Out of scope, explicitly — do not build, do not stub: combat arithmetic (another worker owns it),
XP awards, death handling, rendering, message generation, monster factions or infighting,
fleeing, ranged monster attacks, depth-scaled spawn tables, monster inventories, or a fifth
species. Extra surface is a defect, not initiative.

Coordinates are `(x, y)`, origin top-left, `y` grows **down**.

## Produce

`roguelike/npc.py` (new):
```python
class Species(Enum):
    RAT = auto(); JACKAL = auto(); GIANT_BAT = auto(); CAVE_SNAKE = auto()

@dataclass(frozen=True)
class SpeciesData:
    name: str; glyph: str
    stats: Stats
    attack_min: int; attack_max: int
    xp_value: int
    poison_chance: int = 0

class AiState(Enum):
    WANDERING = auto(); HUNTING = auto()

@dataclass(frozen=True)
class NPC:
    actor_id: int
    species: Species
    actor: Actor
    position: Coord
    energy: int = 0
    ai_state: AiState = AiState.WANDERING
    memory: int = 0

class NpcActionKind(Enum):
    WAIT = auto(); MOVE = auto(); ATTACK = auto()

@dataclass(frozen=True)
class NpcAction:
    kind: NpcActionKind
    target: Coord | None = None

SPECIES_DATA: dict[Species, SpeciesData]
PERCEPTION_RADIUS: int = 10
FORGET_TICKS: int = 5
MONSTERS_PER_LEVEL: int = 6
SPAWN_SAFE_RADIUS: int = 8
SPAWN_MIN_SEPARATION: int = 5

def plan_action(rng, npc: NPC, level: Level, open_doors: frozenset[Coord],
                occupied: frozenset[Coord], player: Coord) -> NpcAction
def spawn_npcs(rng, level: Level, first_actor_id: int = 1) -> tuple[NPC, ...]
```

### The bestiary — binding

| Species | `name` | Glyph | Stats (STR/AGI/VIT) | Attack | XP | Poison |
|---|---|---|---|---|---|---|
| `RAT` | `rat` | `r` | 4/14/3 | 1–3 | 5 | 0 |
| `JACKAL` | `jackal` | `j` | 8/13/5 | 2–4 | 10 | 0 |
| `GIANT_BAT` | `giant bat` | `B` | 3/18/2 | 1–2 | 8 | 0 |
| `CAVE_SNAKE` | `cave snake` | `s` | 6/8/5 | 2–4 | 12 | **30** |

HP, speed, evasion and block are **derived by `stats.derive`** and must not be stored on
`SpeciesData`. `name` is lower-case because messages read `The {name} hits you.`

### `plan_action` — binding

**WANDERING:**
- Perception: `fov.has_line_of_sight(level, open_doors, npc.position, player)` **and** Chebyshev
  distance ≤ `PERCEPTION_RADIUS`. **Argument order is `(observer, target)` — the NPC is the
  observer.** On success, return an action appropriate to hunting *this same turn* (see below).
- Otherwise a coin flip: `WAIT`, or `MOVE` to a uniformly chosen legal orthogonal neighbour.
  No legal neighbour → `WAIT`.

**HUNTING:**
- Chebyshev distance 1 from the player → `ATTACK` with `target = player`.
- Otherwise `find_path` to the player and `MOVE` to `path[1]`. No path → `WAIT`.

**The state transition itself belongs to `game.py`, not to you** — `plan_action` is pure and
returns only an action. But it must *behave* as though the transition has happened: an NPC that
can see the player should return a hunting action immediately, not waste a turn wandering. Make
this explicit in your report so the integrator knows exactly where the state changes.

**Legality of a `MOVE` target:** passable by `world.is_planning_passable` (so a closed door is a
legal target — the NPC bumps it open) **and not in `occupied`**. `occupied` holds every other
NPC's position and the player's. NPCs do not stack and do not swap places. The predicate you
hand to `find_path` must exclude `occupied` too, or a monster will path straight through its
neighbour.

**Not restricted to `explored`.** An NPC is not fogged — it lives on this level and knows it.
That is the opposite of how the player's travel activity plans, and it is deliberate.

### `spawn_npcs` — binding
- Places **exactly `MONSTERS_PER_LEVEL` (6)** NPCs, unless the placement rules cannot be met.
- Only on cells passable with an **empty** `open_doors` set.
- **Never within `SPAWN_SAFE_RADIUS` (8, Chebyshev) of `level.player_start`.**
- **Never within `SPAWN_MIN_SEPARATION` (5, Chebyshev) of another spawned NPC.**
- Species chosen uniformly from the four.
- `energy` seeded to `rng.randrange(0, 100)` — **not 0**.
- `actor.hp` starts at the species' full `max_hp`; `status_effects` starts empty.
- `actor_id` is assigned sequentially from `first_actor_id`. **The player is permanently
  `actor_id 0`**, so NPC ids start at 1.
- If the rules cannot be satisfied after a **bounded** number of attempts, place **fewer** NPCs.
  Never relax the rules, and never loop forever.

## Acceptance criteria
- `SPECIES_DATA` has exactly four entries, one per `Species` member, with the names, glyphs,
  stats, attack ranges, XP values and poison chances in the table above. Assert each field.
- **Derived values come out right with no special cases** — assert via `stats.derive`:
  rat `max_hp 17, speed 140, evasion 17, block 0`; jackal `25/130/14/0`;
  giant bat `13/180/29/0`; cave snake `25/80/0/0`.
- Only `CAVE_SNAKE` has a non-zero `poison_chance`, and it is exactly `30`.
- `PERCEPTION_RADIUS == 10`, `FORGET_TICKS == 5`, `MONSTERS_PER_LEVEL == 6`,
  `SPAWN_SAFE_RADIUS == 8`, `SPAWN_MIN_SEPARATION == 5`.
- **`plan_action`, HUNTING, adjacent:** returns `ATTACK` targeting the player from all eight
  adjacent cells, including diagonals.
- **`plan_action`, HUNTING, distant:** returns `MOVE` to a cell that is one step along a real
  path towards the player — assert the returned target is adjacent to the NPC and strictly
  closer to the player.
- **`plan_action`, HUNTING, unreachable player** (walled off): returns `WAIT`, never raises.
- **`plan_action`, WANDERING, player in plain sight within radius:** returns a hunting action
  (`ATTACK` if adjacent, else `MOVE` towards the player) — not a random wander.
- **`plan_action`, WANDERING, player visible but beyond `PERCEPTION_RADIUS`:** wanders. Assert
  with the player at Chebyshev distance 11 down a long clear corridor, so line of sight succeeds
  and only the radius rejects it.
- **`plan_action`, WANDERING, player behind a wall:** wanders even at distance 2.
- **A closed door blocks perception, an open one does not** — same coordinates, varying only
  `open_doors`.
- **Occupancy is respected:** a `MOVE` target is never in `occupied`; with the only route through
  an occupied cell, the NPC routes around it or returns `WAIT`, but never targets it. Assert two
  NPCs contending for one corridor cell do not both get it.
- **NPCs never swap places:** an NPC adjacent to another cannot `MOVE` onto that other's cell.
- **Closed doors are routable:** a hunting NPC whose only path runs through a closed door
  returns a `MOVE` towards it rather than `WAIT`.
- **NPCs are not fogged:** the same hunting NPC behaves identically regardless of what the
  *player* has explored — assert `plan_action` takes no `explored` argument and that its result
  is unchanged for two different explored sets (i.e. it genuinely cannot depend on one).
- **`spawn_npcs` placement, over at least 30 different seeds and several generated levels:**
  exactly 6 NPCs; every position passable; **every position at Chebyshev distance ≥ 8 from
  `level.player_start`**; **every pair of NPCs at Chebyshev distance ≥ 5**; all `actor_id`s
  distinct and starting at 1; every `hp` equal to that species' `max_hp`.
- **Energy is staggered, not zero:** across many seeds, spawned `energy` values take more than
  one distinct value and all lie in `range(0, 100)`. Assert explicitly that they are not all 0 —
  this is the lockstep-pack trap.
- **`spawn_npcs` terminates on a hostile map:** on a tiny or nearly-full level where the rules
  cannot be met, it returns **fewer** than 6 NPCs, does not raise, and does not hang. Give this
  test a strict wall-clock guard.
- **Determinism:** `spawn_npcs` with the same seed and level returns identical NPCs; and a
  `subprocess` run under two different `PYTHONHASHSEED` values produces the same spawn — a
  set-iteration-order dependency must fail this.
- **Purity:** `plan_action` and `spawn_npcs` do not mutate any argument; every dataclass rejects
  assignment.
- **Performance:** planning for 6 hunting NPCs on a full 80×22 level completes in well under
  50 ms. *Reference: ~0.5 ms per hunter.* Generous margin so it is not flaky.
- `npc.py` imports only the six permitted modules and no `curses` — assert with `ast`, and
  assert explicitly that it does **not** import `combat`, `game`, `render`, `keys` or `events`.
- No float literal in `npc.py`.
