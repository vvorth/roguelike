# T10 — Permissive field of view
Status: todo
Depends on: T07

## Goal
Compute, from the character's position, the exact set of cells currently in sight — using the
permissive model the project's visibility rule requires.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Version 1 is complete and passing 912 tests: it generates a dungeon of rooms and corridors,
walks an `@` around it, and quits cleanly, with the whole map always visible. Version 2 adds
fog of war: the map starts unexplored, and only what the character can actually see is shown in
full, with previously-seen areas dimmed. You own the geometry that decides what "can see"
means.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Another worker is building the renderer in parallel — it consumes the set you
return and decides how things *look*. You decide only *what is visible*. You must not import
the renderer, and it must not import you.

### The rule that decides the algorithm

The project's visibility requirement, stated by the user, is:

> "a symbol is considered visible if any side or corner is in direct eye sight"

**This rules out recursive shadowcasting**, the usual roguelike algorithm, which tests tile
**centres**. Testing sides and corners is the textbook definition of **permissive field of
view**, and that is what you must implement.

Three algorithms were prototyped and measured on real levels before this task was written:

| Algorithm | Cells visible (seed 1234, r=20) | Time / move | Faithful to the rule? |
|---|---|---|---|
| Recursive shadowcasting | 130 | 0.10 ms | **No** — misses 12 cells |
| **Permissive (8 sample points)** | **142** | **15.29 ms** | **Yes** |
| Hybrid: shadowcast + reveal touching walls | ~142 | 0.16 ms | **No** — over-shows 6.8% |

Permissive was measured to be a **strict superset** of shadowcasting: 12 cells it sees that
shadowcasting does not, and **zero** the other way. Those extra cells are wall corners — without
them, the walls of the room you are standing in have **holes in them**, the classic ragged-wall
artifact. Avoiding that is the whole point of the rule.

**Do not "optimise" this into the hybrid.** It is 100× faster and it was rejected because it
reveals wall segments *around corners the character cannot see* — a measured 6.8% over-show.
That leaks map information to the player. A cheap approximation that leaks is worse than a
slow correct rule, and 15 ms against a human keypress budget of ~100 ms is imperceptible.
**Correctness is the priority here, explicitly, and speed is not a goal.**

Out of scope, explicitly — do not build, do not stub: monsters, combat, items, inventory,
save-load, multiple levels, stairs, sound, colour. No light sources, no light levels, no
per-cell brightness or distance falloff, no memory of *when* a cell was seen, no per-entity
FOV. You return a set of coordinates; nothing more.

Coordinates are `(x, y)`, origin top-left, `x` grows right, `y` grows **down**, so up is
`dy = -1`. Grid storage is `grid[y][x]`.

### The visibility rule, precisely
- The **eye** is the centre of the origin cell: `(ox + 0.5, oy + 0.5)`.
- Cell `(x, y)` has **eight sample points** — four corners `(x, y)`, `(x+1, y)`, `(x, y+1)`,
  `(x+1, y+1)`, and four side midpoints `(x+0.5, y)`, `(x+0.5, y+1)`, `(x, y+0.5)`,
  `(x+1, y+0.5)`.
- `(x, y)` is **visible** iff it is within `radius` **and** at least one sample point is
  reachable from the eye by a straight segment crossing **no opaque cell**, where opaque means
  `not world.is_transparent(...)`.
- Cells crossed are judged **excluding the origin cell and the target cell itself**. This is
  what lets you see the *face* of a wall — the rule's whole point.
- **Diagonal-corner rule:** where a segment passes exactly through a grid lattice point, it is
  blocked **only if both cells diagonally flanking that point are opaque.** This stops sight
  leaking through a diagonal join of two walls while still allowing corner peeking.

The segment-clearance test itself is **your choice** — supercover line, dense sampling, or
exact rational arithmetic — provided F1–F9 hold. Dense sampling must be fine enough that no
cell of the crossed run is skipped.

## Constraints
- Python 3.10+, **standard library only**. `from __future__ import annotations` at the top.
- Imports from the project: **only** `roguelike.level` and `roguelike.world`. Plus stdlib
  `math` if you want it. **No `curses`** — FOV has no business with a terminal. You must not
  import `roguelike.render`, `roguelike.game`, `roguelike.generator`, or `roguelike.style`.
- **Opacity comes only from `world.is_transparent`.** Do not call `level.tile_at` and compare
  to `Tile.WALL` yourself, and do not re-derive the closed-door rule — it has one home, and
  duplicating it is how the two copies drift apart.
- Pure and deterministic: no RNG, no mutation of any argument, no I/O, no module-level mutable
  state, no caching keyed on anything, and **no dependence on set iteration order**.
- Return a `frozenset`. Never return `None`.
- `radius` is a parameter, not a constant. `DEFAULT_RADIUS = 20`.
- Negative `radius` → **`ValueError`**. `radius=0` → exactly `{origin}`.
- The origin is **always** in the result (F1), even if the character stands on a wall or on
  terrain that is itself opaque.
- Every returned cell must be **in bounds** and within Euclidean radius
  (`(x-ox)² + (y-oy)² <= radius²`).
- Do not implement shadowcasting, and do not add a `fast=True` mode or any approximation
  switch. There is one algorithm here.
- Build test levels by constructing `Level` directly with hand-written character grids. **Do
  not import the generator** — another worker is editing it. A tiny helper in your test file
  that turns a list of strings into a `Level` will make every test in this task readable; write
  one.
- Tests must not initialise curses and must pass with no TTY. No `conftest.py`.

## Acceptance criteria
- **F1** `origin` is always in the result — on floor, on a wall, and with `radius=0`.
- **F2** Every returned cell is in bounds and satisfies `(x-ox)² + (y-oy)² <= radius²`; sweep
  several radii on an open level and assert no cell escapes either bound.
- **F3** Purity and determinism: two identical calls return equal sets; a `deepcopy` of the
  level compares equal afterwards; `open_doors` is unmodified.
- **F4 (superset property)** On an open room and on a level with a pillar, **every cell whose
  centre has unobstructed sight from the eye is visible.** Implement a simple independent
  centre-to-centre ray test in the test file and assert the result is a subset of
  `compute_visible`. Permissive must never see less than centre-only.
- **F5** A pillar casts a shadow: on a hand-built open level with a single wall cell between
  the eye and a far cell, that far cell is **not** visible, and the shadow widens with distance.
- **F6** No holes in the walls of the room you stand in: build a rectangular room, stand in the
  middle, and assert **every** cell of the surrounding wall ring is visible. This is the
  ragged-wall artifact test and it is the reason the permissive rule exists.
- **F7** A **closed door is opaque**: build two rooms joined by a door, stand in one, and
  assert no cell of the far room is visible. Add the door to `open_doors` and assert cells of
  the far room now **are** visible. This is the single most important behavioural test in the
  task.
- **F8** `radius=0` → exactly `{origin}`. `radius=-1` → `ValueError`.
- A cell directly behind a long wall is never visible, at any radius.
- **Diagonal-corner rule:** build a diagonal join of two walls and assert sight does **not**
  leak through the lattice point between them; build a single wall corner and assert corner
  peeking still works.
- Sight is not blocked by the target cell itself — a wall adjacent to the eye is visible.
- A level that is entirely wall returns `{origin}` plus at most the immediately adjacent ring;
  nothing raises.
- A 1×1 level returns `{origin}`.
- Radius larger than the map (e.g. 1000) does not raise and returns only in-bounds cells.
- `fov.py` imports only `roguelike.level`, `roguelike.world`, and stdlib — asserted by parsing
  the source with `ast`. It does not import `curses`, `render`, `game`, `generator`, or `style`.
- No test in this file initialises curses; the suite passes with stdin from `/dev/null`.
