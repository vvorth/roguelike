# T27 — Rendering NPCs and the stats row
Status: todo
Depends on: T24 (`events.py`), T26 (`npc.py` — the species glyphs)

## Goal
Draw monsters, colour them, highlight the ranged-attack target, and fill in the top chrome row
that has been deliberately blank since version 3.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1–4 are complete and passing **1982 tests**: a procedurally generated multi-level
dungeon, field of view, fog of war, doors, colour, diagonal movement, pathfinding and automatic
navigation.

Version 5 adds monsters, hit points and levelling. They need to be visible.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. You are the only worker running right now.

**The renderer never mutates state and never decides anything.** It is handed primitives — a
level, a position, some frozensets, a `Chrome` of finished strings — and returns cells. That
separation is what has let the renderer be written by someone who never spoke to the game loop's
author, and it must survive this change: **you receive NPC positions and glyphs, you do not
receive a `GameState` and you do not import `game.py`.**

`style.py` is pure data with **no `curses` import at all** — that is what makes it testable with
no terminal. Keep it that way. Allocating colour pairs belongs to `render.py`.

### The one visibility rule that matters

**Monsters are drawn only when currently visible, never from memory.** Terrain is remembered —
that is fog of war, and a wall you saw an hour ago is still there. A monster you saw an hour ago
has moved. Drawing a monster from `explored` would be drawing a lie, and it is the single most
likely mistake in this task.

Out of scope, explicitly — do not build, do not stub: a health bar, a minimap, a message log
pane, monster health display, animation, a separate cursor glyph, a sidebar, or any new `Chrome`
field beyond what the contract names. Extra surface is a defect, not initiative.

Coordinates are `(x, y)`, origin top-left, `y` grows **down**. The `(y, x)` inversion curses
needs lives inside `render.draw` and nowhere else.

## Produce

`roguelike/style.py` (modified) — `Role` gains `NPC`:
```python
class Role(Enum):
    TERRAIN = auto(); DOOR = auto(); PLAYER = auto()
    NPC = auto()      # NEW
```

Per-species 256-colour indices, binding:

| Species | Colour |
|---|---|
| rat | `250` |
| jackal | `173` |
| giant bat | `140` |
| cave snake | `70` |

At 8 colours every NPC is red (`curses.COLOR_RED`, spelled as the literal `1` — this module
must not import `curses`). Monochrome: terminal default (`-1`).

`roguelike/render.py` (modified) — accepts NPCs to draw and the current ranged target, and
renders both.

Plus modifications to `tests/test_render.py` and `tests/test_style.py`.

### Binding rules
- An NPC is drawn **only when its position is in `visible`**. Never from `explored`.
- The NPC glyph is drawn over the terrain, exactly as the player glyph already is.
- **The player glyph wins** over an NPC glyph on the same cell. (The occupancy rule upstream
  makes this unreachable, but the renderer must not depend on an invariant it cannot check.)
- **`attr_for(Role.NPC, Visibility.EXPLORED)` raises `ValueError`**, exactly as
  `(Role.PLAYER, Visibility.EXPLORED)` already does — an NPC is only ever drawn when visible, so
  asking for its dimmed attribute is a caller bug.
- `attr_for(Role.NPC, Visibility.UNSEEN)` raises, like every other role.
- When a ranged target is selected, **that cell is drawn with `curses.A_REVERSE`**. This is the
  only cursor; **no separate cursor glyph is drawn** and no character is changed.
- `role_for` still returns `Role.PLAYER` for the player regardless of the tile beneath, and the
  existing terrain/door behaviour is unchanged.

### `format_stats` layout
Another worker makes `game.py` produce:
```
HP {hp}/{max_hp}  Lv {level}  XP {xp}/{xp_to_next}  Str {s} Agi {a} Vit {v}
```
Two spaces between fields. **You do not write that string** — you receive it as
`Chrome.stats` and must pad or clip it to the terminal width exactly as you already do. Your
tests should cover a stats row that is longer than the terminal.

## Constraints
- Python 3.10+, **standard library only**. `from __future__ import annotations` at the top.
- **`style.py` must not import `curses`** — at all. Spell colour indices as integer literals with
  a comment naming the curses constant, exactly as the module already does for white and yellow.
- `style.py` imports only `roguelike.tiles`. `render.py` imports only `roguelike.tiles`,
  `roguelike.level`, `roguelike.style` and `curses`. **Neither may import `game`, `npc`,
  `combat`, `stats` or `events`.**
- **`render.py` must not import `npc.py`.** Glyphs and species identity arrive as parameters. If
  you need a type for "an NPC to draw", define a small local structure or accept plain tuples —
  the renderer must stay usable without the monster module.
- No module may call `initscr`, `wrapper`, or any terminal-mutating curses function at import
  time. Colour pairs are allocated in `init_colors`, called by the game loop after curses is up.
- `init_colors` must keep degrading gracefully: monochrome terminals and terminals without
  `use_default_colors` must not raise.
- The renderer never mutates its arguments and never decides game rules.
- Clipping behaviour is unchanged: a terminal smaller than the map draws what fits and never
  raises, including the bottom-right cell.
- Extend the existing structures; do not restructure the renderer's cell model or `Chrome`.
- Tests must not initialise curses and must pass with no TTY — use the existing `to_lines`
  / cell-inspection approach rather than a real screen. No `conftest.py`.

## Acceptance criteria
- `len(Role) == 4` and the new member is exactly `NPC`.
- **The four species colours** are returned by `attr_for(Role.NPC, Visibility.VISIBLE, colors=256)`
  per species — assert each of `250`, `173`, `140`, `70`. (How a species selects its colour is
  your design; state it in your report.)
- At `colors=8` every NPC attribute is red; at `colors=2` (or 0) it is `-1`.
- **`attr_for(Role.NPC, Visibility.EXPLORED)` raises `ValueError`**, and so does
  `attr_for(Role.NPC, Visibility.UNSEEN)`. Assert both.
- Every existing `style.py` behaviour is unchanged — assert the full v2 palette table again:
  terrain `250`/`238`, door `180`/`94`, player `231` bold, and the 8-colour and monochrome
  fallbacks.
- **A visible NPC is drawn**: its glyph appears at its cell in the rendered output.
- **An NPC on an explored-but-not-currently-visible cell is NOT drawn** — the terrain glyph
  appears instead. Name this test after the rule; it is the headline correctness criterion.
- **An NPC on an unseen cell is not drawn** and reveals nothing about the terrain.
- **The player glyph wins** when a player and an NPC occupy the same cell.
- Multiple NPCs of different species render their correct distinct glyphs simultaneously.
- **The ranged target cell carries `curses.A_REVERSE`** in its attribute, its glyph is
  **unchanged**, and no other cell carries `A_REVERSE`. With no target selected, no cell does.
- The target highlight applies to the NPC's cell even though the NPC glyph is drawn over
  terrain — assert the glyph is still the species glyph, not a cursor character.
- **`Chrome.stats` is rendered into the top row**, padded to the terminal width; a stats string
  longer than the terminal is clipped and does not raise or wrap.
- Every existing renderer property still holds: map rows in the right places, status row layout,
  message versus `status_right` collision behaviour, unseen cells blank, explored cells dimmed,
  the open-door glyph `'` versus the closed `+`, and clipping on a terminal smaller than the map.
- **`style.py` contains no `curses` import** — assert with `ast`. **`render.py` does not import
  `npc`, `game`, `combat`, `stats` or `events`** — assert with `ast`.
- No module-level terminal initialisation — assert no `initscr`/`wrapper`/`setupterm` call
  outside `init_colors` (`ast` walk).
- Tests pass with no TTY.
