# T07 — Runtime passability seam
Status: todo
Depends on: none

## Goal
Introduce the single home for "what is the world like right now" — passability and
transparency in the presence of openable doors — and move the movement layer onto it.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Version 1 is complete and passing 912 tests: it generates one dungeon level of rooms and
corridors, walks an `@` around it, and quits cleanly. Version 2 adds colour, fog of war, and
field of view. You are building the foundation of that increment.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Two other workers are running in parallel on unrelated files.

**The invariant you are changing.** In v1, walkability was a pure function of the map:
`Level.is_walkable(x, y)` answered completely from frozen terrain, and `movement.try_move` was
built on that one predicate — which is what collapsed walls, borders and off-map into a single
rejection branch and kept `movement.py` at about 40 lines.

v2 gives doors an **open/closed state**. A closed door is *terrain-walkable but currently
impassable*, and its state changes during play. So passability is no longer derivable from the
map alone. The state cannot live in `Level` either — `Level` is a frozen dataclass, generated
once, and deliberately immutable so the renderer cannot touch it.

The resolution is a new module, `roguelike/world.py`, holding the two runtime predicates, with
the open-door set threaded in as an explicit parameter. Both the movement layer (yours) and the
field-of-view module (another worker, later) go through it, so the door rule has exactly one
implementation.

**Passability and transparency genuinely differ now**, which is why there are two predicates
and not one: a floor cell is both; a closed door is neither; an open door is both; a wall is
neither — but for a different reason, and future terrain would separate them further. Do not
collapse them into one function.

Out of scope, explicitly — do not build, do not stub: monsters, combat, items, inventory,
save-load, multiple levels, stairs, sound. No lock/key state on doors, no door HP, no trap
doors, no secret doors. No `o`-to-open command (opening is handled by another task via
"bump-to-open"). Extra surface is a defect here, not initiative.

Coordinates are `(x, y)`, origin top-left, `x` grows right, `y` grows **down**, so up is
`dy = -1`. Grid storage is `grid[y][x]`.

def is_closed_door(level: Level, open_doors: frozenset[tuple[int, int]], x: int, y: int) -> bool

@dataclass(frozen=True)
class MoveResult:
    position: tuple[int, int]
    moved: bool

    level: Level,
    position: tuple[int, int],
    dx: int,
    dy: int,
    open_doors: frozenset[tuple[int, int]] = frozenset(),

## Constraints
- Python 3.10+, **standard library only**. `from __future__ import annotations` at the top.
- `world.py` imports **only** `roguelike.tiles` and `roguelike.level`. `movement.py` imports
  **only** `roguelike.level` and `roguelike.world` (and optionally `roguelike.tiles`).
  No `curses` in either — neither has any business with a terminal.
- **`Level.is_walkable` keeps its exact v1 meaning** — *terrain* walkability, with a `DOOR`
  cell always counting as walkable terrain. Do not change it, do not reinterpret it, and do
  not edit `level.py`.
- All three `world` predicates **return `False` out of bounds and never raise**. Pure: no
  module-level state, no caching, no mutation, no I/O.
- `open_doors` is a `frozenset[tuple[int, int]]` and defaults to `frozenset()` on `try_move`,
  so every v1 call site keeps working.
- `try_move` must use `world.is_passable` for the target test — **not** `level.is_walkable`,
  and not a re-derived bounds check. The uniform rejection path is the design.
- If the target is a **closed door**, return `MoveResult(position, False,
  blocked_by_door=(tx, ty))`. All other rejections leave `blocked_by_door=None`.
- Everything else in v1 §6 is unchanged and still binding: unchanged position on rejection
  (return the caller's own tuple object), `(0, 0)` → `moved=False` unconditionally,
  `dx`/`dy` outside `{-1, 0, 1}` → `ValueError` raised **before** anything else, no
  corner-cutting rule (a diagonal move is legal iff the destination is passable), purity, and
  never raising for an ordinary illegal move.
- `MoveResult` stays `frozen=True`; `blocked_by_door` is a **third** field with a default, so
  v1 positional construction `MoveResult(pos, True)` still works.
- `is_blocked` is retained **exactly as it is** — terrain-only, `not level.is_walkable(x, y)`.
  Do not route it through `world`. It exists for v1 compatibility.
- `tiles.py`: add `DOOR_OPEN_CHAR` and **nothing else**. `Tile` gains no member — the grid keeps
  one `Tile.DOOR` and open/closed is a runtime concern. `TILE_CHARS[Tile.DOOR]` stays `"+"`.
  If `tiles.py` has an `__all__`, add the new name to it.
- Build test levels by constructing `Level` directly with hand-written grids. **Do not import
  the generator** — another worker is editing it right now.
- Tests must not initialise curses and must pass with no TTY. No `conftest.py`.
- The existing `tests/test_movement.py` (67 tests) must **still pass** — extend it, do not
  gut it. Where a v1 test asserted two-field `MoveResult` behaviour, it must keep passing.

## Acceptance criteria
- `is_passable` is True for `FLOOR`, True for a `DOOR` in `open_doors`, **False** for a `DOOR`
  not in `open_doors`, False for `WALL`, and False for every out-of-bounds coordinate.
- `is_transparent` is True for `FLOOR`, True for an open `DOOR`, **False** for a closed `DOOR`,
  False for `WALL`, False out of bounds.
- `is_closed_door` is True only for a `DOOR` cell absent from `open_doors`; False for an open
  door, for `FLOOR`, for `WALL`, and out of bounds.
- The two predicates differ where they must: assert explicitly that for a closed door both are
  False, for an open door both are True, and that no input makes `is_passable` True while
  `is_transparent` is False (or vice versa) **for the current tile set** — with a comment noting
  this equivalence is incidental to today's three tiles, not a rule to rely on.
- None of the three predicates raises for any coordinate, including `(-1, -1)` and
  `(10**6, 10**6)`; sweep a small level plus a two-cell out-of-bounds margin.
- All three are pure: a `deepcopy` of the level compares equal after a full sweep, and
  `open_doors` is unmodified.
- `try_move` onto `FLOOR` → `MoveResult(target, True, None)`.
- `try_move` onto an **open** door → `moved=True`.
- `try_move` onto a **closed** door → `moved=False`, `position` unchanged **and identical**
  (assert with `is`), and `blocked_by_door == (tx, ty)`.
- `try_move` into a `WALL` → `moved=False`, `blocked_by_door is None`.
- `try_move` off every map edge → `moved=False`, `blocked_by_door is None`, no raise.
- `try_move` with no `open_doors` argument treats every door as closed — a v1 call site now
  gets `moved=False` where it used to get `moved=True`. Assert this explicitly; it is the
  intended behaviour change and must be visible in the tests.
- `dx`/`dy` of `2`, `-2`, `10` raise `ValueError`, tested on each argument, and raise **before**
  the door check.
- `try_move(level, pos, 0, 0)` → `moved=False`, no raise, standing on floor or on a door.
- All eight deltas work from a start position where `x != y`, landing on exactly
  `(x+dx, y+dy)`; `dy = -1` decreases `y`.
- `MoveResult` is frozen (`FrozenInstanceError` on assignment) and `MoveResult(pos, True)`
  still constructs positionally with `blocked_by_door is None`.
- `DOOR_OPEN_CHAR == "'"`, `TILE_CHARS[Tile.DOOR] == "+"` still, and `Tile` still has exactly
  three members `WALL`, `FLOOR`, `DOOR`.
- `world.py` imports nothing but `roguelike.tiles`, `roguelike.level` and the stdlib; asserted
  by parsing the source with `ast`. Neither `world.py` nor `movement.py` imports `curses`.
- The full pre-existing `tests/test_movement.py` behaviour still passes.
