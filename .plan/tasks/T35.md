# T35 — Chest glyph and the inventory screen
Status: todo
Depends on: T29 (`items.py` complete)

## Goal
Draw a chest on the map, and build the inventory screen's frame.

## Context
An interactive terminal roguelike, ADOM-ish, standard library only. Versions 1–5 are complete
(2615 tests). Version 6 adds items, and the player needs to see them.

Three other workers are running in parallel on unrelated modules.

**The renderer never mutates state and never decides anything.** It is handed primitives —
a level, a position, frozensets, a `Chrome` of finished strings — and returns cells. That
separation must survive this change: **you receive chest positions and finished inventory
lines; you do not receive a `GameState` and you do not import `game.py`.**

`style.py` is pure data with **no `curses` import at all**. Keep it that way.

**The inventory screen is not new layout work.** `render.render_text_page` already exists,
built for the help screen: it takes finished lines and a `Chrome` and returns a frame of the
same shape as a map frame. The inventory screen is that function with different lines — and
`game.py` composes the lines, because wording is not the renderer's business. **Do not build a
second full-screen layout.**

Out of scope: what the inventory lines say (that is `game.py`), item pickup, equipping, a
health bar, a minimap, an item glyph on the floor (items exist only inside chests in v6).

## Produce
`style.py`: `Role.CHEST` with a 256-colour index, an 8-colour fallback and a monochrome one.
Choose a colour that reads as treasure and is distinct from every existing role (terrain
250/238, door 180/94, player 231, projectile 226, the four species 250/173/140/70) — state your
choice in the report.

`render.py`: a chest glyph (proposed `~`, yours to choose — it must not collide with `#`, `.`,
`+`, `'`, `<`, `>`, `@`, `*`, or the species glyphs `r`, `j`, `B`, `s`), and a `chests`
parameter on `render_to_cells`, **appended with a default** so every existing call keeps working.

Plus `tests/test_render.py`, `tests/test_style.py`.

### The visibility rule for chests — decide it and say why
A monster is never drawn from memory because it moves. **A chest does not move.** So a chest
*should* be drawn from `explored`, like terrain — that is the recommendation, and it is what
makes a remembered chest worth walking back to. State the choice in your report either way.

## Constraints
- Python 3.10+, standard library only.
- **`style.py` must not import `curses`** — spell colour indices as integer literals with a
  comment naming the constant, as the module already does.
- `render.py` imports only `tiles`, `level`, `style` and `curses`. **It must not import
  `items`, `loot`, `npc`, `game`, `combat`, `stats` or `events`** — chest positions arrive as
  parameters, exactly as NPC glyphs do.
- No terminal initialisation at import; colour pairs allocated in `init_colors` only.
- The renderer never mutates its arguments and holds no game rules.
- Clipping behaviour unchanged.

## Acceptance criteria
- `Role` gains exactly `CHEST`; its colours assert at 256, 8 and monochrome.
- A chest is drawn at its position with the chosen glyph, and that glyph collides with nothing
  listed above — assert the collision check explicitly.
- The chest visibility rule you chose, asserted, with the test named after the reasoning.
- **The player and monsters still win over a chest on the same cell** — assert both.
- `render_text_page` still behaves exactly as it does today (the help screen depends on it):
  frame shape, clipping a long line, blank rows for a short page, every cell plain visible
  terrain.
- An inventory screen renders through `render_text_page` with a title, item lines and a footer
  — assert the frame shape matches a map frame, since `draw` takes either.
- **Every existing renderer property still holds**: map rows, chrome rows, the status row's
  collision rule, unseen blank, explored dimmed, open vs closed door glyph, the ranged-target
  `reverse`, the projectile, NPCs never drawn from `explored`, and the pre-v6 call signature.
- `style.py` has no `curses` import; `render.py` imports none of the forbidden modules — both
  asserted with `ast`.
- Tests pass with no TTY. No `conftest.py`.
