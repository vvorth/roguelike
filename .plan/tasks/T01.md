# T01 — Core types: tiles and level
Status: todo
Depends on: none

## Goal
Provide the tile vocabulary and the immutable `Level`/`Room` data structures that every other
module in the project is defined in terms of.

## Context
This project is an interactive terminal roguelike engine with ASCII graphics, similar in feel
to ADOM. It is being built by several independent workers who never communicate; a frozen
contract document defines every seam where their code meets. You are writing the foundation
layer — three other modules (a dungeon generator, a renderer, and a collision/movement layer)
are being written against the types you produce, by people who cannot ask you questions.
Everything they need must therefore match the contract exactly.

The engine's scope is deliberately tiny: generate one dungeon level, walk an `@` around it,
quit cleanly. There are **no** monsters, combat, items, inventory, field of view, save-load,
multiple levels, stairs, sound, or colour — these are explicitly out of scope. Do not build
them, and do not add speculative placeholders, "for later" fields, or empty hook classes for
any of them. An `entities` list on `Level` would be a defect, not foresight.

The single most important convention in this codebase: **all coordinates are `(x, y)` with
origin top-left, `x` growing right and `y` growing DOWN — so "up" is `dy = -1`. Grid storage
is the one inversion: `grid[y][x]`, a sequence of rows.** Read CONTRACT §0.1 carefully before
writing a line.

Two design decisions you must implement rather than second-guess:
- `Level` is a **frozen** dataclass whose grid is a `tuple` of `tuple`s. This is deliberate:
  it makes "the renderer must never mutate game state" a structural guarantee enforced by the
  interpreter rather than a code-review promise.
- Out-of-bounds access is handled **two different ways on purpose**. `tile_at` raises
  `IndexError` because an off-map lookup is a caller bug that should be loud. `is_walkable`
  returns `False` and never raises because "can I step there?" has a correct answer outside
  the map. Do not unify them.

## Produce

`roguelike/tiles.py`:
```python
class Tile(IntEnum):            # WALL = 0, FLOOR = 1, DOOR = 2
TILE_CHARS: dict[Tile, str]     # {WALL: "#", FLOOR: ".", DOOR: "+"}
WALKABLE: frozenset[Tile]       # {FLOOR, DOOR}
PLAYER_CHAR: str                # "@"
def tile_char(tile: Tile) -> str
def is_walkable_tile(tile: Tile) -> bool
```

`roguelike/level.py`:
```python
@dataclass(frozen=True)
class Room:
    x: int; y: int; width: int; height: int
    @property
    def x2(self) -> int
    @property
    def y2(self) -> int
    @property
    def center(self) -> tuple[int, int]
    def contains(self, x: int, y: int) -> bool
    def on_perimeter(self, x: int, y: int) -> bool
    def intersects(self, other: "Room", margin: int = 1) -> bool

@dataclass(frozen=True)
class Level:
    width: int
    height: int
    grid: tuple[tuple[Tile, ...], ...]
    rooms: tuple[Room, ...]
    player_start: tuple[int, int]
    seed: int
    def in_bounds(self, x: int, y: int) -> bool
    def tile_at(self, x: int, y: int) -> Tile
    def is_walkable(self, x: int, y: int) -> bool

def freeze_grid(grid: list[list[Tile]]) -> tuple[tuple[Tile, ...], ...]
def blank_grid(width: int, height: int, fill: Tile = Tile.WALL) -> list[list[Tile]]
```

`tests/test_level.py` — unit tests covering both modules.

Field order on both dataclasses is binding: positional construction must work exactly as
written above.

## Constraints
- Python 3.10+, **standard library only**. No third-party imports, ever.
- `from __future__ import annotations` at the top of both modules.
- `roguelike/tiles.py` imports nothing from `roguelike`. `roguelike/level.py` imports only
  from `roguelike.tiles`. No other intra-package imports (CONTRACT §10).
- Do not import `curses` in either module — neither has any business with a terminal.
- Both dataclasses are `frozen=True`. Do not add mutating methods.
- `Room` describes the **floor rectangle only**; its walls are the ring outside it and are
  not part of `x/y/width/height`.
- `contains` and `on_perimeter` must be mutually exclusive for every input.
- `intersects(other, margin=1)` — true iff the two floor rects come within `margin` cells.
  The default detects "overlapping, touching, or sharing a wall"; `margin=0` is strict
  overlap only.
- `Level.__post_init__` validates `width >= 1`, `height >= 1`, `len(grid) == height`, every
  row `len(row) == width`, and `in_bounds(*player_start)` — raising `ValueError`. It must
  **not** require `player_start` to be walkable and must **not** require `rooms` to be
  non-empty; degenerate levels have to be constructible in other tasks' tests.
- `Room.__post_init__` raises `ValueError` if `width < 1` or `height < 1`.
- `tile_at` must raise `IndexError` for negative coordinates too — no Python negative-index
  wraparound.
- `blank_grid` returns a **mutable** list-of-lists (the generator carves into it);
  `freeze_grid` converts for `Level` construction. Both raise `ValueError` on non-positive
  dimensions. `blank_grid` rows must be independent objects — no `[row] * height` aliasing.
- Tests must not initialise curses and must pass with no TTY attached.
- Do not write a `conftest.py`; nobody owns that file.

## Acceptance criteria
- `Tile` is an `IntEnum` with exactly WALL=0, FLOOR=1, DOOR=2 — no additional members.
- `tile_char` returns `#`/`.`/`+` for the three tiles and raises `KeyError` otherwise.
- `is_walkable_tile` is True for FLOOR and DOOR, False for WALL.
- `Room.x2 == x + width - 1` and `Room.y2 == y + height - 1` (inclusive edges).
- `Room.center == (x + width // 2, y + height // 2)`.
- For a sample room, every cell inside the floor rect satisfies `contains` and not
  `on_perimeter`; every cell of the surrounding ring including all four corners satisfies
  `on_perimeter` and not `contains`; a cell two steps away satisfies neither.
- Two rooms separated by exactly one wall cell report `intersects(margin=1) is True` and
  `intersects(margin=0) is False`.
- Two rooms separated by two or more cells report `intersects() is False`.
- `intersects` is symmetric: `a.intersects(b) == b.intersects(a)`.
- `Level.in_bounds` is True exactly for `0 <= x < width` and `0 <= y < height`, including
  False for negatives, and never raises.
- `Level.tile_at` returns the right tile for in-bounds coordinates and raises `IndexError`
  for out-of-bounds ones including `(-1, 0)` and `(0, -1)`.
- `Level.is_walkable` returns False for every out-of-bounds coordinate without raising, and
  matches `is_walkable_tile` for in-bounds ones.
- `Level` and `Room` are immutable: assigning to any field raises
  `dataclasses.FrozenInstanceError`, and the grid rejects item assignment with `TypeError`.
- Constructing a `Level` with a row-count/width mismatch raises `ValueError`.
- Constructing a `Level` with `player_start` out of bounds raises `ValueError`.
- Constructing a `Level` with `rooms=()` succeeds.
- `blank_grid(w, h)` has `h` rows of `w` cells, all `WALL`, and mutating `grid[0][0]` leaves
  `grid[1][0]` unchanged.
- `freeze_grid(blank_grid(w, h))` produces a tuple of tuples with the same dimensions.
- No module in this task imports `curses` or anything outside the standard library.
