# T24 — Input and event vocabulary
Status: todo
Depends on: none

## Goal
Two new key bindings, twelve new event kinds with their exact wording, and two new fields on
`Event`.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1–4 are complete and passing **1982 tests**: a procedurally generated multi-level
dungeon, field of view, fog of war, doors, colour, diagonal movement, pathfinding and automatic
navigation.

Version 5 adds combat and monsters. The player needs a way to fire a ranged weapon and cycle
targets, and the game needs to be able to say twelve new things — hits, misses, kills, death,
levelling up, poison, and a hostile coming into view.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Two other workers are running in parallel on unrelated modules.

**Both your modules are leaves.** `events.py` imports nothing from the project; `keys.py`
imports only `curses`, and only to reference key constants by name — it never touches a
terminal. Everything you write is testable with no TTY.

**All English wording in this project lives in exactly one table, and it is yours.** Game logic
emits structured `Event` values and never a sentence. The message strings below are binding:
copy them character for character, including punctuation and capitalisation.

Out of scope, explicitly — do not build, do not stub: combat logic, monsters, the targeting
state machine (another worker owns it), a message log or history, event severity levels, an
event bus, an observer registry, or any binding not listed below. Extra surface is a defect, not
initiative.

## Produce

`roguelike/keys.py` (modified):
```python
class CommandKind(Enum):
    ...                        # all seven v4 members unchanged
    FIRE        = auto()       # NEW — "f"
    TARGET_NEXT = auto()       # NEW — Tab
```

| Intent | Key |
|---|---|
| `FIRE` | `f` |
| `TARGET_NEXT` | `Tab` — code `9`, referenced as `curses.ascii.TAB` |

Both carry `dx == dy == 0`.

`roguelike/events.py` (modified):
```python
@dataclass(frozen=True)
class Event:
    kind: EventKind
    depth: int | None = None
    name: str | None = None      # NEW — species name
    level: int | None = None     # NEW — character level
```

`EventKind` gains **twelve** members (16 → 28). The wording table is binding:

| Kind | Message |
|---|---|
| `PLAYER_HIT_NPC` | `You hit the {name}.` |
| `PLAYER_MISSED_NPC` | `You miss the {name}.` |
| `NPC_HIT_PLAYER` | `The {name} hits you.` |
| `NPC_MISSED_PLAYER` | `The {name} misses you.` |
| `NPC_KILLED` | `You kill the {name}!` |
| `PLAYER_DIED` | `You die...` |
| `LEVELLED_UP` | `Welcome to level {level}.` |
| `POISONED` | `You feel sick.` |
| `POISON_DAMAGE` | `The poison burns.` |
| `NO_TARGET` | `There is nothing to shoot at.` |
| `TARGETING` | `Target: {name}. [Tab] next, [f] fire, any other key cancels.` |
| `SPOTTED_HOSTILE` | `A {name} comes into view!` |

Plus modifications to `tests/test_keys.py` and `tests/test_events.py`.

### `message_for` — one change only
A template requiring `{name}` or `{level}` raises `ValueError` when the corresponding `Event`
field is `None`, exactly as `{depth}` already does. Fields a template does not use are ignored
entirely, even if supplied. Joining with a single space in emission order is unchanged, and
`message_for(())` still returns `""`.

**`message_for` does not cap or truncate anything.** The message-line cap (§16.1) is applied by
`game.py`, which another worker owns. Do not implement it here.

## Do not touch
Everything except `roguelike/keys.py`, `roguelike/events.py`, `tests/test_keys.py` and
`tests/test_events.py`. In particular `roguelike/fov.py`, `stats.py`, `items.py` and `status.py`
are being created or edited by other workers **right now**. Frozen: `tiles.py`, `level.py`,
`generator.py`, `world.py`, `dungeon.py`, `pathfind.py`, `activity.py` and their tests. Also
`main.py`, `game.py`, `movement.py`, `render.py`, `style.py`, `combat.py`, `npc.py`,
`roguelike/__init__.py`, `pytest.ini`, and anything under `.plan/` except your own report.

## Constraints
- Python 3.10+, **standard library only**. `from __future__ import annotations` at the top.
- `events.py` imports **nothing** from the `roguelike` package and no `curses`.
- `keys.py` imports `curses` (and `curses.ascii`) **only** to name key constants. It must not
  call `initscr`, `wrapper`, or any terminal-mutating function, at import time or ever.
- **Reference `Tab` as `curses.ascii.TAB`, not the literal `9`** — the same rule that already
  applies to `curses.KEY_SR` and friends.
- **Every v1–v4 binding stays exactly as it is**, including numpad `1/3/7/9`, `yubn`, `HJKL`, the
  shifted arrows, `q`/`Q`, `>`, `<`, `E`, `w`. `5`, `ESC`, `F`, `t`, `a`, `i`, `g`, `Y`, `U`,
  `B`, `N` remain `UNKNOWN`.
- `MESSAGES` must hold an entry for **every** `EventKind` member — no gaps.
- The two new `Event` fields are **appended with defaults**, so every existing construction keeps
  working positionally and by keyword.
- Extend the existing binding tables; do not restructure `keys.py`'s table-driven design.
- Do not add: a message log, event timestamps, severity or priority fields (the *cap* logic
  belongs to `game.py`), an event bus, a registry, or a `format()` helper beyond `message_for`.
- Tests must not initialise curses and must pass with no TTY. No `conftest.py`.

## Acceptance criteria
- `len(CommandKind) == 9`, and the two new members are exactly `FIRE` and `TARGET_NEXT`.
- `translate_key("f").kind is CommandKind.FIRE`, with `dx == 0 and dy == 0`.
- `translate_key(curses.ascii.TAB).kind is CommandKind.TARGET_NEXT`, with `dx == dy == 0`.
  Also assert `translate_key(9)` gives the same, since that is what `getch` actually returns.
- **`F`, `t`, `a`, `i`, `g` are still `UNKNOWN`** — assert explicitly, because `f`/`F` is the
  easiest pair in this task to get wrong.
- **A full regression sweep of every v1–v4 binding**: all eight movement deltas from all of their
  keys (letters, numpad digits, arrows, shifted arrows, `HJKL`), `q`/`Q` → `QUIT`, `>` →
  `DESCEND`, `<` → `ASCEND`, `E` → `AUTO_EXPLORE`, `w` → `WALK_PREFIX`. Assert `K == u == 9` and
  the other three diagonal equivalences still hold as value-equal `Command`s.
- `translate_key` still raises `TypeError` for a non-`int`, non-length-1-`str`, and still returns
  `UNKNOWN_COMMAND` for any unbound code.
- `len(EventKind) == 28` and `len(MESSAGES) == 28`, and **`set(MESSAGES) == set(EventKind)`** —
  no kind without wording, no wording without a kind.
- Every one of the twelve new messages matches the table **character for character**. Assert each
  rendered string literally, e.g. `message_for((Event(EventKind.PLAYER_DIED),)) == "You die..."`.
- The sixteen v1–v4 messages are **unchanged** — assert several literally, including
  `DESCENDED` with its `{depth}` substitution.
- `{name}` substitution works: `message_for((Event(EventKind.NPC_KILLED, name="jackal"),))
  == "You kill the jackal!"`.
- `{level}` substitution works: `message_for((Event(EventKind.LEVELLED_UP, level=3),))
  == "Welcome to level 3."`.
- **Missing-field errors:** `NPC_KILLED` with `name=None` raises `ValueError`; `LEVELLED_UP` with
  `level=None` raises `ValueError`; and `DESCENDED` with `depth=None` still does.
- **Irrelevant fields are ignored:** `Event(EventKind.PLAYER_DIED, name="rat", level=9, depth=2)`
  renders exactly `"You die..."` and does not raise.
- `message_for` joins multiple events with a single space in emission order — assert with three
  events, since version 5 is the first caller to pass more than one.
- `message_for(())` returns `""`. `message_for` never mutates its argument.
- `Event` is frozen and its field order is `(kind, depth, name, level)` — assert positional
  construction `Event(EventKind.DESCENDED, 3)` still works.
- `events.py` imports nothing from `roguelike` and no `curses`; `keys.py` imports no project
  module — assert both with `ast`.
- **No terminal is initialised at import:** assert `keys.py`'s source contains no call to
  `initscr`, `wrapper`, `newwin` or `setupterm` (`ast` walk).
