# T02 — Procedural dungeon generator
Status: todo
Depends on: T01

## Goal
Deterministically generate a single fully-connected dungeon level of rectangular rooms joined
by corridors, from a seed.

## Context
This project is an interactive terminal roguelike engine with ASCII graphics, similar in feel
to ADOM. It is being built by several independent workers who never communicate; a frozen
contract document defines every seam where their code meets. You own the generator — the
largest and most algorithmically interesting piece.

The data types you build on (`Tile`, `Room`, `Level`, and the grid helpers) already exist and
are frozen; read them before designing anything. A renderer and a collision layer are being
written concurrently against the same types, by people who cannot ask you questions. They
consume the `Level` you produce and assume every guarantee below holds.

The engine's scope is deliberately tiny: generate one dungeon level, walk an `@` around it,
quit cleanly. There are **no** monsters, combat, items, inventory, field of view, save-load,
multiple levels, stairs, sound, or colour — explicitly out of scope. Do not place stairs. Do
not add a `spawn_points` field. Do not generate anything you were not asked for.

Two conventions that will break your code if you skim them:
- **All coordinates are `(x, y)` with origin top-left, `x` growing right and `y` growing
  DOWN.** Grid storage is the one inversion: **`grid[y][x]`**, a sequence of rows. When you
  carve a horizontal corridor you vary `x`; when you carve a vertical one you vary `y`.
- **`Room` describes the FLOOR rectangle only.** Its walls are the 1-cell ring immediately
  outside it and are *not* part of `x/y/width/height`. A room at `x=1, width=4` occupies floor
  columns 1–4 and needs column 0 and column 5 to remain available as wall.

The determinism requirement is the hardest constraint in this task and the easiest to violate
by accident. See the constraints section.

## Produce

`roguelike/generator.py`:
```python
DEFAULT_WIDTH: int = 80
DEFAULT_HEIGHT: int = 22
MIN_ROOM_SIZE: int = 4       # minimum floor width and height of a room
MAX_ROOM_SIZE: int = 12      # maximum floor width and height of a room

def generate_level(
    seed: int,
    width: int = DEFAULT_WIDTH,
    height: int = DEFAULT_HEIGHT,
    max_rooms: int = 12,
) -> Level
```

`tests/test_generator.py` — unit tests, including the connectivity flood fill.

Private helpers are yours to name and shape; only the four constants and `generate_level` are
public surface. The algorithm is your choice (random placement with rejection, BSP, whatever
you prefer) provided every guarantee below holds.

### The twelve guarantees — these are the specification
- **G1 Determinism.** Two calls with identical arguments return `Level`s equal in every
  field, including `rooms` order. Must hold across separate processes.
- **G2 Local RNG.** `random.Random(seed)` only.
- **G3 Border.** Every cell with `x == 0`, `y == 0`, `x == width - 1`, or `y == height - 1`
  is `Tile.WALL`.
- **G4 At least one room.** `len(level.rooms) >= 1` always.
- **G5 Rooms disjoint.** For any two distinct rooms, `not a.intersects(b)` with the default
  `margin=1`, so at least one wall cell separates them.
- **G6 Rooms in bounds with margin.** Every room satisfies `1 <= x`, `1 <= y`,
  `x2 <= width - 2`, `y2 <= height - 2`.
- **G7 Room floors carved.** Every cell inside a room's floor rect is `Tile.FLOOR`.
- **G8 Full connectivity.** A 4-directional flood fill over walkable tiles starting from
  `player_start` reaches **every** walkable tile in the grid. No isolated pockets, no
  unreachable rooms, no orphan corridor stubs.
- **G9 Doors.** Every `Tile.DOOR` cell lies on some room's `on_perimeter`. Doors are walkable.
  Zero doors is acceptable for a single-room level.
- **G10 Player start.** Inside some room's floor rect, and `level.is_walkable(*player_start)`.
- **G11 Seed recorded.** `level.seed == seed`.
- **G12 Dimensions honoured.** `level.width == width`, `level.height == height`.

## Constraints
- Python 3.10+, **standard library only**. No third-party imports, ever.
- `from __future__ import annotations` at the top of the module.
- Imports from `roguelike`: **only** `roguelike.tiles` and `roguelike.level` (CONTRACT §10).
- Do not import `curses` — the generator has no business with a terminal.
- **Determinism, stated precisely.** Use a single local `rng = random.Random(seed)`. Calling
  module-level `random.random()`, `random.randint()`, `random.shuffle()`, `random.choice()`
  etc. is **forbidden** — the global generator is shared mutable state and would make output
  depend on test ordering. Also forbidden as influences on output: `time`, `os.urandom`,
  `uuid`, `id()`, object `hash()` of anything non-deterministic, and **iteration over a `set`
  whose order affects the result** (iterate over a sorted or list-ordered collection instead).
- Build the map by carving into a mutable `blank_grid(width, height)` filled with `WALL`, then
  `freeze_grid` it for `Level` construction. Do not build tuples incrementally.
- Doors: place `Tile.DOOR` only where a corridor pierces a room's wall perimeter — use
  `Room.on_perimeter` rather than reinventing the test. Never place a door in the middle of a
  corridor or inside a room's floor.
- Never return a `Level` that violates G1–G12. Raise instead.
- Errors, per CONTRACT §3.1: non-`int` seed **or a `bool`** → `TypeError`; non-`int`
  `width`/`height`/`max_rooms` → `TypeError`; `max_rooms < 1` → `ValueError`;
  `width < MIN_ROOM_SIZE + 2` or `height < MIN_ROOM_SIZE + 2` → `ValueError`.
  Note `bool` is an `int` subclass, so `isinstance(True, int)` is `True` — you must reject it
  explicitly.
- `max_rooms` is a *ceiling*, not a target: placing fewer rooms because the map filled up is
  correct and expected. Placing zero is not (G4).
- Tests must not initialise curses and must pass with no TTY attached.
- Do not write a `conftest.py`; nobody owns that file.
- Keep it readable. A generator nobody can follow is a liability in an engine base.

## Acceptance criteria
- `generate_level(1234)` returns a `Level` with `width == 80`, `height == 22`, `seed == 1234`.
- Determinism: two calls with the same arguments produce levels whose `grid`, `rooms`, and
  `player_start` are all equal. Test at least three different seeds.
- Determinism across processes: the test suite includes a check that hashing the grid of a
  fixed seed matches a value computed in a **separate `subprocess`** running the same call.
- Different seeds produce different grids (test a handful; not all pairs need differ, but a
  sample of at least five seeds must not be uniformly identical).
- The module source contains no bare `random.` module-level RNG calls — assert this in the
  test by reading the source and checking for `random.Random(` while rejecting
  `random.randint(`, `random.choice(`, `random.shuffle(`, `random.random(`.
- G3: every border cell is `WALL`, checked over the whole ring, for several seeds.
- G4: `len(rooms) >= 1` for every seed tested.
- G5: all room pairs are non-intersecting at `margin=1`, for several seeds.
- G6: every room lies within `1 <= x`, `1 <= y`, `x2 <= width - 2`, `y2 <= height - 2`.
- G7: every cell of every room's floor rect is `FLOOR`.
- G8: **flood fill from `player_start` over 4-neighbours reaches every walkable cell in the
  grid** — assert the reached count equals the total walkable count. Test over at least 20
  seeds; this is the single most important test in the task.
- G9: every `DOOR` cell satisfies `on_perimeter` for at least one room, and no `DOOR` cell
  satisfies `contains` for any room.
- G10: `player_start` is inside some room's floor rect and is walkable.
- G12: non-default `width`/`height` are honoured — test e.g. `generate_level(7, 40, 15)`, and
  confirm G3/G8 still hold at that size.
- Small-but-legal dimensions work: `generate_level(0, MIN_ROOM_SIZE + 2, MIN_ROOM_SIZE + 2)`
  returns a valid single-room level satisfying G3, G4, G8, G10.
- `generate_level("abc")`, `generate_level(1.0)`, and `generate_level(True)` each raise
  `TypeError`.
- `generate_level(1, width=MIN_ROOM_SIZE + 1)` and `generate_level(1, height=MIN_ROOM_SIZE+1)`
  each raise `ValueError`.
- `generate_level(1, max_rooms=0)` raises `ValueError`.
- Negative and zero seeds are accepted and deterministic.
- Every generated level is walkable-consistent: no `FLOOR` or `DOOR` cell is on the border.
