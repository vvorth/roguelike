# T14 — Event vocabulary and stair commands
Status: todo
Depends on: none

## Goal
Give the game a way to tell the player what just happened, and a way for the player to say
"go down these stairs" — both as pure, terminal-free leaf modules.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1 and 2 are complete and passing 1300 tests: it generates a dungeon level, walks an
`@` around it with field of view and fog of war, opens doors by bumping them, renders in
256 colour, and quits cleanly.

Version 3 makes the dungeon multi-level and adds a message line so the player learns what is
happening — a door opened, a staircase is underfoot, you descended a level. You own two small
pieces of that: the **event vocabulary** and the **two new keys** that use stairs.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Another worker is running in parallel on the tile and level data structures.

Both of your modules are **leaves**: `events.py` imports nothing from the project at all, and
`keys.py` imports nothing from the project either. That is deliberate. It is how the project
keeps input and messaging testable with no terminal and no game state, and it is why you can
work with no dependencies.

The design principle for events: **game logic emits structured events; wording lives in one
table.** The turn loop never contains a sentence. Adding an event later must be one enum
member, one table entry, one emission — no framework, no registry, no subscriber list.

Out of scope, explicitly — do not build, do not stub: monsters, combat, items, inventory,
save-load, sound. No message history, scrollback, or log buffer — there is exactly one message
line and it is replaced each turn. No severity levels, colours, or timestamps on events. No
event bus, no observers, no callbacks. Extra surface is a defect here, not initiative.

## Produce

`roguelike/events.py` (new):
```python
class EventKind(Enum):
    DOOR_OPENED      = auto()
    STAIRS_HERE_UP   = auto()
    STAIRS_HERE_DOWN = auto()
    DESCENDED        = auto()
    ASCENDED         = auto()
    LEFT_DUNGEON     = auto()
    NO_STAIRS_DOWN   = auto()
    NO_STAIRS_UP     = auto()

@dataclass(frozen=True)
class Event:
    kind: EventKind
    depth: int | None = None

MESSAGES: dict[EventKind, str]

def message_for(events: Sequence[Event]) -> str
```

`roguelike/keys.py` (amend) — two new command kinds and two new bindings:
```python
class CommandKind(Enum):
    MOVE = auto(); QUIT = auto(); UNKNOWN = auto()
    DESCEND = auto()      # ">"
    ASCEND  = auto()      # "<"
```

`tests/test_events.py` (new) and `tests/test_keys.py` (extend).

### The wording table — binding

| Kind | Message |
|---|---|
| `DOOR_OPENED` | `The door opens.` |
| `STAIRS_HERE_UP` | `There is a staircase leading up here.` |
| `STAIRS_HERE_DOWN` | `There is a staircase leading down here.` |
| `DESCENDED` | `You descend to level {depth}.` |
| `ASCENDED` | `You climb up to level {depth}.` |
| `LEFT_DUNGEON` | `You climb out of the dungeon and give up. Farewell.` |
| `NO_STAIRS_DOWN` | `There are no stairs leading down here.` |
| `NO_STAIRS_UP` | `There are no stairs leading up here.` |

## Constraints
- Python 3.10+, **standard library only**. `from __future__ import annotations` at the top of
  both modules.
- **`events.py` imports nothing from the `roguelike` package** — not `tiles`, not `level`, not
  anything. Stdlib `enum`, `dataclasses` and `typing` only. **No `curses`.**
- **`keys.py` still imports nothing from the `roguelike` package.** It may keep importing
  `curses` for the arrow-key constants, and must still never call `curses.initscr`,
  `curses.wrapper`, or any terminal-mutating function.
- `Event` is `frozen=True`; `EventKind` and `CommandKind` use `auto()`.
- `DESCEND` is bound to `>` and `ASCEND` to `<` — the literal characters, as produced by
  `ord('>')` and `ord('<')`. Both must also work when passed as a length-1 `str`.
- `DESCEND` and `ASCEND` commands carry `dx == 0` and `dy == 0`.
- **Every v2 binding is unchanged.** `hjkl`, `yubn`, digits `1`–`9`, the four arrows, `q`/`Q`.
  `5` is still `UNKNOWN`, `ESC` is still `UNKNOWN`, uppercase movement letters are still
  `UNKNOWN`. Do not renumber or reorder existing `CommandKind` members' meaning.
- `message_for` joins multiple events with a **single space**, in emission order, and returns
  `""` for an empty sequence. It never raises for empty input.
- `message_for` never truncates and never pads — fitting the line is the renderer's job.
- A template that needs `{depth}` and receives an `Event` with `depth=None` raises
  `ValueError`. A kind whose template has no placeholder ignores `depth` entirely.
- Do not add a "you bump into a wall" event, or any event not in the table. It would fire on
  every misstep and is deliberately excluded.
- The existing 111 tests in `tests/test_keys.py` must still pass. Extend, do not gut.
- Tests must not initialise curses and must pass with no TTY. No `conftest.py`.

## Acceptance criteria
- `EventKind` has exactly the eight members listed, no more.
- `MESSAGES` has an entry for **every** `EventKind` member — assert by iterating `EventKind`,
  so adding a kind without wording fails loudly.
- Each message matches the table **exactly**, compared against string literals.
- `message_for([Event(DESCENDED, depth=3)])` returns `You descend to level 3.`
- `message_for([Event(ASCENDED, depth=1)])` returns `You climb up to level 1.`
- `Event(DESCENDED)` with `depth=None` passed to `message_for` raises `ValueError`.
- `Event(DOOR_OPENED, depth=7)` ignores the depth and returns the plain message.
- `message_for([])` returns `""` and does not raise; so does `message_for(())`.
- Two events join with exactly one space and in the order given; reversing the input reverses
  the output.
- `message_for` is pure: same input, same output; the input sequence is not mutated.
- `Event` is frozen (`FrozenInstanceError`) and compares by value.
- `translate_key(">")` and `translate_key(ord(">"))` both return a `DESCEND` command with
  `dx == 0` and `dy == 0`; likewise `<` and `ASCEND`.
- `CommandKind` has exactly five members.
- Every v2 binding still resolves as before — re-assert the full movement table, `q`/`Q`, and
  that `5`, `ESC`, `H`, `Z`, `-1` and the integer `4` are still `UNKNOWN`.
- `translate_key` still raises `TypeError` for `None`, `1.5`, `""` and `"ab"`.
- No `MOVE` command has `dx == dy == 0`; all eight directions are still reachable.
- `events.py` imports nothing from `roguelike` and no `curses` — asserted by parsing the source
  with `ast`.
- `keys.py` still imports nothing from `roguelike`, and contains no call to `curses.initscr`,
  `curses.wrapper` or `curses.newwin` — asserted with `ast`.
- Importing either module in a fresh subprocess with stdin from `/dev/null` does not initialise
  a terminal.
