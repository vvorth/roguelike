# T15 — Generator: anchor room, seed-chosen spawn, stairs
Status: todo
Depends on: T13

## Goal
Place an up-staircase and a down-staircase on every generated level, and guarantee the
up-staircase can be forced to an exact coordinate handed in from the level above.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1 and 2 are complete and passing 1300 tests. You own the dungeon generator, which
already produces a fully connected level of rooms and corridors, deterministically from a seed,
with well-formed doors.

Version 3 makes the dungeon **multi-level**, ADOM-style. The player spawns on an up-staircase,
crosses the level, and descends. The next level must be generated with its **up-staircase at
exactly the coordinate the player descended from**, so the two levels line up. That constraint
comes into your function as `required_up`, and satisfying it is the heart of this task.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Another worker is running in parallel on the renderer.

### The approach is mandated, and it makes the hard problem disappear

The naive route is: generate the level, discover there is no room where the stair must go,
carve one, then repair the rooms you damaged and the doors you orphaned. **Do not do that.**

Instead: when `required_up` is given, **place a room containing that coordinate in its interior
before any other room**, then place the rest by the existing rejection sampling. Every later
candidate is rejected against the anchor, so nothing is ever carved after the fact — no room
changes shape, no door is orphaned, and there is nothing to repair.

This was prototyped before the task was written. Measured over 150 level pairs:

| | Result |
|---|---|
| Anchor lands as a valid open spot | **150 / 150** |
| G8 connectivity failures | **0** |
| Rooms per level, before → after | 10.87 → **9.71** |

And over 60 five-level chains (300 levels): zero link failures, zero connectivity failures,
zero invalid stair cells, fully deterministic.

The anchor is **always** placeable: an open spot satisfies `2 ≤ x ≤ width - 3`, so a room whose
interior contains it always fits the map margins. Measured minimum coordinate over 300 levels:
exactly 2 — the bound is hit but never crossed.

### What must not regress

Two guarantees fail **silently** and are why this task exists:

- **G8 full connectivity** — 4-directional flood fill from the up-stair must reach every
  walkable tile.
- **G1/G2 determinism** — one local `random.Random(seed)`; the global `random` module is
  forbidden. Changing the *order* or *number* of RNG draws is allowed (levels may differ from
  v2), but the result must stay reproducible, including across processes.

Out of scope: monsters, items, combat, level themes, trap doors, portals, locked stairs. Do not
write descent logic or seed derivation — another task owns that. You take a `depth` and an
optional `required_up` as plain data and know nothing about dungeons.

Coordinates are `(x, y)`, origin top-left, `y` grows **down**, grid storage `grid[y][x]`.
`Room` describes the **floor rectangle only**; its walls are the 1-cell ring outside it.

### Definitions and new guarantees

An **open spot** is a walkable, non-door cell all eight of whose neighbours are non-`WALL`
(out-of-bounds counts as `WALL`). This is "at least 1 tile away from any wall".

- **G7 amended** — every cell inside a room's floor rect is `FLOOR` **or a stair tile**.
- **G13** Both stair cells are open spots.
- **G14** If `required_up` is given, `level.stairs_up == required_up`.
- **G15** `len(level.stairs_down) == 1`.
- **G16** `stairs_up != stairs_down[0]`, and when `len(rooms) > 1` they are in **different
  rooms**.
- **G17** `level.player_start == level.stairs_up`.
- **G18** Exactly one `STAIRS_UP` cell in the grid, at `stairs_up`; exactly one `STAIRS_DOWN`,
  at `stairs_down[0]`.
- **G19** `level.depth == depth`.
- **G20** When `required_up` is `None`, the up-stair is chosen from the open spots using the
  level's own RNG — **it must not simply be `rooms[0].center`**.

## Constraints
- Python 3.10+, **standard library only**. Imports from the project: **only**
  `roguelike.tiles` and `roguelike.level`. No `curses`.
- **Determinism is the hardest constraint.** One local `rng = random.Random(seed)`.
  Module-level `random.randint` / `choice` / `shuffle` / `random` remain **forbidden**, as does
  any dependence on `time`, `os.urandom`, `id()`, `hash()`, or set-iteration order.
- **Do not carve, reshape or repair rooms after placement.** The anchor goes in first. If you
  find yourself writing code to delete an orphaned door, stop — the design prevents them.
- Do not change the four module constants or the existing error behaviour from v1 §3.1.
- Stairs are stamped over room-interior floor cells. They do not change walkability, so G8 is
  unaffected — but flood fill must still be re-verified.
- Extend `_assert_guarantees` so the generator never returns a level violating G13–G20.
- Levels may differ from v2 for a given seed; that is allowed. Do not pin any test to a v2
  grid snapshot.
- `required_up` must be honoured **exactly**, not approximately.
- Tests must not initialise curses and must pass with no TTY. No `conftest.py`.

## Acceptance criteria
- `generate_level(1234)` returns a level with `depth == 1`, a `stairs_up`, exactly one
  `stairs_down`, and `player_start == stairs_up`.
- **G13** over ≥200 seeds: both stair cells are open spots — all eight neighbours non-`WALL`.
- **G14** over ≥200 seeds: for every open spot of a freshly generated level, regenerating with
  `required_up` set to it yields `stairs_up` exactly equal to it. Sample several spots per seed.
- **G15/G18** over ≥200 seeds: exactly one `STAIRS_UP` and one `STAIRS_DOWN` cell in the grid,
  at the recorded coordinates.
- **G16** over ≥200 seeds: the two stairs differ, and sit in different rooms whenever the level
  has more than one room.
- **G17/G19** over ≥200 seeds.
- **G20**: over ≥50 seeds the up-stair is not always `rooms[0].center` — assert the set of
  outcomes is not a constant relationship, so a lazy implementation fails.
- **G8 connectivity** from `stairs_up` reaches every walkable tile — ≥30 seeds, three map
  sizes, **with and without** `required_up`. Implement the flood fill independently in the test.
- **G1 determinism**: two identical calls produce equal levels, including with `required_up`
  set; ≥5 seeds.
- **G2 cross-process**: a fixed seed's grid digest recomputed in a `subprocess` under ≥2
  `PYTHONHASHSEED` values matches, both with and without `required_up`.
- Source scan: `random.Random(` present, module-level `random.*` calls absent.
- All v1/v2 guarantees still hold: G3 border, G4 ≥1 room, G4a every room has a door, G5 rooms
  disjoint, G6 margins, **G7 amended** (room cells are `FLOOR` or stairs), G9a–d door
  well-formedness, G10, G11, G12 — over several seeds and sizes.
- `required_up` at the extreme legal coordinates `(2, 2)` and `(width-3, height-3)` works.
- Errors: `depth=0` and `depth=-1` raise `ValueError`; `depth="1"` raises `TypeError`;
  `required_up=(0, 0)` or `(1, 1)` raises `ValueError` (not anchorable);
  `required_up=(width, 0)` raises `ValueError`; `required_up="x"` or `(1,)` raises `TypeError`.
- The minimal legal map `generate_level(0, MIN_ROOM_SIZE + 2, MIN_ROOM_SIZE + 2)` still works
  and satisfies G13–G18 — note a one-room level still needs two distinct stair cells.
- All 414 pre-existing tests still pass.
