# T30 — Input and event vocabulary
Status: todo
Depends on: none

## Goal
Two new key bindings and fifteen new event kinds with their exact wording.

## Context
An interactive terminal roguelike, ADOM-ish, standard library only. Versions 1–5 are complete
and passing **2615 tests**. Version 6 gives the player an inventory: items to pick up, wield,
drink and drop, shields that turn blows, monsters that resist damage types, and chests.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Two other workers are running in parallel on unrelated leaf modules.

**Both your modules are leaves.** `events.py` imports nothing from the project; `keys.py`
imports `curses` only to name key constants, and never touches a terminal.

**All English wording in this project lives in one table, and it is yours.** Game logic emits
structured `Event` values and never a sentence. The strings in §16 v6 are binding — copy them
character for character.

Out of scope: combat logic, the inventory screen's behaviour (another worker owns it), a
message log, event severity, an event bus. Extra surface is a defect.

## Read first
- `.plan/CONTRACT-v6.md` — **§5 v6 and §16 v6 in full** bind this task. Also read §9 v6, §10 v6.
- `.plan/CONTRACT-v5.md` §5 v5, §16 v5 — the existing bindings and wording, all unchanged.
- `roguelike/keys.py`, `roguelike/events.py` — the implementations you extend.

## Produce
`keys.py`: `CommandKind.INVENTORY` on `i` and `CommandKind.PICK_UP` on `g`, both with
`dx == dy == 0`. Add both to `HELP_ENTRIES` with a short description.

`events.py`: the fifteen new `EventKind` members and their exact messages from §16 v6.

Plus `tests/test_keys.py` and `tests/test_events.py`.

## Constraints
- Python 3.10+, standard library only.
- `events.py` imports nothing from `roguelike` and no `curses`.
- `keys.py` must not call `initscr`, `wrapper` or any terminal-mutating function, ever.
- **Every v1–v5 binding stays exactly as it is.** `e`, `d` and `t` remain `UNKNOWN` — they are
  used *inside* the inventory screen as raw keys and must not become `CommandKind` members
  (§5 v6).
- `MESSAGES` must hold an entry for every `EventKind`.
- Extend the existing table-driven design; do not restructure it.
- Tests pass with no TTY. No `conftest.py`.

## Acceptance criteria
- `len(CommandKind) == 15`; the two new members are exactly `INVENTORY` and `PICK_UP`.
- `translate_key("i").kind is CommandKind.INVENTORY`, `translate_key("g")` is `PICK_UP`, both
  with `dx == dy == 0`.
- **`e`, `d` and `t` are still `UNKNOWN`** — asserted explicitly, since they are live keys
  inside the inventory screen and binding them globally would break it.
- A full regression sweep of every v1–v5 binding: all eight movement deltas from every key,
  `q/Q/>/</E/w/f/Tab/?/a/x/R`.
- `set(MESSAGES) == set(EventKind)`, both counts equal.
- Each of the fifteen new messages asserted **literally**, including `{name}` substitution.
- The v5 messages are unchanged — assert several literally.
- Import purity asserted with `ast`.
