# T11 — Renderer: colour and fog of war
Status: todo
Depends on: T07, T08

## Goal
Turn a level plus visibility state into a frame of styled cells, and blit that frame to a
curses window in colour — without ever mutating game state.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Version 1 is complete and passing 912 tests: it generates a dungeon, walks an `@` around it, and
quits cleanly, drawing the whole map in monochrome. Version 2 adds colour and fog of war. You
own rendering, and you are **rewriting** the v1 renderer.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Another worker is building the field-of-view module in parallel — it computes
*what is visible*; you decide *how visible things look*. **You must not import it**, and it
must not import you. You are handed the visibility sets as plain frozensets of coordinates.

Two hard project constraints shape this module, and each explains a piece of the design:

1. **Rendering is decoupled from state — no module may both mutate state and draw.** You are
   handed primitives: a `Level`, a player position, three coordinate sets, and a status string.
   You never receive the game's state object. The `Level` you get is a frozen dataclass whose
   grid is a tuple of tuples, so mutation fails at the interpreter level. That is intentional.
2. **Every module must be testable without a live terminal.** So the module splits in two: the
   pure part (`render_to_cells`, `to_lines`) carries all the logic and all the tests, and the
   curses part (`init_colors`, `draw`) is a dumb blitter with no layout logic.

`draw` is **the only place in the entire codebase where `(y, x)` ordering appears.** Curses
takes `(y, x)`; everything else in this project is `(x, y)`. Confining that swap to your one
`addstr` call site is what makes the footgun auditable.

### What fog of war means here

Three visibility states, and they are the heart of this task:
- **UNSEEN** — never seen. **Not drawn at all** — a blank space, *not* a dimmed glyph. The
  player must not be able to infer the map shape from unexplored area.
- **EXPLORED** — seen before, not in view now. Drawn in a **darker shade** of its natural
  colour, so the player knows the memory may be stale.
- **VISIBLE** — in view now. Natural colour.

The target terminal has been probed: `COLORS=256`, `COLOR_PAIRS=32767`,
`can_change_color=True`, and all five needed pairs allocate. But the renderer must **degrade,
never crash**, on an 8-colour or monochrome terminal.

Out of scope, explicitly — do not build, do not stub: monsters, combat, items, inventory,
save-load, multiple levels, stairs, sound. No viewport/camera, no scrolling, no message log, no
lighting or light levels, no distance falloff, no background colours, no animation, no
`KEY_RESIZE` handling. The map fits the screen. Extra surface is a defect, not initiative.

Coordinates are `(x, y)`, origin top-left, `y` grows **down**. Grid storage is `grid[y][x]`.

## Produce

`roguelike/render.py` (rewrite):
```python
@dataclass(frozen=True)
class Cell:
    char: str
    role: Role
    visibility: Visibility

def render_to_cells(
    level: Level,
    player_pos: tuple[int, int],
    visible: frozenset[tuple[int, int]],
    explored: frozenset[tuple[int, int]],
    open_doors: frozenset[tuple[int, int]],
    status: str,
) -> list[list[Cell]]

def to_lines(cells: list[list[Cell]]) -> list[str]

def init_colors(colors: int | None = None) -> None

def draw(stdscr, cells: list[list[Cell]]) -> None
```

`tests/test_render.py` (rewrite — the v1 signature it tests no longer exists).

### `render_to_cells` — pure, all the logic
- Exactly `level.height + 1` rows, each of exactly `level.width` `Cell`s: the map, then one
  status row.
- Per map cell `(x, y)`:
  - in `visible` → `Visibility.VISIBLE`, glyph from the tile.
  - else in `explored` → `Visibility.EXPLORED`, glyph from the tile.
  - else → `Visibility.UNSEEN`, **`char = " "`**, `role = Role.TERRAIN`.
- **Door glyph:** `TILE_CHARS[Tile.DOOR]` (`"+"`) when closed, `DOOR_OPEN_CHAR` (`"'"`) when
  `(x, y) in open_doors`. `Role.DOOR` either way.
- **Player** at `player_pos`: `PLAYER_CHAR`, `Role.PLAYER`, `Visibility.VISIBLE`, overriding the
  tile — even on a wall. Out-of-bounds `player_pos` is **not drawn, no exception**.
- **Status row:** every cell `Role.TERRAIN`, `Visibility.VISIBLE`, padded or truncated to
  exactly `level.width`.

### `to_lines` — plain-text view
One string per row, each exactly the row length. Never raises.

### `init_colors` / `draw` — the only curses here
- `init_colors(colors=None)` — call once after curses is up. `curses.start_color()`,
  `curses.use_default_colors()`, detect `curses.COLORS` when `colors is None`, allocate one
  pair per `(Role, Visibility)` from `style.attr_for`. Every curses call wrapped against
  `curses.error`; a colourless terminal must leave the renderer working in monochrome.
- `draw(stdscr, cells)` — `erase()`, blit, `refresh()`. `UNSEEN` cells write a space.
  `A_BOLD` for the player; `A_DIM` for `EXPLORED` when `colors < 256`. Clipping and the
  bottom-right-cell guard from v1 §4 retained exactly. No layout logic, no visibility logic.

## Constraints
- Python 3.10+, **standard library only**. `from __future__ import annotations` at the top.
- Imports from the project: **only** `roguelike.tiles`, `roguelike.level`, `roguelike.style`.
  You must **not** import `roguelike.fov`, `roguelike.movement`, `roguelike.keys`,
  `roguelike.game`, or `roguelike.generator`.
- `curses` may be imported (you need `curses.error` and the attribute constants), but you must
  **never** call `curses.initscr`, `curses.wrapper`, or `curses.newwin`. `init_colors` and
  `draw` receive an already-initialised terminal from their caller.
- **`render_to_cells` and `to_lines` must not touch `curses` at all.**
- Use `TILE_CHARS`, `PLAYER_CHAR` and `DOOR_OPEN_CHAR` from `roguelike.tiles`, and `Role` /
  `Visibility` / `attr_for` from `roguelike.style`. **Do not hardcode** `#`, `.`, `+`, `'` or
  `@` anywhere in `render.py`, and do not hardcode any colour number — both have exactly one
  home each.
- No mutation of any argument. Build new `Cell`s; do not copy and edit the grid.
- `Cell` is `frozen=True`.
- Colour-pair allocation happens **once** in `init_colors`, never per frame and never inside
  `draw`. Store the mapping in a module-level dict that `draw` reads.
- `draw` must tolerate being called before `init_colors` — fall back to no attribute rather
  than raising.
- Tests must not initialise curses and must pass with no TTY. Test `render_to_cells` and
  `to_lines` directly. For `draw` and `init_colors`, use a small hand-written fake that records
  `addstr` calls and raises `curses.error` where a real window would — do **not** attempt a real
  terminal. The pure functions are where the value is.
- No `conftest.py`.

## Acceptance criteria
- `len(render_to_cells(...)) == level.height + 1`; every row has exactly `level.width` cells.
- Every `to_lines(...)` string is exactly `level.width` characters, including the status row,
  tested with a status shorter than, equal to, and longer than the width (the long one
  truncated).
- **Unexplored is blank:** with `visible=frozenset()` and `explored=frozenset()`, every map
  cell has `char == " "` and `visibility is Visibility.UNSEEN`, and `to_lines` yields rows of
  pure spaces. **Assert no `#` or `.` appears anywhere** — the map shape must not leak.
- A cell in `visible` renders with `Visibility.VISIBLE` and its true glyph.
- A cell in `explored` but not `visible` renders with `Visibility.EXPLORED` and its true glyph.
- A cell in **both** `visible` and `explored` renders `VISIBLE` — visible wins.
- **Closed vs open door:** a `DOOR` cell not in `open_doors` renders `"+"`; the same cell in
  `open_doors` renders `"'"`. `Role.DOOR` in both cases, at both `VISIBLE` and `EXPLORED`.
- Roles are right: `WALL` and `FLOOR` → `Role.TERRAIN`, `DOOR` → `Role.DOOR`, player →
  `Role.PLAYER`.
- The player renders at exactly `cells[y][x]` for `player_pos == (x, y)` — assert with
  `x != y` so the axes cannot be swapped silently — with `PLAYER_CHAR`, `Role.PLAYER` and
  `Visibility.VISIBLE`, over floor **and** over a wall, and even when the cell is `UNSEEN`.
- Exactly one `Role.PLAYER` cell in the map region for an in-bounds player.
- Out-of-bounds `player_pos` — `(-1, 0)`, `(0, -1)`, `(width, 0)`, `(0, height)` — produces no
  exception and no `Role.PLAYER` cell anywhere.
- A **non-square** level (e.g. 7×3) produces `height + 1` rows of `width` cells, and a hand-built
  5×3 level matches literal expected strings via `to_lines` — a transposition bug cannot pass.
- Status row: every cell `Role.TERRAIN` and `Visibility.VISIBLE`.
- Purity: two identical calls return equal output; the `level` compares equal to a pre-call
  deepcopy; the three input frozensets are unmodified.
- Rendering a level with `rooms=()` and an all-`WALL` grid works and does not raise.
- `render.py` contains no literal `"#"`, `"."`, `"+"`, `"'"` or `"@"` glyph constant and no
  bare colour integer — assert by reading the source.
- `render.py` does not import `fov`, `movement`, `keys`, `game` or `generator` — assert with
  `ast`.
- `init_colors` does not raise when curses reports no colour support (simulate via the fake or
  by passing `colors=0`), and `draw` still produces output afterwards.
- `draw` with the fake window: calls `erase()` before and `refresh()` after; clips rows beyond
  `max_y`; truncates columns beyond `max_x`; never writes the bottom-right cell; swallows
  `curses.error` from every call; works on a 1×1 and a 0×0 window; and works when
  `init_colors` was never called.
- No test initialises curses; the suite passes with stdin from `/dev/null`.
