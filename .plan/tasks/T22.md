# T22 — Stats, items and status effects
Status: todo
Depends on: none

## Goal
Three leaf modules: the character statistics and the four formulas derived from them, the two
static weapons, and the status-effect vocabulary with its ticking rules.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1–4 are complete and passing **1982 tests**: a procedurally generated multi-level
dungeon, field of view, fog of war, doors, colour, diagonal movement, pathfinding and automatic
navigation.

Version 5 adds the character: statistics, hit points, weapons, combat, monsters, levelling and
status effects. You build the **foundation layer** that everything else is defined against —
combat, NPCs and the game loop are all written by other workers on top of your three modules.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Two other workers are running in parallel on unrelated modules.

**Your three modules are leaves.** `items.py` and `status.py` import nothing from the project at
all; `stats.py` imports only `status`. That means every line is testable with no engine, no
level, no terminal — which is how this task should be tested.

**Every number in this task is binding and was arrived at by simulation, not taste.** An earlier
draft of these formulas was internally consistent and produced a game where the player died
after a median of 2 kills and cleared 0.0% of floors. The numbers below are the corrected ones.
Do not retune them. If you believe one is wrong, say so in your report and stop — do not
silently change it.

Out of scope, explicitly — do not build, do not stub: combat resolution, NPCs, AI, rendering,
XP or levelling logic, inventory management, item generation, loot tables, an `Item` base class,
equipment slots beyond the two fields named below, or any status effect other than `POISONED`.
Extra surface is a defect, not initiative.

    kind: WeaponKind

`roguelike/status.py` (new):
```python
class StatusKind(Enum):
    POISONED = auto()

@dataclass(frozen=True)
class StatusEffect:
    kind: StatusKind
    remaining_turns: int
    magnitude: int

REGEN_TURNS: int = 10

def apply_effect(effects: tuple[StatusEffect, ...], new: StatusEffect) -> tuple[StatusEffect, ...]
def tick_effects(effects: tuple[StatusEffect, ...]) -> tuple[tuple[StatusEffect, ...], int]
```

### The four derived formulas — binding, copy exactly

| Derived | Formula | At baseline 10/10/10 |
|---|---|---|
| `max_hp` | `5 + vit * 4` | **45** |
| `speed` | `100 + 10 * (agi - 10)` | 100 |
| `evasion` | `clamp(5 + (agi - 10) * 3, 0, 60)` | 5 |
| `block` | `max(0, (str_ - 10) // 2)` | **0** |

> **`block` is deliberately ZERO at baseline. Do not "fix" it.** An earlier version used
> `str_ // 2`, giving a baseline block of 5 against attacks of 1–5 damage. Because a hit always
> does at least 1 damage, that floored **every single attack in the game to exactly 1**, and all
> four monster species became mechanically identical. Block means *advantage over an average
> creature*. A positive baseline value re-creates a measured, fatal bug.

### `apply_effect` — refresh, never stack
- No effect of that `kind` present → append it.
- One present → replace it **only if** `new.remaining_turns` is greater than the existing
  `remaining_turns`. Otherwise return the input unchanged.
- Magnitude never stacks. Never more than one entry per kind.

### `tick_effects` — returns `(surviving_effects, total_damage)`
- Each effect contributes `magnitude` to the damage total and has `remaining_turns` reduced by 1.
- An effect reaching `remaining_turns == 0` is dropped.
- Order within the tuple is preserved. Pure — the input tuple is never mutated.

## Constraints
- Python 3.10+, **standard library only**. `from __future__ import annotations` at the top of
  each module.
- `items.py` and `status.py` import **nothing** from the project. `stats.py` imports **only**
  `roguelike.status`. No `curses` anywhere.
- **All arithmetic is integer.** No floats, anywhere.
- **The rounding rule is binding:** the STR modifier used downstream is `(str_ - 10) // 2`, which
  floors toward −∞ — at `str_ == 5` it is `-3`, **not** `-2`. You do not implement that modifier
  (combat does), but `block` uses the same `//` form and you must not write `int(x / 2)`
  anywhere. It silently rebalances the game.
- `derive` is pure and **total**: it never raises, for any integer input including negative and
  zero. Do not add validation.
- Every dataclass is `frozen=True`.
- **No `Random` instance may be stored in any of these modules** (§0.12). None of your functions
  takes or needs one.
- Do not add: an `Item` base class, an inventory container, ammo counts, equipment slots,
  a `heal()` helper, a second `StatusKind`, an effect registry, or a `Derived` cache.
- Tests must not initialise curses and must pass with no TTY. No `conftest.py`.

## Acceptance criteria
- `BASELINE == 10`, and `derive(Stats(10, 10, 10))` is exactly `Derived(max_hp=45, speed=100,
  evasion=5, block=0)`. Assert all four fields explicitly.
- **`block` is 0 at baseline and stays 0 below it.** `derive(Stats(4, ...)).block == 0`,
  `derive(Stats(10, ...)).block == 0`, `derive(Stats(12, ...)).block == 1`,
  `derive(Stats(16, ...)).block == 3`. Add a test named so that a future "fix" to `str_ // 2` is
  loud and obvious.
- `evasion` clamps at both ends: `agi=8` gives `0` (not `-1`), and a very high `agi` gives `60`,
  never more.
- `speed` is `100` at `agi=10`, `140` at `agi=14`, `80` at `agi=8`.
- **The four bestiary stat blocks derive correctly with no special cases** — this is the check
  that the formulas are expressive enough. Assert each:

  | Stats | max_hp | speed | evasion | block |
  |---|---|---|---|---|
  | `Stats(4, 14, 3)` rat | 17 | 140 | 17 | 0 |
  | `Stats(8, 13, 5)` jackal | 25 | 130 | 14 | 0 |
  | `Stats(3, 18, 2)` giant bat | 13 | 180 | 29 | 0 |
  | `Stats(6, 8, 5)` cave snake | 25 | 80 | 0 | 0 |

- `derive` never raises for negative, zero or very large stats.
- `Stats`, `Derived`, `Actor`, `Weapon`, `StatusEffect` are all frozen — assert that assignment
  raises `FrozenInstanceError`.
- `Actor` defaults `status_effects` to `()`.
- `DAGGER` and `SHORTBOW` have exactly the values above; `DAGGER.kind is WeaponKind.MELEE` and
  `DAGGER.range == 1`; `SHORTBOW.kind is WeaponKind.RANGED` and `SHORTBOW.range == 6`.
- **`apply_effect` refresh semantics**, each asserted separately: appending to an empty tuple;
  a longer duration replacing a shorter one; a **shorter** duration leaving the tuple
  **unchanged** (identical contents); an equal duration leaving it unchanged; and the result
  never containing two entries of the same kind.
- `apply_effect` never mutates its input — assert the original tuple is unchanged afterwards.
- **`tick_effects`**: `((), 0)` for an empty tuple; damage equals the sum of magnitudes; each
  `remaining_turns` reduced by exactly 1; an effect at `remaining_turns == 1` is dropped and
  **still contributes its damage on the tick that removes it**; order preserved with two
  effects present.
- `REGEN_TURNS == 10`.
- **Import purity, asserted with `ast`:** `items.py` and `status.py` contain no `roguelike`
  import at all; `stats.py` imports only `roguelike.status`; none of the three imports `curses`.
- No float literal appears in any of the three modules — assert with `ast` over the source.
