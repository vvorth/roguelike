# T17 — Dungeon, descent and ascent, messages
Status: todo

## Goal
Turn a single level into a persistent multi-level dungeon the player can descend and climb,
with a message line reporting what just happened.

### The three ideas that make this task

**Levels line up.** When the player descends, the next level is generated with
`required_up` set to the coordinate they descended from. So the down-staircase on level *N* and
the up-staircase on level *N+1* are the same `(x, y)`, and the player simply stays put while
the world changes underneath them.

**Levels persist.** Climbing back up must return you to the level as you left it — same
explored ground, same opened doors. Terrain is free because generation is deterministic, but
fog and doors are runtime state, so you keep a per-depth store. This is why the decision to let
deeper up-stairs ascend normally makes persistence load-bearing rather than optional.

**Wording lives in one table.** `step` emits structured `Event` values; `events.message_for`
turns them into a sentence. Your turn loop must not contain a sentence.

### The rules that are easiest to get wrong

- **A rejected move still consumes no turn** — v1's headline rule, still binding. Bumping a
  closed door *does* consume one (it opens the door). Pressing `>` off-stairs does **not**
  consume one, but *does* emit a message.
- **The event rule:** the returned state's `events` is what *this* command produced, whenever
  the command produced any event or consumed a turn. Otherwise the state is returned
  **unchanged**, so the previous message stays on screen. That is "the message stays until
  another turn", and it falls out of the existing turn rule rather than needing new machinery.
- **`explored`, `visible` and `open_doors` on `GameState` always describe the current depth.**
  Other depths live in `saved`.
- **Ascending at depth 1 ends the game** with a clear message. Deeper up-stairs go back up.

Out of scope, explicitly — do not build, do not stub: monsters, combat, items, inventory,
save-load to disk, sound, score, a game-over screen, menus, a title screen, message history or
scrollback, branch generation. The `stairs_down` tuple is scaffolding — read `[0]` and move on.
Do not invent content for the stats row; it is reserved and blank.

## Constraints
- Python 3.10+, **standard library only**. `from __future__ import annotations`.
- `dungeon.py` imports only `roguelike.generator` and `roguelike.level`; it is pure, has no
  caching and never touches curses. `game.py` may import `level`, `keys`, `movement`, `render`,
  `fov`, `world`, `dungeon`, `events`.
- `curses.wrapper` may be called **only inside `play()`**, never at import time.
- **`step` must be pure** — a new `GameState`, no mutation, no curses, no drawing. `saved` is
  never mutated: build a new dict (`{**old, d: v}`).
- **`step` must not format wording.** Emit `Event` values; `message_for` is called when
  building `Chrome`, in `run`.
- **`run` must not implement game rules.** Anything decidable without a terminal is in `step`.
- Do not reimplement collision (`movement.try_move`), visibility (`fov.compute_visible`),
  passability (`world.is_passable`), key mapping (`keys.translate_key`), frame layout
  (`render.render_to_cells`) or wording (`events.message_for`). Delegate to all six.
- No direct screen writes — no `addstr`/`addch`/`move` in this module.
- `format_stats` returns `""`. Do not invent stats.
- `format_status_right` returns `f"Level {depth}  Seed {master_seed}"` — two spaces, and the
  **master** seed, not the per-level derived seed, so the run can be replayed.
- `run` calls `render.init_colors()` once after curses is up, guarded against `curses.error`,
  and **returns the final `GameState`**. `play` prints `state.outcome` after `curses.wrapper`
  returns, so the farewell lands on a restored terminal.
- Tests must not initialise curses and must pass with no TTY. Test `step` directly; do not test
  `run` or `play` against a real terminal — the orchestrator runs the live smoke test.
- No `conftest.py`.

## Acceptance criteria
- `seed_for` is deterministic, non-negative, and differs for different depths; equal inputs
  give equal outputs across a `subprocess` under two `PYTHONHASHSEED` values.
- `seed_for(m, d, branch=1) != seed_for(m, d, branch=0)` — the scaffolding works.
- `level_for(m, d)` returns a level with `depth == d`; with `required_up` set, its `stairs_up`
  equals that coordinate exactly. `depth < 1` raises `ValueError`.
- `new_game(1234)` puts the player on level 1's `stairs_up`, `depth == 1`, `turns == 0`,
  `running is True`, `open_doors == frozenset()`, `saved == {}`, `events == ()`,
  `outcome is None`, and **`explored == visible` and both non-empty**.
- **Descend:** standing on `stairs_down`, `DESCEND` moves to `depth + 1`, places the player at
  the same `(x, y)`, and that coordinate is the new level's `stairs_up`. `turns + 1`. Emits
  `DESCENDED` with the new depth. The previous level is in `saved`.
- **The coordinate really is preserved:** assert `after.player == before.player` across the
  descent, and `after.level.stairs_up == before.level.stairs_down[0]`.
- **Descend off-stairs:** `DESCEND` anywhere else emits `NO_STAIRS_DOWN`, consumes **no turn**,
  and changes nothing else — assert depth, player, turns, explored and open_doors all identical.
- **Ascend at depth 1** on `stairs_up` sets `running=False`, sets `outcome` to a non-empty
  string, and emits `LEFT_DUNGEON`.
- **Ascend at depth > 1** on `stairs_up` returns to `depth - 1`, places the player on that
  level's `stairs_down[0]`, and emits `ASCENDED` with the new depth.
- **Ascend off-stairs** emits `NO_STAIRS_UP`, consumes no turn, changes nothing else.
- **Persistence round trip — the most important test in this task.** Descend, walk far enough
  to explore and open at least one door, ascend, and assert the restored level's `explored` and
  `open_doors` are **exactly** what they were on leaving; then descend again and assert the
  lower level's `explored`/`open_doors` are also exactly preserved. Fog must not reset.
- Descending twice to the same depth reuses the saved level object rather than regenerating a
  different one — assert the `Level` compares equal across the round trip.
- **Stair messages:** stepping onto a `STAIRS_DOWN` cell emits `STAIRS_HERE_DOWN`; onto
  `STAIRS_UP`, `STAIRS_HERE_UP`. Not emitted when merely walking adjacent.
- **The event rule:** after a blocked move, the state is returned unchanged **including
  `events`**, so the previous message survives; after `UNKNOWN`, likewise. After any
  turn-consuming action, `events` is replaced.
- A `MOVE` into a wall leaves player, turns, visible, explored, open_doors **and events**
  untouched.
- Bump-to-open still works: position unchanged, `turns + 1`, exactly one door added, FOV
  recomputed, `DOOR_OPENED` emitted.
- `format_status_right` matches a literal string and uses the master seed, not the derived one.
- `format_stats` returns `""`.
- **Purity:** every input field captured before the call is unchanged after, for each command
  kind; a `deepcopy` of the level still compares equal; the input frozensets and `saved` dict
  are unmodified.
- `GameState` is frozen; field order and defaults match the contract via `dataclasses.fields`.
- Source-parsed hygiene: `curses.wrapper` only inside `play`; `init_colors` only inside `run`;
  no `addstr`/`addch`; `step` references nothing in `render`; `run` does not call `try_move` or
  `compute_visible`; the import graph is within the §10 v3 allowance; a subprocess import
  leaves `curses.LINES` unset.
- A scripted sequence spanning **at least three depths** ends at the expected depth, player
  position and turn count, with the turn count matching neither the command count nor the move
  count.
