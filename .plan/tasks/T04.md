# T04 — Input abstraction
Status: todo
Depends on: none

## Goal
Translate raw keyboard codes into immutable movement/quit intents, with zero terminal
involvement, so input is fully testable headless.

## Context
This project is an interactive terminal roguelike engine with ASCII graphics, similar in feel
to ADOM. It is being built by several independent workers who never communicate; a frozen
contract document defines every seam where their code meets. You own the input seam.

At runtime a curses game loop (written by someone else, in another module) calls
`stdscr.getch()`, which returns an `int`, and hands it to your `translate_key`. You return a
`Command`. The loop dispatches on it. You never see a terminal, you never block on input, you
never read from stdin. Your module is a pure lookup table — and that is precisely the point:
it is how the project satisfies its "every module must be testable without a live terminal"
constraint for the input path.

Your module depends on nothing else in the project, which is why it is being built first, in
parallel with the core data types. You cannot import from `roguelike`, and nothing you need
lives there.

The engine's scope is deliberately tiny: generate one dungeon level, walk an `@` around it,
quit cleanly. There are **no** monsters, combat, items, inventory, field of view, save-load,
multiple levels, stairs, sound, or colour — explicitly out of scope. Do not add commands for
them. No `PICKUP`, no `INVENTORY`, no `WAIT`, no "for later" enum members.

The single most important convention in this codebase: **all coordinates are `(x, y)` with
origin top-left, `x` growing right and `y` growing DOWN.** Therefore **north/up is
`dy = -1`** and south/down is `dy = +1`. Getting this backwards is the most likely way this
task fails.

## Produce

`roguelike/keys.py`:
```python
class CommandKind(Enum):
    MOVE    = auto()
    QUIT    = auto()
    UNKNOWN = auto()

@dataclass(frozen=True)
class Command:
    kind: CommandKind
    dx: int = 0
    dy: int = 0

QUIT_COMMAND: Command      # Command(CommandKind.QUIT)
UNKNOWN_COMMAND: Command   # Command(CommandKind.UNKNOWN)

def translate_key(key: int | str) -> Command
```

`tests/test_keys.py` — unit tests.

The binding table, reproduced from CONTRACT §5.1 (remember `dy = -1` is up):

| Intent | dx, dy | Keys |
|---|---|---|
| West       | (-1,  0) | `h`, `4`, `curses.KEY_LEFT` |
| East       | ( 1,  0) | `l`, `6`, `curses.KEY_RIGHT` |
| North      | ( 0, -1) | `k`, `8`, `curses.KEY_UP` |
| South      | ( 0,  1) | `j`, `2`, `curses.KEY_DOWN` |
| North-west | (-1, -1) | `y`, `7` |
| North-east | ( 1, -1) | `u`, `9` |
| South-west | (-1,  1) | `b`, `1` |
| South-east | ( 1,  1) | `n`, `3` |
| Quit       | —        | `q`, `Q` |

## Constraints
- Python 3.10+, **standard library only**. No third-party imports, ever.
- `from __future__ import annotations` at the top of the module.
- **`roguelike/keys.py` must not import anything from the `roguelike` package** (CONTRACT
  §10). It is a leaf.
- Importing `curses` at module top level **is explicitly allowed and required** — you must
  reference `curses.KEY_LEFT`, `curses.KEY_RIGHT`, `curses.KEY_UP`, `curses.KEY_DOWN` through
  the module rather than hardcoding `259`/`260`/etc. Importing curses does not touch the
  terminal; only `initscr()` does. You must **not** call `curses.initscr`, `curses.wrapper`,
  or any terminal-mutating curses function — not at import time, not ever.
- The digit keys are the **ASCII characters** `'1'`–`'9'` (i.e. `ord('4') == 52`), **not** the
  integers `1`–`9`. A raw `int` `4` is not the numpad-4 key and must be `UNKNOWN`.
- `Command` is `frozen=True`. `CommandKind` uses `auto()` — do not assign explicit values.
- Movement letters are **lowercase only**. Uppercase `H`/`J`/`K`/`L`/`Y`/`U`/`B`/`N` mean
  "run" in some roguelikes, which is out of scope, so they are `UNKNOWN`. `Q` is the sole
  uppercase binding.
- Numpad `5` is `UNKNOWN`. There is no wait command.
- `ESC` (27) is **not** quit — it is the prefix of every arrow-key escape sequence, and
  binding it invites a timing race. It is `UNKNOWN`.
- `translate_key` must **never raise for an unrecognised key** — that is ordinary input.
  It raises `TypeError` only for a wrong *type*: anything that is not an `int` or a length-1
  `str`. A `str` of length 0 or 2+ is a `TypeError`. Note `bool` is an `int` subclass and
  need not be special-cased here.
- A `MOVE` command must always have `dx, dy ∈ {-1, 0, 1}` and never `(0, 0)`.
- Prefer a single module-level mapping table over a long if/elif chain — it is the honest
  shape of this problem and makes the exhaustiveness test trivial.
- Tests must not initialise curses and must pass with no TTY attached.
- Do not write a `conftest.py`; nobody owns that file.

## Acceptance criteria
- Every key in the binding table maps to the exact `(dx, dy)` listed, tested for both the
  `int` and (where applicable) the single-char `str` form.
- `translate_key(ord('k'))` and `translate_key('k')` both return `Command(MOVE, 0, -1)` —
  north is negative dy.
- `translate_key(curses.KEY_UP)` returns `Command(MOVE, 0, -1)`, and matches `translate_key('k')`.
- `translate_key(curses.KEY_DOWN)` returns `Command(MOVE, 0, 1)`.
- All eight directions are reachable, and the set of `(dx, dy)` pairs produced by the letter
  keys equals the set produced by the digit keys equals all eight non-zero pairs in
  `{-1,0,1}²`.
- `translate_key('q')` and `translate_key('Q')` both return a `QUIT` command.
- `translate_key('5')`, `translate_key(27)`, `translate_key('H')`, `translate_key('Z')`,
  `translate_key(-1)`, and `translate_key(4)` all return `UNKNOWN_COMMAND` without raising.
  (`-1` is what `getch` returns in non-blocking mode with no input; `4` is the integer four,
  not the numpad key.)
- `translate_key(None)`, `translate_key(1.5)`, `translate_key('')`, and `translate_key('ab')`
  each raise `TypeError`.
- No `MOVE` command anywhere in the table has `dx == 0 and dy == 0`.
- Every `MOVE` command has `dx` and `dy` in `{-1, 0, 1}`.
- `Command` is immutable: assigning to `.dx` raises `dataclasses.FrozenInstanceError`.
- `Command` equality is by value: `Command(CommandKind.QUIT) == QUIT_COMMAND`.
- `roguelike/keys.py` imports nothing from `roguelike` and nothing outside the standard
  library.
- Importing `roguelike.keys` does not initialise a terminal — the test module imports it at
  the top and passes with stdin redirected from `/dev/null`.
