# T19 — Pathfinding and map topology
Status: todo
Depends on: none

## Goal
Provide shortest-path search with diagonal movement, and the local tests that tell a corridor
from a room without consulting the level's room list.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1–3 are complete and passing 1666 tests: a procedurally generated multi-level dungeon,
field of view, fog of war, doors, colour.

Version 4 adds automatic navigation — walk to a known staircase, explore the level
automatically, follow a corridor until it forks or opens out. All of that needs two things:
**a pathfinder**, and **a way to recognise what kind of space the character is standing in**.
You build both. Other workers build the exploration logic and the control flow on top.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. One other worker is running in parallel on the key bindings.

**Your module is a leaf: it imports nothing from the project.** It works entirely through a
`passable(x, y) -> bool` callable handed in by the caller. That is deliberate and important —
the same function must plan over *real terrain* for one caller and over *only the terrain the
character has explored* for another, without ever knowing the difference. It also means you can
test every line against hand-drawn ASCII maps with no engine at all, which is how this task
should be tested.

Two decisions are already made and measured, so do not re-derive them:

- **Costs are integers**: orthogonal `10`, diagonal `14`. No floats anywhere in the pathfinder,
  so ordering is exact and no epsilon or tie-break fudge can appear.
- **`is_wide` must check all four 2×2 quadrants.** A two-quadrant version was measured at 96.4%
  accuracy against true room membership; the four-quadrant version scores **99.98%** with zero
  room cells misread as corridor. This is a real, measured trap.

Performance is a solved problem: a full-level search was measured at **0.235 ms**, against a
budget of one turn at ten turns per second. That is why the contract forbids caching and
incremental replanning — callers re-plan every turn because they can afford to, and simpler is
better.

Out of scope, explicitly — do not build, do not stub: monsters, items, combat. No path caching,
no incremental or hierarchical replanning, no flow fields, no path smoothing, no "fast" mode.
No frontier or exploration logic — another task owns that. No knowledge of doors, stairs, fog
or the level type. Extra surface is a defect, not initiative.

Coordinates are `(x, y)`, origin top-left, `y` grows **down**.

## Produce

`roguelike/pathfind.py` (new):
```python
Coord = tuple[int, int]
Passable = Callable[[int, int], bool]

ORTHOGONAL_COST: int = 10
DIAGONAL_COST: int = 14
DIRECTIONS: tuple[tuple[int, int], ...]      # the 8 deltas, in a FIXED order

def octile(a: Coord, b: Coord) -> int
def find_path(passable: Passable, start: Coord, goals: AbstractSet[Coord]) -> list[Coord] | None
def is_wide(passable: Passable, x: int, y: int) -> bool
def degree(passable: Passable, x: int, y: int) -> int
def is_intersection(passable: Passable, x: int, y: int) -> bool
```

`tests/test_pathfind.py` (new).

### `find_path`
- Returns the full path **including `start`**, ending on a member of `goals`; `[start]` if
  `start` is already a goal; `None` if no goal is reachable or `goals` is empty.
- The path is **shortest** under the 10/14 cost model.
- **Deterministic** run to run and process to process. Break ties with a total order: iterate
  `DIRECTIONS` in its fixed order and include the coordinate in the priority-queue key so no
  comparison is ever ambiguous.
- `start` need not itself be passable; every other cell on the path must be.
- Pure: no mutation, no I/O, no global state, no caching. Never raises for an unreachable goal.
- **≤ 5 ms per call on an 80×22 map.**

### The topology predicates
- `is_wide` — true iff `(x, y)` belongs to **any** 2×2 block of passable cells; **all four
  quadrants**.
- `degree` — count of passable **orthogonal** neighbours, 0 to 4.
- `is_intersection` — `not is_wide(...) and degree(...) >= 3`.

## Constraints
- Python 3.10+, **standard library only** (`heapq` is the obvious tool). `from __future__
  import annotations` at the top.
- **No project imports at all.** Not `tiles`, not `level`, nothing. No `curses`.
- **No floats.** Costs, the heuristic and every comparison are integer arithmetic.
- The heuristic must be **admissible and consistent** for the 10/14 model:
  `octile(a, b) = 10 * (dx + dy) + (14 - 2 * 10) * min(dx, dy)` where `dx`, `dy` are absolute
  differences. Do not invent a different one; an inadmissible heuristic silently returns
  non-shortest paths.
- `DIRECTIONS` is a module-level constant in a fixed order and must not be shuffled, sorted or
  regenerated at call time.
- No corner-cutting rule: a diagonal step is allowed whenever its destination is passable, even
  if both orthogonal neighbours are walls. This matches CONTRACT §6 and must not be "improved".
- Do not add a `max_nodes`, `timeout`, `heuristic_weight` or `fast` parameter.
- `passable` may be called many times; do not memoise it inside the module (the caller owns any
  caching, and today there is none).
- Tests must not initialise curses and must pass with no TTY. **Build test maps from lists of
  strings** (`#` blocked, `.` passable) with a small local helper — that is the natural way to
  test this module and keeps every case readable. Do not import the generator.
- No `conftest.py`.

## Acceptance criteria
- `ORTHOGONAL_COST == 10`, `DIAGONAL_COST == 14`, and `DIRECTIONS` has exactly the eight
  non-zero deltas with each component in `{-1, 0, 1}`.
- `octile` returns `0` for equal points, `10` for an orthogonal neighbour, `14` for a diagonal
  neighbour, is symmetric, non-negative, and always an `int`.
- **Admissibility:** on several hand-built open maps, `octile(start, goal)` is never greater
  than the true cost of the returned path. Assert over a sweep of point pairs.
- `find_path` on an open map returns a path whose cost is the octile distance — i.e. it uses
  diagonals rather than walking in an L.
- **Shortest-path correctness:** on at least three hand-built maps with obstacles, the returned
  path's cost equals the cost found by an independent, obviously-correct Dijkstra written in
  the test file. This is the criterion that catches a broken heuristic.
- `find_path` returns `[start]` when `start` is in `goals`, and `None` for an empty `goals`
  set, an unreachable goal, and a goal enclosed by walls — never raising in any of those cases.
- `start` need not be passable: a path from a blocked cell to a reachable goal still works.
- Every cell of a returned path other than `start` satisfies `passable`, and consecutive cells
  differ by a delta in `DIRECTIONS`.
- **Multi-goal:** with several goals, the returned path ends on the **nearest** one by path
  cost, verified against per-goal single-target searches.
- **Determinism:** the same call returns an identical path twice, and a `subprocess` under two
  different `PYTHONHASHSEED` values returns the same path — a set-iteration-order dependency
  must fail this.
- **Diagonal movement is not corner-restricted:** on a map where two walls meet diagonally and
  the far cell is passable, the path may pass between them. Assert it explicitly so a future
  "fix" is loud.
- **`is_wide` four-quadrant behaviour:** for a cell whose *only* open 2×2 block lies up-left, or
  only down-right, or only up-right, or only down-left, `is_wide` is `True` in **all four**
  cases. This is the measured trap and must be tested per quadrant.
- `is_wide` is `False` for an isolated cell, for a 1-wide horizontal corridor, and for a 1-wide
  vertical corridor.
- `degree` returns 0–4 correctly for a dead end, a straight corridor, a T-junction and open
  floor, counting only orthogonal neighbours.
- `is_intersection` is `True` for a thin T-junction and a thin cross, and `False` for a straight
  corridor, a dead end, and any cell inside open floor (however high its degree).
- **Performance:** a search across an 80×22 map completes in under 5 ms, measured in the test
  with a generous margin so it is not flaky.
- `pathfind.py` imports nothing from `roguelike` and no `curses` — assert with `ast`. It
  contains no float literal in its cost or heuristic arithmetic.
