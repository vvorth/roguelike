# T12 — Game state, FOV per move, bump-to-open
Status: todo
Depends on: T07, T08, T09, T10, T11

## Goal
Wire fog of war and openable doors into the turn loop: recompute visibility on every accepted
move, accumulate explored ground, and open a door by walking into it.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Version 1 is complete: it generates a dungeon, walks an `@` around it, and quits cleanly, with
the whole map always visible in monochrome. Version 2 adds colour, fog of war, field of view,
and openable doors. **Every other v2 module is now finished and verified.** You are the last
worker: you wire them together and you own the turn semantics.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. You are the only module that imports from all the others, and the first person to
see the whole v2 stack at once.

What exists and is finished — **read all of it, do not assume its shape**:
- `roguelike/tiles.py` — `Tile`, `TILE_CHARS`, `PLAYER_CHAR`, `DOOR_OPEN_CHAR`.
- `roguelike/level.py` — frozen `Room` and `Level`. **Unchanged from v1.**
- `roguelike/keys.py` — `CommandKind`, `Command`, `translate_key`. **Unchanged from v1.**
- `roguelike/world.py` — `is_passable`, `is_transparent`, `is_closed_door`.
- `roguelike/style.py` — `Visibility`, `Role`, `Attr`, `role_for`, `attr_for`.
- `roguelike/generator.py` — `generate_level(...)`, now with properly embedded doors.
- `roguelike/fov.py` — `compute_visible(level, open_doors, origin, radius)`.
- `roguelike/movement.py` — `try_move(level, position, dx, dy, open_doors)` returning a
  `MoveResult` with a `blocked_by_door` field.
- `roguelike/render.py` — `render_to_cells(...)`, `to_lines(...)`, `init_colors(...)`,
  `draw(stdscr, cells)`.

### The three constraints that shape this task

1. **Rendering is decoupled from state.** You hold the state; the renderer draws. You never
   write to the screen yourself — you call `render.render_to_cells` then `render.draw`. And the
   renderer never sees your `GameState`: you hand it a `Level`, a position, three frozensets and
   a string. `GameState` lives in your module and **nothing else imports it**. That is what let
   the renderer be written by someone who never spoke to you.
2. **Everything must be testable without a live terminal.** `step` is a **pure function**
   carrying all the game logic and all the tests; `run` is a thin shell. Your tests exercise
   `step` exhaustively and never initialise curses.
3. **A clean quit path always restores the terminal.** `play()` uses `curses.wrapper`, which
   restores on normal return *and* on exception, including `KeyboardInterrupt`.

### The rules you must not get wrong

- **A rejected move still consumes no turn.** This was v1's headline rule and it survives
  unchanged. But there is now a *third* outcome: blocked-by-closed-door, which **does** consume
  a turn (it opens the door). Blocked-by-wall and blocked-by-edge still consume nothing.
- **FOV recomputes only on an accepted move or a door opening** — never on a rejected move,
  never on `UNKNOWN`, never on `QUIT`.
- **`explored` only ever grows**: `explored | visible`. Ground once seen is never forgotten.
- **The initial state is not blank.** `new_game` computes FOV immediately, so you see where you
  stand. "Nothing is explored" is the state *before* the first FOV, which is never observable.

Out of scope, explicitly — do not build, do not stub: monsters, combat, items, inventory,
save-load, multiple levels, stairs, sound. No explicit `o`-to-open command — bump-to-open covers
it. No message log, menus, title screen, pause state, help overlay, game-over state, score, or
debug mode. No command beyond move and quit. Extra surface is a defect, not initiative.

Coordinates are `(x, y)`, origin top-left, `y` grows **down**, so up is `dy = -1`.

## Produce

`roguelike/game.py` (amend):
```python
@dataclass(frozen=True)
class GameState:
    level: Level
    player: tuple[int, int]
    explored: frozenset[tuple[int, int]]
    visible: frozenset[tuple[int, int]]
    open_doors: frozenset[tuple[int, int]]
    turns: int = 0
    running: bool = True
    radius: int = fov.DEFAULT_RADIUS

def new_game(level: Level, radius: int = fov.DEFAULT_RADIUS) -> GameState
def step(state: GameState, command: Command) -> GameState
def format_status(state: GameState) -> str
def run(stdscr, level: Level) -> None
def play(seed: int, width: int = 80, height: int = 22) -> None
```

`tests/test_game.py` (rewrite — `GameState` gains three fields, so the v1 constructor calls no
longer apply).

### Exact behaviour
- `new_game(level, radius)` — player at `level.player_start`, `open_doors=frozenset()`,
  `turns=0`, `running=True`, then `visible = fov.compute_visible(level, frozenset(),
  player, radius)` and `explored = visible`.
- **`step` is pure** — returns a new `GameState`, never mutates the input, never touches curses,
  never draws:
  - `running=False` → returned unchanged, for every command kind.
  - `QUIT` → `running=False`; turns, player, and all three sets unchanged. No FOV recompute.
  - `UNKNOWN` → unchanged (may be the same object). No FOV recompute.
  - `MOVE` → delegate to `movement.try_move(level, player, dx, dy, open_doors)`:
    - `moved=True` → new position, `turns + 1`, **recompute FOV**, `explored |= visible`.
    - `blocked_by_door is not None` → **bump-to-open**: `open_doors | {door}`, `turns + 1`,
      position **unchanged**, **recompute FOV**, `explored |= visible`.
    - otherwise → state returned unchanged, **turns unchanged**.
- `format_status(state)` — v1 format **retained exactly**:
  `f"Seed: {seed}  Pos: ({x}, {y})  Turns: {turns}  [q] quit"`. Do **not** add FOV or door counts.
- `run(stdscr, level)` — `render.init_colors()` once after curses is up (guarded against
  `curses.error`), then loop: `render_to_cells(...)` → `render.draw(stdscr, cells)` →
  `stdscr.getch()` → `translate_key` → `step`, until `not state.running`. Set
  `curses.curs_set(0)` and `stdscr.keypad(True)` defensively, each guarded.
- `play(seed, width, height)` — `generate_level(seed, width, height)` then
  `curses.wrapper(run, level)`. **The only place in the codebase that initialises curses.**

## Acceptance criteria
- `new_game` — player at `level.player_start`, `turns == 0`, `running is True`,
  `open_doors == frozenset()`, and **`explored == visible` and both non-empty** (the starting
  cell is always seen).
- `new_game` honours a custom `radius`, and a larger radius yields a `visible` superset of a
  smaller one on an open level.
- A `MOVE` onto passable ground → new position, `turns == 1`, and `visible` recomputed for the
  **new** position (assert it differs from the old set on a level where it must).
- **`explored` grows and never shrinks:** over a multi-step walk, assert
  `state.explored >= previous.explored` at every step, and that `explored >= visible` always.
- A `MOVE` into a **wall** leaves position, turns, `visible`, `explored` and `open_doors` all
  unchanged — assert every field. This is the "rejected move consumes no turn" rule.
- A `MOVE` off the map edge does the same and does not raise.
- **Bump-to-open:** a `MOVE` into a closed door leaves the **position unchanged**, sets
  `turns + 1`, adds exactly that door to `open_doors`, and **recomputes FOV** — assert the
  room beyond the door becomes visible, which it was not before. This is the single most
  important test in the task.
- After opening, a second `MOVE` in the same direction **does** move the player onto the door
  cell, with `turns` now `+2` total.
- Opening a door adds **only** that door: `len(new.open_doors) == len(old.open_doors) + 1`.
- Bumping a door that is **already open** moves the player normally (it is no longer blocked).
- `QUIT` sets `running=False` and leaves turns, player, and all three sets unchanged.
- `UNKNOWN` leaves the state entirely unchanged, including `visible` and `explored`.
- `step` on a `running=False` state returns an equal state for every command kind.
- **Purity:** capture every input field before the call and assert all are unchanged
  afterwards, for each command kind; a `deepcopy` of the level still compares equal; the input
  frozensets are unmodified; the returned object is distinct when something changed.
- A scripted command sequence over a hand-built level produces the exact expected final
  position and turn count, **including at least one blocked move and one door opening**, so the
  turn count differs from both the command count and the move count.
- Sign convention: a north command (`dy = -1`) decreases `y`; assert from a start where `x != y`.
- `format_status` matches a literal string for a known state and is **unchanged from v1** — no
  new fields.
- `GameState` is frozen (`FrozenInstanceError`), and its field order matches the contract via
  `dataclasses.fields`.
- Importing `roguelike.game` does not initialise a terminal; `curses.wrapper` appears only
  inside `play` and there are no `addstr`/`addch` calls — assert by parsing the source.
- FOV is recomputed on exactly the two intended transitions and no others — assert `visible` is
  unchanged (identical set) after a rejected move and after `UNKNOWN`.
- The suite passes with stdin from `/dev/null`.
