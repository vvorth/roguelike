# T16 — Renderer: stats row and status row
Status: todo
Depends on: T13

## Goal
Give the frame a reserved stats row above the map and a status row below it carrying a message
on the left and the level and seed on the right.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1 and 2 are complete and passing 1300 tests: a dungeon level, an `@` you walk around,
permissive field of view, fog of war, bump-to-open doors, 256-colour rendering.

Version 3 makes the dungeon multi-level and gives the player some UI. You own the frame layout.
Today the frame is the map plus one status line. It becomes: a **reserved stats row** at the
top (for player stats that do not exist yet), the map, and a **status row** at the bottom that
carries an event message on the left and the current level and seed on the right.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Another worker is running in parallel on the dungeon generator.

Two constraints shape this module and explain its shape:

1. **Rendering is decoupled from state.** You are handed primitives — a level, a position,
   three coordinate sets, and now a small `Chrome` value holding three finished strings. You
   never see the game state, and you never format wording: the message arrives already
   composed. That is why you can be written by someone who never spoke to the worker building
   the event system.
2. **Everything is testable without a terminal.** `render_to_cells` and `to_lines` are pure and
   carry all the logic and all the tests; `init_colors` and `draw` are the only curses, and
   `draw` is a dumb blitter.

### The one dangerous change

The map is no longer at row 0. **Map cell `(x, y)` now renders at `cells[y + 1][x]`.** That
`+1` exists in exactly one place — your `render_to_cells` — and nowhere else in the codebase.
It is the single most likely thing to break in this task, so it must be pinned by tests using a
**non-square** level and a player at `x != y`.

Out of scope, explicitly — do not build, do not stub: monsters, items, inventory, a viewport or
camera, scrolling, message history or scrollback, lighting, background colours, animation,
`KEY_RESIZE` handling, or any content in the stats row. Extra surface is a defect here, not
initiative.

Coordinates are `(x, y)`, origin top-left, `y` grows **down**.

## Produce

`roguelike/render.py` (amend):
```python
@dataclass(frozen=True)
class Chrome:
    stats: str = ""            # top row — reserved, blank for now
    message: str = ""          # bottom row, left
    status_right: str = ""     # bottom row, right

def render_to_cells(
    level: Level,
    player_pos: tuple[int, int],
    visible: frozenset[tuple[int, int]],
    explored: frozenset[tuple[int, int]],
    open_doors: frozenset[tuple[int, int]],
    chrome: Chrome,
) -> list[list[Cell]]
```

`Chrome` **replaces** the bare `status: str` parameter. `Cell`, `to_lines`, `init_colors` and
`draw` keep their existing signatures and behaviour.

`tests/test_render.py` (rewrite the parts that call the old signature — the 101 existing tests
are yours, and most should survive with a `Chrome(...)` at the call site).

### Frame layout — exactly `level.height + 2` rows, each exactly `level.width` cells

| Row | Content |
|---|---|
| `0` | `chrome.stats`, padded or truncated to width |
| `1 … level.height` | the map — cell `(x, y)` at `cells[y + 1][x]` |
| `level.height + 1` | `chrome.message` left, `chrome.status_right` right |

Both chrome rows are `Role.TERRAIN`, `Visibility.VISIBLE` in every cell.

### Status row composition

- If `len(message) + 1 + len(status_right) <= width`: `status_right` flush right, `message`
  flush left, spaces between.
- Otherwise truncate `message` to `width - len(status_right) - 1`, floored at 0.
  **`status_right` always wins** — the level and seed must stay readable.
- If `len(status_right) >= width`: truncate `status_right` to `width` and drop `message`.

## Constraints
- Python 3.10+, **standard library only**. Imports from the project: **only**
  `roguelike.tiles`, `roguelike.level`, `roguelike.style`. You must **not** import
  `roguelike.events`, `fov`, `game`, `generator`, `movement` or `keys` — you receive finished
  strings, never events or state.
- `curses` may be imported for `curses.error` and the attribute constants; never call
  `initscr`, `wrapper` or `newwin`. `render_to_cells` and `to_lines` must not touch curses.
- **Do not hardcode** `#`, `.`, `+`, `'`, `<`, `>` or `@` — glyphs come from `roguelike.tiles`,
  including the new stair characters. Do not hardcode any colour number.
- `Chrome` is `frozen=True` with all three fields defaulting to `""`.
- No mutation of any argument. `render_to_cells` stays pure.
- Colour-pair allocation stays **once** in `init_colors`, never in `draw`.
- Do not give stairs their own role or colour — they are `Role.TERRAIN` by design.
- Do not add a second message line, a history buffer, or scrolling.
- Tests must not initialise curses and must pass with no TTY. Keep using a hand-written fake
  window for `draw`; do not attempt a real terminal.
- No `conftest.py`.

## Acceptance criteria
- `render_to_cells(...)` returns exactly `level.height + 2` rows, each of exactly `level.width`
  cells.
- **The row offset is pinned:** on a **non-square** level (e.g. 7×3) with a player at `x != y`,
  the player cell is at `cells[y + 1][x]`, and the cell at `cells[y][x]` is *not* the player.
  A transposition or an off-by-one cannot pass this.
- A hand-built 5×3 level renders to literal expected strings via `to_lines`, including both
  chrome rows.
- Row `0` reproduces `chrome.stats`, padded to width; with the default `Chrome()` it is all
  spaces.
- Every cell of both chrome rows is `Role.TERRAIN` and `Visibility.VISIBLE`.
- Status row: message left, `status_right` flush right, with a short message; assert the exact
  string via `to_lines`.
- Status row: when message and `status_right` together exceed the width, the message is
  truncated and `status_right` survives **intact and flush right**.
- Status row: a `status_right` longer than the width is truncated to the width and the message
  disappears; no exception.
- Status row: empty `Chrome()` yields a row of spaces of exactly `width`.
- **Stair glyphs:** a `STAIRS_UP` cell renders `<` and a `STAIRS_DOWN` cell renders `>`, both
  from `TILE_CHARS`, at `VISIBLE` and at `EXPLORED`, with `Role.TERRAIN`.
- All v2 behaviour retained and re-tested: unexplored cells are blank (assert no `#` or `.`
  leaks with empty sets); `visible` beats `explored`; a door renders `+` closed and `'` open;
  the player is drawn over any tile including a wall and an unseen cell; an out-of-bounds
  player draws nothing and raises nothing; purity via a deepcopy comparison.
- `to_lines` returns one string per row, each exactly `level.width` characters, for a frame of
  `height + 2` rows.
- `render.py` contains no literal glyph constant and no bare colour integer — assert by reading
  the source.
- `render.py` does not import `events`, `fov`, `game`, `generator`, `movement` or `keys` —
  assert with `ast`.
- `draw` with the fake window still: erases before and refreshes after, clips rows beyond
  `max_y`, truncates columns beyond `max_x`, never writes the bottom-right cell, swallows
  `curses.error`, works on 1×1 and 0×0 windows, and works when `init_colors` was never called.
- A default 80×22 level produces a 24-row frame — assert the exact number, since that is the
  classic terminal budget.
