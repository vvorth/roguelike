# T03 — Renderer
Status: todo
Depends on: T01

## Goal
Turn a level plus a player position into exact frame text, and blit that text to a curses
window, without ever mutating game state.

## Context
This project is an interactive terminal roguelike engine with ASCII graphics, similar in feel
to ADOM. It is being built by several independent workers who never communicate; a frozen
contract document defines every seam where their code meets. You own rendering.

One of the project's hard constraints is that **rendering is decoupled from game state — no
module may both mutate state and draw.** Your module is the "draw" half of that split, and it
is deliberately built so it *cannot* reach game state: you are handed a `Level`, a
`(x, y)` player position, and a status string. That is all. You never receive the game's
state object, you do not know what a turn is, and you must not import the game loop, the input
layer, the movement layer, or the generator. The `Level` you receive is a frozen dataclass
whose grid is a tuple of tuples, so mutation attempts fail at the interpreter level — this is
intentional and you should not work around it.

Your module has two layers, and the split is the whole design:
1. `render_to_lines` — **pure**, no curses, returns the frame as a list of strings. All the
   logic lives here, and so do all the unit tests.
2. `draw` — a dumb blitter that calls `render_to_lines` and pushes the result at a curses
   window. It contains no layout logic.

`draw` is **the only place in the entire codebase where `(y, x)` ordering appears.** Curses
takes `(y, x)`; everything else in this project is `(x, y)`. Confining the swap to your
`addstr` call site is what makes that footgun auditable.

The engine's scope is deliberately tiny: generate one dungeon level, walk an `@` around it,
quit cleanly. There are **no** monsters, combat, items, inventory, field of view/lighting,
save-load, multiple levels, stairs, sound, or colour beyond terminal defaults — explicitly out
of scope. Do not add a colour system, a viewport/camera, a message log, or a lighting pass.
The map fits the screen; there is no scrolling.

Coordinate convention: **`(x, y)`, origin top-left, `x` grows right, `y` grows DOWN.** Grid
storage is `grid[y][x]`.

## Produce

`roguelike/render.py`:
```python
def render_to_lines(
    level: Level,
    player_pos: tuple[int, int],
    status: str,
) -> list[str]

def draw(stdscr, level: Level, player_pos: tuple[int, int], status: str) -> None
```

`tests/test_render.py` — unit tests, essentially all of them against `render_to_lines`.

### `render_to_lines` — exact behaviour
- Returns exactly `level.height + 1` strings: `level.height` map rows, then one status row.
- **Every returned string is exactly `level.width` characters** — space-padded or truncated.
  This includes the status line.
- Map cell `(x, y)` renders as `TILE_CHARS[level.tile_at(x, y)]`, except `player_pos` renders
  as `PLAYER_CHAR`.
- The player is drawn even if standing on a wall or an unexpected tile.
- If `player_pos` is out of bounds it is simply **not drawn — no exception**.
- Pure: same inputs ⇒ same output; no global state, no I/O, no `curses` import used by it.

### `draw` — exact behaviour
- Calls `render_to_lines`, then blits. No layout logic of its own.
- Clips to the window: draws only rows `< max_y`, truncates each line to `max_x`.
- Guards the bottom-right cell — writing the last cell of the last row raises in curses.
- Swallows `curses.error`.
- Calls `stdscr.erase()` before drawing and `stdscr.refresh()` after.
- Returns `None`.

## Constraints
- Python 3.10+, **standard library only**. No third-party imports, ever.
- `from __future__ import annotations` at the top of the module.
- Imports from `roguelike`: **only** `roguelike.tiles` and `roguelike.level` (CONTRACT §10).
  You must **not** import `roguelike.movement`, `roguelike.keys`, `roguelike.game`, or
  `roguelike.generator`.
- Importing `curses` at module top level is allowed (needed for `curses.error`), but you must
  **never** call `curses.initscr`, `curses.wrapper`, `curses.newwin`, or any other
  terminal-mutating curses function — not at import time, not ever. `draw` receives an
  already-initialised `stdscr` from its caller.
- `render_to_lines` must not touch `curses` at all.
- Use `TILE_CHARS` and `PLAYER_CHAR` from `roguelike.tiles`. Do not hardcode `#`, `.`, `+`,
  or `@` anywhere in `render.py` — the glyph mapping has exactly one home.
- No mutation of any argument. Do not build a mutable copy of the grid and edit the player
  into it, then hand it onward; build strings.
- `draw` is the only function in this file — and in the codebase — that may use `(y, x)`
  ordering, and only at the curses call site.
- Do not add colour, colour pairs, `curses.start_color`, a camera/viewport, scrolling, or a
  message log. Out of scope.
- Tests must not initialise curses and must pass with no TTY attached. Test `render_to_lines`
  directly; do **not** attempt to test `draw` against a real terminal. If you want coverage of
  `draw`'s clipping logic, use a small hand-written fake object that records `addstr` calls
  and raises `curses.error` where a real window would — but a fake is optional, and the pure
  function is where the value is.
- Do not write a `conftest.py`; nobody owns that file.

## Acceptance criteria
- `len(render_to_lines(level, pos, status)) == level.height + 1`.
- Every returned line has `len(line) == level.width`, including the status line, tested with a
  status string that is shorter than the width, exactly the width, and longer than the width
  (the long one must be truncated to exactly `level.width`).
- A hand-built `Level` renders the expected exact strings — build a small level (e.g. 5×3)
  with known tiles and compare against literal expected rows. This test pins the
  `grid[y][x]`-to-line mapping and must fail if rows and columns are ever transposed.
- Rows are rows: for a **non-square** level (width != height, e.g. 7×3), the output has
  `height + 1` lines each of `width` chars — a transposition bug cannot pass this.
- `WALL` renders `#`, `FLOOR` renders `.`, `DOOR` renders `+`, taken from `TILE_CHARS`.
- The player glyph `@` appears at exactly `line[y][x]` for `player_pos == (x, y)` — assert
  with `x != y` so the axes cannot be swapped silently.
- Exactly one `@` appears in the map region for an in-bounds player.
- The player renders over a wall tile as well as a floor tile.
- An out-of-bounds `player_pos` — `(-1, 0)`, `(0, -1)`, `(width, 0)`, `(0, height)` — produces
  no exception and no `@` anywhere in the output.
- Purity: calling `render_to_lines` twice on the same inputs returns equal output, and the
  `level` object compares equal to a pre-call copy of itself afterwards.
- Rendering a level whose `rooms` is empty and whose grid is entirely `WALL` works and
  produces all-`#` map rows.
- `render.py` contains no literal `"#"`, `"."`, `"+"`, or `"@"` glyph constants.
- `render.py` does not import `roguelike.movement`, `roguelike.keys`, `roguelike.game`, or
  `roguelike.generator` — assert this by reading the module source in a test.
- Importing `roguelike.render` does not initialise a terminal; the suite passes with stdin
  redirected from `/dev/null`.
