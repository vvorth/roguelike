# T18 — Diagonal keys and activity messages
Status: todo
Depends on: none

## Goal
Add the Shift-diagonal bindings, the two new commands that drive multi-turn actions, and the
messages those actions report.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1–3 are complete and passing 1666 tests: a procedurally generated multi-level dungeon,
permissive field of view, fog of war, openable doors, 256-colour rendering, a stats row and a
status line with event messages.

Version 4 adds two things to the player's vocabulary: **more ways to move diagonally**, and
**actions that run for many turns** — auto-explore, travel to a known staircase, and walking
down a corridor until something interesting happens. You own the input and message vocabulary
for all of it. Other workers build the pathfinding and the control flow.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. One other worker is running in parallel on the pathfinder.

Both your modules are **leaves**: `events.py` imports nothing from the project at all, and
`keys.py` imports nothing from it either. That is what keeps input and messaging testable with
no terminal and no game state.

**Diagonal movement already half exists.** Numpad `1/3/7/9` and `yubn` have produced the four
diagonals since v1 and must keep working exactly as they do. What is new is Shift+arrows and
Shift+hjkl, each rotated **45° clockwise** from the base direction.

The Shift+arrow key codes were measured on a real terminal before this task was written, so you
do not need to discover them — but note the names are a trap: the constants for Shift+Up and
Shift+Down are called `KEY_SR` and `KEY_SF` ("scroll reverse/forward") for historical reasons.
**`KEY_SR` is Shift+Up.** Getting that backwards is the most likely mistake in this task.

Out of scope, explicitly — do not build, do not stub: monsters, combat, items, inventory,
save-load, sound. No message history, scrollback or log buffer. No event bus, observers or
callbacks. No escape-sequence parser for terminals that lack the shifted-arrow capabilities —
`HJKL` is the portable path and that is deliberate. Extra surface is a defect, not initiative.

## Produce

`roguelike/keys.py` (amend):
```python
class CommandKind(Enum):
    MOVE = auto(); QUIT = auto(); UNKNOWN = auto()
    DESCEND = auto(); ASCEND = auto()
    AUTO_EXPLORE = auto()      # NEW — "E"
    WALK_PREFIX  = auto()      # NEW — "w"
```

New bindings, rotated 45° clockwise from the base direction:

| Delta | Direction | Keys |
|---|---|---|
| ( 1, -1) | NE | `curses.KEY_SR` (Shift+Up), `K` |
| ( 1,  1) | SE | `curses.KEY_SRIGHT` (Shift+Right), `L` |
| (-1,  1) | SW | `curses.KEY_SF` (Shift+Down), `J` |
| (-1, -1) | NW | `curses.KEY_SLEFT` (Shift+Left), `H` |

Plus `E` → `AUTO_EXPLORE` and `w` → `WALK_PREFIX`.

## Constraints
- Python 3.10+, **standard library only**. `from __future__ import annotations` at the top.
- **`events.py` imports nothing from the `roguelike` package** and must not import `curses`.
- **`keys.py` imports nothing from the `roguelike` package.** It keeps importing `curses` for
  the key constants and must still never call `initscr`, `wrapper` or any terminal-mutating
  function.
- Reference the shifted-arrow constants **through `curses`** — `curses.KEY_SR`,
  `curses.KEY_SF`, `curses.KEY_SLEFT`, `curses.KEY_SRIGHT`. **Never hardcode 337/336/393/402.**
- `AUTO_EXPLORE` and `WALK_PREFIX` commands carry `dx == 0` and `dy == 0`.
- **Every v1–v3 binding must still resolve identically**: `hjkl`, `yubn`, digits `1`–`9`, the
  four plain arrows, `q`/`Q`, `>`, `<`. `5`, `ESC`, `Y`, `U`, `B`, `N` remain `UNKNOWN`.
  Uppercase `H`/`J`/`K`/`L` change from `UNKNOWN` to diagonals — that is the intended change and
  the existing tests asserting they are `UNKNOWN` are **yours to update**, not delete.
- `MESSAGES` must hold an entry for **every** `EventKind` member, asserted by iterating
  `EventKind` so a future kind without wording fails loudly.
- Copy the eight messages **character for character**. `{depth}` templating and the
  `ValueError` on a missing depth are unchanged.
- Do not add `AUTO_EXPLORE_COMMAND`-style singletons; none of the existing kinds beyond
  `QUIT`/`UNKNOWN` have them.
- The existing 120 tests in `tests/test_keys.py` and 51 in `tests/test_events.py` must still
  pass, except the `HJKL`-are-`UNKNOWN` ones and any member-count assertions, which you update.
- Tests must not initialise curses and must pass with no TTY. No `conftest.py`.

## Acceptance criteria
- `CommandKind` has exactly seven members: the five from v3 plus `AUTO_EXPLORE` and
  `WALK_PREFIX`.
- **The 45°-clockwise mapping is exact**, tested key by key:
  `curses.KEY_SR` and `K` → `(1, -1)`; `curses.KEY_SRIGHT` and `L` → `(1, 1)`;
  `curses.KEY_SF` and `J` → `(-1, 1)`; `curses.KEY_SLEFT` and `H` → `(-1, -1)`.
- **The up/down constants are not swapped** — assert explicitly that `KEY_SR` gives a
  **negative** `dy` (north-east) and `KEY_SF` a **positive** one (south-west). This is the
  named trap; a swap must fail loudly.
- Shift+Up and `K` produce **equal** `Command` values; likewise each other pair.
- Each Shift-diagonal equals the corresponding legacy diagonal: `K` == `u` == `9`,
  `L` == `n` == `3`, `J` == `b` == `1`, `H` == `y` == `7`.
- `translate_key("E")` → `AUTO_EXPLORE`; `translate_key("w")` → `WALK_PREFIX`; both with
  `dx == dy == 0`. Both work as `int` and as a length-1 `str`.
- `e` (lowercase) and `W` (uppercase) are `UNKNOWN` — only the specified cases are bound.
- The full v1–v3 table still resolves: all eight directions from `hjkl`/`yubn`, digits `1`–`9`
  with `5` `UNKNOWN`, the four plain arrows, `q`/`Q` quit, `>` descend, `<` ascend.
- `Y`, `U`, `B`, `N`, `ESC`, `Z`, `-1` and the integer `4` are still `UNKNOWN`.
- `translate_key` still raises `TypeError` for `None`, `1.5`, `""`, `"ab"`.
- No `MOVE` command has `dx == dy == 0`; the eight deltas produced by the Shift keys are
  exactly the four diagonals.
- `EventKind` has exactly sixteen members — the eight from v3 plus the eight new ones.
- `MESSAGES` covers every `EventKind`, asserted by iteration, and each of the eight new
  messages matches the table exactly as a string literal.
- `message_for` still joins with a single space, returns `""` for empty input, and still raises
  `ValueError` for a depth-templated kind with `depth=None`.
- `keys.py` contains no literal `337`, `336`, `393` or `402` — assert by reading the source.
- `keys.py` and `events.py` import nothing from `roguelike`; `events.py` imports no `curses` —
  assert with `ast`.
- Importing either module in a fresh subprocess with stdin from `/dev/null` initialises no
  terminal.
