# T29 — Item vocabulary and inventory
Status: todo
Depends on: none

## Goal
One leaf module describing everything the player can carry, wield or drink, plus the four pure
functions that move items between the pack and the equipment slots.

## Context
An interactive terminal roguelike, ADOM-ish, standard library only. Versions 1–5 are complete
and passing **2615 tests**: procedural multi-level dungeon, field of view, fog of war, doors,
colour, diagonal movement, pathfinding, auto-navigation, combat, monsters with AI, levelling,
status effects, a help screen and a look cursor.

Version 6 gives the player an inventory. **You build the foundation every other v6 task
consumes** — combat reads your damage types, monsters read your resistances, loot generates
your items, the renderer lists them and the game loop equips them.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Two other workers are running in parallel on unrelated leaf modules.

**Your module is a leaf: it imports nothing from the project.** Everything is testable with no
engine, no level and no terminal.

### Numbers you must not retune

**The dagger stays 2–5 and the shortbow stays 1–4.** They are the reference the entire game
balance is measured against. Measured: one point of melee damage is worth **20–40 percentage
points** of floor-clear survival — 1–4 clears 2.2% of floors, 2–5 clears 45.6%, 4–8 clears
98.3%. The tiers in §25.1 are close together for exactly that reason, and an earlier draft
proposing 1–4 and 4–8 was rejected on those measurements.

If a number looks wrong to you, say so in your report and stop. Do not adjust it.

Out of scope, explicitly — do not build, do not stub: weight, encumbrance, stacking, item
identification, curses, enchantments, an `Item` base class beyond what the contract writes,
food, hunger, ammunition, shops, or any item not in §25.1's tables. Extra surface is a defect.

## Produce
`roguelike/items.py` (modified) and `tests/test_items.py` (modified), exactly per §25.

`ItemKind`, `DamageType`, `Resistance` (IntEnum), `Grade` (IntEnum), `Weapon` (two appended
fields), `Shield`, `Consumable`, `Inventory`, `CARRY_LIMIT`, and `equip` / `unequip` / `add` /
`drop`. Plus the module constants for every row of §25.1's tables.

## Constraints
- Python 3.10+, standard library only, `from __future__ import annotations`.
- **Imports nothing from `roguelike`.** No `curses`.
- Every dataclass `frozen=True`. All four functions **pure** — new values out, nothing mutated.
- `Weapon`'s new fields are **appended with defaults**, so `Weapon("dagger", MELEE, 2, 5)`
  still works.
- `Resistance` and `Grade` are `IntEnum` so they order; `ItemKind` and `DamageType` are plain
  `Enum`.
- All arithmetic integer. No floats.

## Acceptance criteria
- Every row of §25.1's three tables asserted literally — name, kind, damage, type, grade, range
  for all six weapons; block chance and grade for all three shields; both consumables.
- **`DAGGER.damage_min == 2 and DAGGER.damage_max == 5`** and **`SHORTBOW` is 1–4**, asserted
  in a test named so that retuning them is loud.
- `Weapon("x", WeaponKind.MELEE, 2, 5)` constructs with `damage_type` and `grade` defaulted —
  the v5 call shape still works.
- `Resistance.IMMUNE < RESISTANT < NORMAL < VULNERABLE`; `Grade.CRUDE < STANDARD < FINE`.
- `equip`: moves a carried item into the right slot; a `Weapon` goes to `melee` or `ranged` by
  its `WeaponKind`; whatever was in the slot returns to `carried`; raises `ValueError` for an
  item not in `carried`.
- `unequip`: slot becomes `None`, item returns to `carried`; a `None` slot is a no-op.
- `add`: appends and returns `(inventory, True)`; at `CARRY_LIMIT` returns
  `(inventory, False)` **with the input unchanged**.
- `drop`: removes by index and returns it; an out-of-range index returns `(inventory, None)`
  with nothing changed.
- **Purity**: every function leaves its input `Inventory` equal to a copy taken beforehand.
- An empty `Inventory()` has all three slots `None` and `carried == ()`.
- `CARRY_LIMIT == 20`.
- Import purity asserted with `ast`: no `roguelike` import, no `curses`, no float literal.
- Tests pass with no TTY. No `conftest.py`.
