# T25 — Combat resolution
Status: todo
Depends on: T22 (`stats.py`, `items.py`, `status.py` must exist)

## Goal
One pure module that answers "does this attack hit, and for how much?" — used unchanged for the
player attacking a monster and for a monster attacking the player.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1–4 are complete and passing **1982 tests**: a procedurally generated multi-level
dungeon, field of view, fog of war, doors, colour, diagonal movement, pathfinding and automatic
navigation.

Version 5 adds combat. You own the arithmetic of it and nothing else.

The engine is built by independent workers who never communicate; a frozen contract defines
every seam. Another worker is running in parallel on the monsters and their AI.

**Your module is a pure calculator.** It takes two `Actor` values and some numbers, and returns
an `AttackResult`. It does not know what an NPC is, does not emit messages, does not remove
anything from the world, and does not end the game. That is deliberate and it is what lets the
same six lines of arithmetic serve both sides of every fight — which is exactly what the user
asked for when they said status effects and combat should work "both for NPC and player
character".

**`combat.py` must not import `events`.** It returns a structured result and `game.py` turns
that into messages, exactly as `movement.try_move` already returns a `MoveResult` that `game.py`
interprets. Follow that precedent.

### The two traps, both of which are previously-measured bugs

An earlier draft of these formulas produced a game where **every attack in the game did exactly
1 damage** and all four monster species were mechanically identical. Two mistakes caused it, and
both look like reasonable code:

1. **Adding an attacker accuracy term to to-hit.** It makes AGI drive speed *and* evasion *and*
   accuracy — strictly the best stat, and a contradiction of the design's one-identity-per-stat
   rule. There is **no attacker term**. To-hit depends only on the defender's evasion.
2. **Applying the attacker's STR modifier to natural attacks.** A rat's 1–3 bite already encodes
   how weak a rat is; subtracting a further 3 for its STR of 4 counts the same fact twice and
   floors the result. STR applies to **wielded weapons only**.

If you find yourself thinking either of these is missing, re-read this section. They are absent
on purpose.

Out of scope, explicitly — do not build, do not stub: critical hits, armour, damage types,
resistances, weapon variety beyond what `items.py` provides, multi-target attacks, attacks of
opportunity, initiative, XP awards, death handling, message generation, or anything that mutates
the world. Extra surface is a defect, not initiative.

## Produce

`roguelike/combat.py` (new):
```python
@dataclass(frozen=True)
class AttackResult:
    hit: bool
    damage: int                 # 0 when hit is False
    defender_hp: int            # after damage
    killed: bool
    poisoned: bool = False

def to_hit_chance(defender_evasion: int) -> int

def resolve_attack(rng, attacker: Actor, defender: Actor,
                   damage_min: int, damage_max: int,
                   strength_applies: bool,
                   poison_chance: int = 0) -> AttackResult
```

`tests/test_combat.py` (new).

### To-hit — binding
```
to_hit_chance(defender_evasion) = clamp(90 - defender_evasion, 5, 95)
```
Baseline vs baseline (evasion 5) is **85%**. The roll is `rng.randint(1, 100) <= chance`.
**There is no attacker term.**

### Damage — binding
```
strength_applies is True   (wielded weapon):
    damage = max(1, rng.randint(dmg_min, dmg_max) + (attacker.stats.str_ - 10)//2 - defender_block)

strength_applies is False  (natural attack — bite, claw — and all ranged weapons):
    damage = max(1, rng.randint(dmg_min, dmg_max)                                 - defender_block)
```
- `defender_block` comes from `stats.derive(defender.stats).block`.
- **Ranged weapons pass `strength_applies=False`** even though they are wielded — a bow's power
  is the bow's, not the archer's arm. That is the one deliberate melee/ranged asymmetry, and the
  *caller* decides it; your function just honours the flag.
- The `max(1, ...)` floor means a confirmed hit is never a no-op.

### Poison
When `poison_chance > 0` **and the attack hit**, roll `rng.randint(1, 100) <= poison_chance` and
set `AttackResult.poisoned`. **Do not apply the effect** — the caller does that via
`status.apply_effect`. On a miss, `poisoned` is always `False`.

### Roll order — binding, because determinism depends on it
Draw from `rng` in exactly this order, and only when needed:
1. the to-hit roll (always),
2. the damage roll (only if the attack hit),
3. the poison roll (only if the attack hit **and** `poison_chance > 0`).

A miss therefore consumes exactly one draw. This ordering is part of the contract because the
same seed must always produce the same fight.

## Constraints
- Python 3.10+, **standard library only**. `from __future__ import annotations` at the top.
- Imports **only** `roguelike.stats`, `roguelike.items`, `roguelike.status`. **Must not import**
  `events`, `npc`, `level`, `world`, `game`, or `curses`.
- **No `Random` instance is created or stored inside this module** (§0.12). `rng` is passed in by
  the caller, which derives a fresh one per roll. Do not call `random.random()`,
  `random.randint()` or any module-level `random` function.
- **All arithmetic is integer.** No floats. Use `//`, never `int(x / 2)` — the STR modifier
  floors toward −∞ and at `str_ == 5` it is `-3`, not `-2`.
- Pure: no mutation of `attacker` or `defender`, no I/O, no module-level state, no caching.
- `AttackResult` is frozen.
- Do not add: critical hits, a `crit_chance` parameter, armour, damage types, a `defender_dodged`
  distinct from `hit=False`, an `events` list on the result, or a `resolve_melee`/`resolve_ranged`
  split (one function, one flag).

## Acceptance criteria
- `to_hit_chance(5) == 85`; `to_hit_chance(0) == 90`; `to_hit_chance(29) == 61`;
  `to_hit_chance(14) == 76`; `to_hit_chance(17) == 73`.
- **Clamping at both ends:** `to_hit_chance(200) == 5` and `to_hit_chance(-200) == 95`. Never
  below 5, never above 95, for any input.
- **To-hit is independent of the attacker.** Assert that `resolve_attack` produces the same
  hit/miss outcome for two attackers with wildly different `Stats` (e.g. AGI 3 vs AGI 18)
  against the same defender with the same seeded `rng`. This is the test that catches a
  reintroduced attacker accuracy term — name it so.
- **`strength_applies` splits correctly.** With a fixed `rng`, a high-STR attacker (`str_ 16`)
  does **more** damage than a baseline one when `strength_applies=True`, and **exactly the same**
  damage when `strength_applies=False`.
- **The low-STR natural attacker is not double-penalised.** A rat (`Stats(4, 14, 3)`) biting a
  baseline defender (block 0) with `damage 1–3` and `strength_applies=False` produces damage in
  `1..3` — **not** floored to 1 every time. Assert the full range appears across many seeds.
  Name this test after the bug it prevents.
- **Damage floor:** a very weak attack against a very high-block defender still does exactly 1,
  never 0 and never negative.
- **Block subtracts:** with a fixed `rng`, raising the defender's `str_` from 10 to 16 (block
  0 → 3) reduces damage by exactly 3, unless the floor intervenes.
- `defender_hp` equals `defender.hp - damage`, and `killed` is exactly `defender_hp <= 0`.
- **A miss:** `hit is False`, `damage == 0`, `defender_hp == defender.hp`, `killed is False`,
  `poisoned is False`.
- **Poison:** never set on a miss; never set when `poison_chance == 0`; set roughly 30% of the
  time over many seeds at `poison_chance=30` (assert a generous band, e.g. 20–40%, so it is not
  flaky); and `resolve_attack` **does not** modify `defender.status_effects`.
- **Roll order and determinism:** two calls with `random.Random(<same seed>)` give identical
  results; a miss consumes exactly one draw from the rng (assert by comparing the state of two
  generators, or by counting draws with a small counting wrapper).
- **Purity:** `attacker` and `defender` are unchanged after the call — assert by equality against
  copies taken beforehand.
- `resolve_attack` raises `ValueError` when `damage_min > damage_max`.
- `resolve_attack` on an already-dead defender (`hp <= 0`) resolves normally and `killed` stays
  `True`.
- **Statistical sanity over many seeds:** at 85% to-hit, the observed hit rate across 2000 rolls
  lands in a generous band (e.g. 80–90%). Use a fixed seed sequence so the test is deterministic.
- `combat.py` imports only `stats`, `items`, `status`; imports no `curses` and no `events` —
  assert with `ast`. No float literal, and no `int(` ... `/` ... `)` pattern in the arithmetic.
- Tests must not initialise curses and must pass with no TTY. No `conftest.py`.
