# T05 — Movement and collision
Status: todo
Depends on: T01

## Goal
Provide a pure, single-step movement resolver that accepts legal moves and rejects illegal
ones without raising, so a rejected move can consume no turn.

## Context
This project is an interactive terminal roguelike engine with ASCII graphics, similar in feel
to ADOM. It is being built by several independent workers who never communicate; a frozen
contract document defines every seam where their code meets. You own collision.

Your module is small on purpose. A game loop written by someone else translates a keypress
into a `(dx, dy)` delta and calls your `try_move`. You answer one question — *may the player
step there, and where do they end up?* — and you answer it as a **pure function**: you never
mutate the level, never mutate the position, never do I/O, and never raise for an ordinary
illegal move. Walking into a wall is normal input, not an error.

The result type carries a `moved` flag, and that flag is how the project satisfies its
"illegal moves consume no turn" requirement: the caller increments its turn counter **iff**
`result.moved` is `True`. Because you return the *unchanged* position on rejection, the caller
cannot get this wrong by accident. Keep that property.

The engine's scope is deliberately tiny: generate one dungeon level, walk an `@` around it,
quit cleanly. There are **no** monsters, combat, items, inventory, field of view, save-load,
multiple levels, stairs, sound, or colour — explicitly out of scope. There is nothing to
collide with except terrain. Do not add an entity/occupancy check, a `blocked_by` reason
field, a push/swap rule, or movement costs.

Two conventions to internalise before writing anything:
- **All coordinates are `(x, y)`, origin top-left, `x` grows right, `y` grows DOWN** — so up
  is `dy = -1`. Grid storage is `grid[y][x]`.
- Out-of-bounds is handled by `Level.is_walkable`, which **returns `False` off-map and never
  raises**. Its sibling `Level.tile_at` *does* raise `IndexError` off-map. Use `is_walkable`.
  This is why walls, the map border, and off-map coordinates all collapse into one uniform
  rejection path in your code — do not write separate bounds handling.

## Produce

`roguelike/movement.py`:
```python
@dataclass(frozen=True)
class MoveResult:
    position: tuple[int, int]   # new position if moved, else the ORIGINAL position
    moved: bool

def try_move(
    level: Level,
    position: tuple[int, int],
    dx: int,
    dy: int,
) -> MoveResult

def is_blocked(level: Level, x: int, y: int) -> bool
```

`tests/test_movement.py` — unit tests.

### Exact behaviour
- Target is `(position[0] + dx, position[1] + dy)`.
- `level.is_walkable(*target)` true → `MoveResult(target, True)`.
- Otherwise → `MoveResult(position, False)`, with `position` **unchanged and equal to the
  input**. Walls, the border, and off-map coordinates all take this path.
- `dx == 0 and dy == 0` → `MoveResult(position, False)`. Not an error.
- `dx` or `dy` outside `{-1, 0, 1}` → **`ValueError`**. Movement is single-step only.
- Diagonals are legal iff the destination is walkable. **No corner-cutting rules.**
- `is_blocked(level, x, y)` → `not level.is_walkable(x, y)`. Never raises.

## Constraints
- Python 3.10+, **standard library only**. No third-party imports, ever.
- `from __future__ import annotations` at the top of the module.
- Imports from `roguelike`: **only** `roguelike.level`, and optionally `roguelike.tiles`
  (CONTRACT §10). You must **not** import `roguelike.render`, `roguelike.keys`,
  `roguelike.game`, or `roguelike.generator`.
- Do not import `curses` — collision has no business with a terminal.
- `MoveResult` is `frozen=True`, field order `(position, moved)` as written.
- **Purity is the point.** No mutation of `level` or `position`, no I/O, no logging, no
  module-level mutable state, no caching keyed on anything.
- Use `level.is_walkable` for the walkability test. Do not call `level.tile_at` and catch
  `IndexError`, and do not re-derive bounds checks yourself — the uniform rejection path is
  the design.
- Do not implement corner-cutting prevention. A diagonal move between two wall corners is
  legal here. This is a deliberate scope decision, not an oversight.
- Do not add entity collision, occupancy, movement cost, or a rejection-reason field.
- Build test levels by constructing `Level` directly with hand-written grids. **Do not import
  the generator** — it may not exist yet, and your tests must not depend on it.
- Tests must not initialise curses and must pass with no TTY attached.
- Do not write a `conftest.py`; nobody owns that file.

## Acceptance criteria
- Moving onto a `FLOOR` tile returns `MoveResult(target, True)` with the correct target.
- Moving onto a `DOOR` tile returns `moved=True` — doors are walkable.
- Moving into a `WALL` returns `moved=False` and `position` equal to the input position.
- Moving off every edge of the map — left of `x=0`, above `y=0`, right of `width-1`, below
  `height-1` — returns `moved=False` and **does not raise**. Test all four edges.
- The rejected result's `position` is equal to the input tuple (assert equality, and that the
  level and position are unchanged after the call).
- `try_move(level, pos, 0, 0)` returns `moved=False` without raising.
- All eight direction deltas work on an open floor area and land on the expected target;
  assert with a starting position where `x != y` so the axes cannot be swapped silently.
- **Sign convention:** `dy = -1` moves to a smaller `y` (up/north), `dy = +1` to a larger `y`.
- `dx` or `dy` of `2`, `-2`, or `10` raises `ValueError` — test both arguments.
- Diagonal movement between two diagonal walls is **allowed** when the destination is
  walkable (explicitly assert the no-corner-cutting decision, so a future change is caught).
- `is_blocked` is `True` for walls and for every out-of-bounds coordinate, `False` for floor
  and door, and never raises.
- `is_blocked(level, x, y) == (not level.is_walkable(x, y))` over a full sweep of a small
  level including out-of-bounds coordinates.
- `MoveResult` is immutable: assigning to `.moved` raises `dataclasses.FrozenInstanceError`.
- Purity: after a sequence of accepted and rejected moves, the original `Level` object still
  compares equal to a copy taken before the sequence.
- Repeated rejected moves against a wall never change position and never raise.
- `movement.py` does not import `roguelike.render`, `roguelike.keys`, `roguelike.game`, or
  `roguelike.generator` — assert by reading the module source in a test.
