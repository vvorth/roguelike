# T06 — Game loop and curses lifecycle
Status: todo
Depends on: T01, T02, T03, T04, T05

## Goal
Tie the finished modules into a turn loop with a pure state transition, and own the curses
lifecycle so the terminal is always restored on exit.

## Context
This project is an interactive terminal roguelike engine with ASCII graphics, similar in feel
to ADOM. It has been built by several independent workers who never communicated; a frozen
contract document defined every seam. **Every other module is now finished and verified.**
You are the last worker: you wire them together and own the only code in the project that
touches a live terminal.

What already exists and is frozen — read all of it before writing anything:
- `roguelike/tiles.py` — `Tile`, `TILE_CHARS`, `WALKABLE`, `PLAYER_CHAR`.
- `roguelike/level.py` — frozen `Room` and `Level` with `in_bounds`/`tile_at`/`is_walkable`.
- `roguelike/generator.py` — `generate_level(seed, width, height, max_rooms) -> Level`.
- `roguelike/render.py` — `render_to_lines(...)` (pure) and `draw(stdscr, ...)` (blitter).
- `roguelike/keys.py` — `CommandKind`, `Command`, `translate_key(key) -> Command`.
- `roguelike/movement.py` — `MoveResult`, `try_move(level, position, dx, dy)`.

You import from all of them. You are the only module permitted to.

Three constraints shape this task, and each one is why a particular line of the design exists:

1. **"Rendering is decoupled from state — no module may both mutate state and draw."** You
   hold the state; the renderer draws. You therefore **never** call `addstr` or write to the
   screen yourself: you call `render.draw`. And `render.draw` never sees your `GameState` —
   you hand it `(level, player_pos, status_string)`. `GameState` lives in your module and
   **nothing else imports it**; that is deliberate, and it is what let the renderer be written
   by someone who never spoke to you.

2. **"Every module must be importable and testable without a live terminal."** So the loop is
   split: `step(state, command)` is a **pure function** carrying all the game logic and all
   the tests, while `run(stdscr, level)` is a thin shell that gets a key, translates it, calls
   `step`, and asks the renderer to draw. Your tests exercise `step` exhaustively and never
   initialise curses.

3. **"A clean quit path that always restores the terminal."** `play()` uses
   `curses.wrapper`, which restores the terminal on normal return *and* on exception,
   including `KeyboardInterrupt`.

Out of scope, explicitly — do not build, do not stub speculatively: monsters, combat, items,
inventory, field of view/lighting, save-load, multiple levels, stairs, sound, colour beyond
terminal defaults. No message log, no menus, no title screen, no pause state, no help
overlay, no `--debug` mode. The engine generates one level, walks an `@`, and quits.

Coordinate convention: **`(x, y)`, origin top-left, `x` grows right, `y` grows DOWN**, so up
is `dy = -1`. Grid storage is `grid[y][x]`. The `(y, x)` swap curses needs lives inside
`render.draw` and must not appear in your module.

## Produce

`roguelike/game.py`:
```python
@dataclass(frozen=True)
class GameState:
    level: Level
    player: tuple[int, int]    # (x, y)
    turns: int = 0
    running: bool = True

def new_game(level: Level) -> GameState
def step(state: GameState, command: Command) -> GameState
def format_status(state: GameState) -> str
def run(stdscr, level: Level) -> None
def play(seed: int, width: int = 80, height: int = 22) -> None
```

`tests/test_game.py` — unit tests, essentially all against `step`/`new_game`/`format_status`.

### Exact behaviour
- `new_game(level)` → `GameState(level, level.player_start, turns=0, running=True)`.
- **`step(state, command)` is pure** — returns a **new** `GameState`, never mutates the input,
  never touches curses, never draws:
  - `CommandKind.QUIT` → same state with `running=False`; **turns unchanged**.
  - `CommandKind.UNKNOWN` → state returned unchanged (returning the same object is fine).
  - `CommandKind.MOVE` → delegate to `movement.try_move(state.level, state.player, dx, dy)`.
    On `moved=True`: new position and `turns + 1`. On `moved=False`: position **and** turns
    both unchanged.
  - A state with `running=False` is returned unchanged, whatever the command.
- `format_status(state)` → exactly
  `f"Seed: {seed}  Pos: ({x}, {y})  Turns: {turns}  [q] quit"` (two spaces between fields).
  Return a plain `str`; padding and truncation are the renderer's job.
- `run(stdscr, level)` — loop: `render.draw(stdscr, level, state.player, format_status(state))`,
  `stdscr.getch()`, `translate_key`, `step`, repeat until `not state.running`. Set
  `curses.curs_set(0)` and `stdscr.keypad(True)` defensively, each wrapped against
  `curses.error` (`curs_set` raises on terminals that cannot hide the cursor). Return when the
  player quits.
- `play(seed, width, height)` — call `generate_level(seed, width, height)`, then
  `curses.wrapper(run, level)`. **This is the only place in the codebase that initialises
  curses.**

## Constraints
- Python 3.10+, **standard library only**. No third-party imports, ever.
- `from __future__ import annotations` at the top of the module.
- Imports from `roguelike`: `level`, `keys`, `movement`, `render`, `generator` (CONTRACT §10).
  This is the only module allowed to import that widely.
- Importing `curses` at module top level is allowed. You may call `curses.wrapper` **only
  inside `play()`** — never at import time. Nothing in this module may initialise a terminal
  as a side effect of being imported.
- `GameState` is `frozen=True`, field order and defaults exactly as written. Use
  `dataclasses.replace` for transitions rather than constructing by hand where it reads better.
- **`step` must not draw and must not call anything in `render`.** Rendering happens in `run`.
- **`run` must not implement game rules.** Anything decidable without a terminal belongs in
  `step`.
- Do not reimplement collision — delegate to `movement.try_move`. Do not reimplement key
  mapping — delegate to `keys.translate_key`. Do not reimplement frame layout — delegate to
  `render.draw`.
- Do not write to the screen directly: no `stdscr.addstr` / `addch` / `move` in this module.
- Do not add a game-over state, score, or any command beyond move and quit.
- Tests must not initialise curses and must pass with no TTY attached. Test `step` directly by
  constructing `GameState` values; do **not** attempt to test `run` or `play` against a real
  terminal — the integrator runs the live smoke test.
- Build test levels either by constructing `Level` directly with hand-written grids or via
  `generate_level` with a fixed seed. Prefer hand-built levels for rule tests so the
  assertions are exact.
- Do not write a `conftest.py`; nobody owns that file.

## Acceptance criteria
- `new_game(level).player == level.player_start`, `turns == 0`, `running is True`.
- A `MOVE` onto walkable terrain returns a new state with the updated position and
  `turns == 1`.
- **A `MOVE` into a wall leaves position unchanged AND `turns` unchanged** — the
  "illegal moves consume no turn" requirement; assert both fields.
- A `MOVE` off the map edge leaves position and turns unchanged and does not raise.
- `QUIT` sets `running=False` and leaves `turns` and `player` unchanged.
- `UNKNOWN` leaves the state entirely unchanged, including `turns`.
- `step` on a state with `running=False` returns an equal state for every command kind,
  including `MOVE`.
- **Purity:** `step` never mutates its input — capture the input state's fields before the
  call and assert they are unchanged afterwards, and assert the returned object is a distinct
  `GameState` when something changed.
- A scripted sequence of commands over a hand-built level produces the exact expected final
  position and turn count — include at least one blocked move in the middle so the turn count
  differs from the command count.
- Sign convention: a north command (`dy = -1`) decreases `y`; assert with a start position
  where `x != y`.
- `format_status` returns exactly the specified format for a known state — compare against a
  literal string.
- `format_status` reflects live values: turns and position change in the string after a move.
- `GameState` is immutable: assigning to `.turns` raises `dataclasses.FrozenInstanceError`.
- Importing `roguelike.game` does not initialise a terminal — the suite passes with stdin
  redirected from `/dev/null`, and `game.py` calls `curses.wrapper` only inside `play`
  (assert by reading the module source).
- `game.py` contains no direct screen writes (`addstr`/`addch`) — assert by reading the
  module source.
- The full turn-loop rule set is reachable without curses: every acceptance criterion above is
  tested through `step`, not through `run`.
