# T21 — Activities, travel and the paced loop
Status: todo
Depends on: T18, T19, T20

## Goal
Let the player start a multi-turn action, watch it run at a readable pace, and stop it instantly
with any key.

## Context
This is an interactive terminal roguelike engine with ASCII graphics, similar in feel to ADOM.
Versions 1–3 are complete and passing 1666 tests: a procedurally generated multi-level dungeon,
permissive field of view, fog of war, bump-to-open doors, 256-colour rendering, stairs you can
descend and climb, and a status line with event messages.

Version 4 adds automatic navigation. **Every other v4 module is finished and verified.** You are
the last worker: you wire them together, and you own the turn loop.

What exists and is finished — **read all of it, do not assume its shape**:
- `roguelike/keys.py` — `CommandKind` now has `AUTO_EXPLORE` (`E`) and `WALK_PREFIX` (`w`);
  Shift+arrows and `HJKL` produce diagonals.
- `roguelike/events.py` — eight new kinds: `WALK_WHICH_WAY`, `TRAVELLING`, `ARRIVED`,
  `EXPLORED_EVERYTHING`, `NOTHING_FURTHER`, `STOPPED_AT_JUNCTION`, `STOPPED_AT_OPENING`,
  `INTERRUPTED`.
- `roguelike/pathfind.py` — `find_path`, `is_wide`, `degree`, `is_intersection`, through a
  `passable` callable.
- `roguelike/activity.py` — `ActivityKind`, `Activity`, `frontier_cells`, `walk_step`.

- Everything else is unchanged and frozen.

### The three ideas that make this task

**One mechanism gives both pacing and cancellation.** `stdscr.timeout(100)` was measured:
**9 ticks in 1.0 s** with no input, and a waiting key returns in **0.00 ms**. So the loop asks
for a key with a 100 ms deadline — a key cancels instantly, no key means take one turn. There is
no `sleep` and no busy-wait, and there must not be.

**Timing must not leak into the pure core.** `step` and your new `advance` are pure functions
and the whole suite depends on it. `run` owns the clock and the keyboard; nothing else may read
a clock at all.

**Re-plan every turn.** A full-level search costs ~0.235 ms against a 100 ms budget. Do not
cache routes, do not store a path on the `Activity`, do not write incremental replanning. The
contract forbids it because simpler is affordable here.

### The rules easiest to get wrong

- **The cancelling keypress is consumed by the cancellation.** It must not also act as a
  command — otherwise a panicked keypress stops the walk *and* moves you into whatever you were
  fleeing.
- **Opening a door does not interrupt an activity** (user decision). The door opens, costs its
  turn, reports `The door opens.`, and the walk continues.
- **Auto-explore never descends** (user decision). It stops on the current level.
- **A rejected move still consumes no turn**, and pressing `>` off-stairs with no known
  staircase still just reports it — v3's rules survive intact.
- An activity **does not survive a level change**.

Out of scope, explicitly — do not build, do not stub: monsters, combat, items, inventory,
save-load to disk, sound, score. No live interrupt conditions — `interruption` returns `None`
today by decision, and the seam is what ships. No observer registry, event bus or plugin
mechanism. No auto-descend, no cross-level travel, no mouse, no message history.

### `step` additions (all v3 behaviour retained)

| Command | Behaviour |
|---|---|
| `WALK_PREFIX` | `awaiting_walk=True`, **no turn**, emit `WALK_WHICH_WAY` |
| `MOVE` while `awaiting_walk` | clear prefix, start `Activity(AUTO_WALK, direction=(dx,dy))`, **no turn yet** |
| any other command while `awaiting_walk` | clear prefix, **consume it entirely** — no turn, no action, no event |
| `AUTO_EXPLORE` | start `Activity(AUTO_EXPLORE)`, no turn |
| `DESCEND` off-stairs, a `STAIRS_DOWN` cell **is** explored | start `Activity(TRAVEL, goal=nearest)`, emit `TRAVELLING`, no turn |
| `DESCEND` off-stairs, none explored | emit `NO_STAIRS_DOWN`, no turn — unchanged from v3 |
| `ASCEND` off-stairs | the same two cases against `STAIRS_UP` |

Any command reaching `step` while an activity is running clears that activity first.

### `advance` — pure, exactly one turn

Next cell by kind: `AUTO_WALK` → `activity.walk_step`; `TRAVEL` → `find_path` over
`is_planning_passable` **restricted to `explored`**, goals `{activity.goal}`; `AUTO_EXPLORE` →
path to the nearest `activity.frontier_cells(...)`.

Perform the move by the **same rules as a `MOVE` command** so doors bump open and the activity
continues. Then call `interruption(before, after)`. Finishing clears the activity and emits
exactly one event: `ARRIVED`, `NOTHING_FURTHER`, `EXPLORED_EVERYTHING`,
`STOPPED_AT_JUNCTION` or `STOPPED_AT_OPENING`.

### `run` — the paced loop
With an activity: `timeout(100)`; a key cancels (emit `INTERRUPTED`, **consume the key**),
`-1` means `advance`. Without one: `timeout(-1)` and the v3 path.

## Acceptance criteria
- `GameState` gains exactly `activity` and `awaiting_walk`, appended with defaults; field order
  matches the contract via `dataclasses.fields`; still frozen.
- **`advance` with no activity returns the state unchanged.**
- **Auto-explore end to end:** from `new_game`, repeated `advance` explores ≥95% of walkable
  tiles on at least two seeds, clears the activity, and emits `EXPLORED_EVERYTHING` exactly
  once. It must **not** change `depth`.
- Auto-explore **opens doors and keeps going** — assert `open_doors` grows during the run and
  the activity is still set immediately afterwards.
- **Travel:** with a down-staircase explored but not underfoot, `DESCEND` starts a `TRAVEL`
  activity and emits `TRAVELLING`, without consuming a turn; repeated `advance` ends **on** the
  staircase with `ARRIVED` and the activity cleared.
- **Travel with nothing known:** `DESCEND` off-stairs with no explored down-staircase emits
  `NO_STAIRS_DOWN`, consumes no turn, and starts **no** activity.
- **Auto-walk:** `WALK_PREFIX` sets `awaiting_walk` and emits `WALK_WHICH_WAY` without a turn; a
  following `MOVE` starts `AUTO_WALK` and clears the prefix; `advance` walks a corridor,
  follows a bend, and stops with `STOPPED_AT_JUNCTION` / `STOPPED_AT_OPENING` /
  `NOTHING_FURTHER` as appropriate.
- **`w` then a non-direction key** clears the prefix, consumes the command, and produces no
  turn, no activity and no event — assert with `QUIT`, which must **not** quit.
- **A command during an activity clears it** — assert for a `MOVE` and for `QUIT`.
- **Activities do not survive a level change:** start a travel or explore activity, descend, and
  assert `activity is None`.
- **Purity:** for each of `step` and `advance`, capture every input field before the call and
  assert it is unchanged after; a `deepcopy` of the level still compares equal; input frozensets
  and `saved` are unmodified.
- `interruption(before, after)` returns `None` for every pair you can construct, including one
  where a door opened — pinned so decision 3 cannot silently change.
- **The loop, via the stub screen:** with an activity set, `run` calls `timeout(100)`; a
  returned key cancels the activity, emits `INTERRUPTED`, and **the key does not also act as a
  command** (assert the player did not move and no turn was consumed); `-1` advances one turn.
  With no activity, `run` calls `timeout(-1)`.
- **No clock anywhere:** assert by source inspection that `game.py` contains no `time.sleep`,
  no `time.time`, no `perf_counter`, and no busy-wait loop.
- Source hygiene retained from v3: `curses.wrapper` only inside `play`; `init_colors` only in
  `run`; no `addstr`/`addch`; `step` references nothing in `render`; import graph within the
  §10 v4 allowance.
- All v1–v3 behaviour still holds: rejected moves cost no turn, bump-to-open, fog monotonic,
  descent keeps the player put, the persistence round trip, `format_status_right` unchanged.
